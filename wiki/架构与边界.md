# 架构与边界

## 服务划分

| 服务 | 目录 | 技术 | 职责 | 明确不做 |
| --- | --- | --- | --- | --- |
| 前端 | `campus-overflow-ai/frontend` | Next.js 16 App Router、React 19、Tailwind 4 | 学生/教师/管理三端页面、BFF 转发、SSE 透传、文件导出 | 不写核心业务规则 |
| 业务后端 | `campus-overflow-ai/backend` | FastAPI、SQLAlchemy 2.x（同步）、Alembic、MySQL | 认证、RBAC、课程、问答、事务、审批、审计 | 不调用模型做决策 |
| Agent | `campus-overflow-ai/agent` | TypeScript、AI SDK、Hono/Nitro、Workflow、Zod | 单 Agent Loop、任务路由、工具网关、RAG、MCP、审批编排 | 不直连 MySQL，不执行高风险处置 |

## 三条硬边界

1. **业务事实唯一**：MySQL 是唯一真值源，只有 FastAPI 能写。Agent 的业务读写必须走 `/internal/agent/*`，服务间凭证鉴权并透传 `x-trace-id`。
2. **工具白名单**：工具在 `agent/src/tools/registry.ts` 注册，未注册不可调用；工具可用性 = 注册表 ∩ 角色权限 ∩ 数据范围。
3. **AI 不处置**：隐藏、删帖、封禁只生成待确认工单，人工确认后由后端复核并原子执行。

## 存储职责

| 存储 | 存什么 | 不存什么 |
| --- | --- | --- |
| MySQL | 用户、课程、问答、工单、审批、审计、回执 | 模型临时状态 |
| PostgreSQL | Workflow 运行状态、队列、必要恢复数据 | 业务事实、私人会话 |
| Markdown / Wiki | 教材与知识参考 | 授权依据、业务事实 |
| 浏览器 | 学生/教师个人记忆（按账号隔离、可清空） | 他人数据 |
| 服务器私有目录 | 管理员私人上下文（分来源目录） | 与中台会话混放 |

个人记忆不作为数据访问授权。

## 后端分层

轻量模块化单体，6 个业务模块：

```text
app/modules/{identity,courses,qa,interaction,discovery,governance}/
  router.py → service.py → domain.py / repository.py → models.py
```

- `domain` 零框架依赖，规则集中；
- `models` 只允许本模块 `repository` 导入；
- `discovery` 是纯读模块，无 domain/repository/models；
- 依赖方向由 `uv run lint-imports` 强制，违规即失败。

## Agent 结构

```text
agent/src/
  loop/          计划生成、执行、停止条件、结果审查
  tasks/         任务路由
  tools/         工具注册与执行
  knowledge/     知识目录、问答快照、RAG
  mcp/           MCP 服务端、凭证策略、限流、审计
  approvals/     审批工单
  observability/ trace 与运行记录
  memory/        记忆读写编排
```

## 默认关闭清单

夜间整理、夜间快照、问答快照读取、管理员快照回退、全量扫描、MCP 外部接入、RAG 检索，全部默认关闭，显式开启后才生效。

新增能力必须同时具备：开关、失败隔离、可停止、可回滚、审计。
