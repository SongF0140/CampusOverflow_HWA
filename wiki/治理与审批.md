# 治理与审批

## 为什么 AI 不能直接处置

内容治理动作（隐藏、删帖、封禁）一旦由模型直接执行，错误判断就变成不可逆事实。因此本系统把“判断”和“执行”拆开：

```text
巡检 / 全量扫描发现内容
  → 读取目标与当前版本
  → 模型规划与评估
  → 生成待确认工单（pending）
  → 管理员确认
  → 后端复核权限与目标版本
  → 原子执行，写审计与回执
  → 重新观察 → 评估 → 完成 / 下一轮 / 转人工
```

模型全程没有写权限，只产出建议与工单。

## 执行前 dry-run

管理员确认前可以调用只读预演接口：

```text
POST /internal/agent/user/governance-dry-run
```

它复用目标状态与版本校验，返回预计影响的问题/回答/评论数量与风险提示，但不建工单、不写审计、不修改目标。预演结果不是执行凭证；真正执行仍要重新校验版本与权限。

详细边界见 [沙箱与验证](./沙箱与验证.md)。

## 轮次与预算

- 最多 **5 轮**完整 loop；一轮可以包含多个动作，不把每次动作当成一轮。
- 观察、评估、执行之间共享同一运行预算，跨计划累计，不能通过“换个任务”重置。
- 无进展、结果未知、目标版本变化，一律转人工，不自动重试扩大影响面。

## 审批冻结

工单确认时冻结三样东西：

1. 动作类型；
2. 参数；
3. 目标当前版本。

执行前再次校验。任一不匹配即拒绝，避免“确认时是 A，执行时已变成 B”。

## 结果未知

执行请求超时、连接中断、响应丢失时，系统不重放写操作，先核对已有回执：

- 找到回执 → 返回原结果；
- 找不到 → 转人工处理。

错一次比错两次好。

## 可追踪

每次 run、tool call、approval request 记录：

- `trace_id`；
- `agent_run_id`；
- 脱敏调用摘要。

审计不存原始 prompt 中的密钥、密码、Cookie 与隐私原文。
