# 下一期四阶段执行计划

日期：2026-11-18。
依据：`docs/Agent层设计与实施分期.md`「夜间静默治理」与「后续分期」第 4、5 项；项目宪法 C-05～C-08；`docs/审查记录/夜间离线整理/审查记录.md`。
范围：夜间定时调度 → 管理员全量扫描 → 教师周报增强 → MCP 外部接入。
执行方式：按阶段顺序推进；每阶段完成冒烟验证后停下交用户审查，审查通过再进入下一阶段。

## 零、全局不变量

1. AI 不处置：所有阶段只建单、只产出建议，处置仍由管理员确认后 FastAPI 执行（C-06）。
2. 不扩权：定时与扫描不能扩大任何角色的可见范围；外部 MCP 仍受 scope 与账号映射约束。
3. 不存原文：笔记、审计、进度只存脱敏摘要，不存内容快照、私人会话或凭证（C-07）。
4. 默认关闭：新增定时任务、全量扫描、MCP 扩展能力一律默认关闭，显式开启后才生效。
5. 失败隔离：定时任务失败不影响在线巡检、问答与审批；扫描单条失败记录后继续。
6. 可停止：每个长任务必须有停止方式（开关、取消接口或进程退出）。

## 二、P1 夜间定时调度

### 目标

让已完成的离线整理按日自动运行，同时保留手动触发。

### 范围

- Agent 新增 `scheduler/nightly-scheduler.ts`，仿照周报调度器的"计算下次触发时刻 + 单定时器"结构。
- 注册到 `runtime/agent-services.ts` 后台服务列表。
- 不在本阶段改整理逻辑本身。

### 默认参数（用户未反对即生效）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `NIGHTLY_CONSOLIDATION_ENABLED` | `false` | 默认不启用，避免未验收就跑 |
| `NIGHTLY_CONSOLIDATION_HOUR` | `1` | 本地时区 01:00 |
| `NIGHTLY_CONSOLIDATION_MINUTE` | `0` | |
| `NIGHTLY_CONSOLIDATION_DAYS` | `14` | 反馈回溯天数，与手动触发一致 |
| `NIGHTLY_SNAPSHOT_ENABLED` | `false` | 是否在整理前构建并切换知识槽 |
| 重试 | 0 次 | 失败记录，次日再跑；不立即重试 |
| 并发 | 进程内互斥 | 与手动触发同时发生时跳过本轮并记录 |

### 改动点

### 验证

- 单测：配置边界、下次触发跨日/跨周、默认关闭不调度、到期执行一次、失败后仍能安排次日、停止后不再触发。

### 验收与回滚

- 开启开关后一天内产生一条 `agent_runs` 整理记录，且次日同一时刻再次触发。
- 回滚：关闭开关或移除服务注册，手动路由不受影响。

## 三、P2 管理员全量扫描

### 目标

管理员可对指定范围发起一次全站扫描，能看到进度、能取消，结果仍只建单。

### 范围

- 后端新增扫描任务表与内部接口；Agent 新增管理端路由与分批执行器。
- 不改 15 分钟巡检行为。

### 数据与接口

- 表 `patrol_scan_jobs`：状态（queued/running/succeeded/failed/cancelled）、范围 JSON、游标、计数、取消标记、发起人、trace、起止时间。
- 内部接口：创建、查询、取消、进度回写（服务凭证）。
- Agent 管理端：`POST /agent/patrol/full-scan`、`GET /agent/patrol/full-scan/{id}`、`POST /agent/patrol/full-scan/{id}/cancel`，仅管理员，默认关闭。

### 默认参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `PATROL_FULL_SCAN_ENABLED` | `false` | 默认关闭 |
| 批量大小 | 50 | 每批之间让出事件循环 |
| 单次上限 | 5000 条 | 超出需管理员显式提高 |
| 范围 | 问题/回答/评论，全部状态 | 可传 target_types 缩小 |
| 处置 | 无 | 只建 pending 工单 |

### 执行规则

- 按 `(target_type, id)` 游标推进，可中断可续跑。
- 每批检查取消标记；取消后状态置 `cancelled`，已建单保留。
- 单条失败计入 failed 并继续；同一目标已有未结案工单仍幂等跳过。
- 进度每批回写一次，前端轮询即可，不引入推送。

### 验证

- 后端：创建/查询/取消/越权/非法状态迁移；取消后不再推进。
- Agent：分批游标、取消生效、单条失败隔离、上限生效、审计记录。
- 不新增真实数据库联调要求；MySQL 并发归 T-18。

### 验收与回滚

- 管理员发起 100 条以内扫描能完整跑完并显示计数；取消能在一批内生效。
- 回滚：关闭开关；表保留不影响现有巡检。

### 完成状态（2026-11-18）

已实现：`patrol_scan_jobs` 表与 `p2_patrol_scan_jobs` 迁移；内部接口 `POST/GET /internal/agent/patrol/scans`、`POST .../{id}/cancel`、`PATCH .../{id}/progress`、`GET .../{id}/page`；Agent 管理端 `POST/GET /agent/patrol/full-scan`、`POST /agent/patrol/full-scan/{id}/resume`、`POST /agent/patrol/full-scan/{id}/cancel`（`PATROL_FULL_SCAN_ENABLED` 默认关闭，仅 active 管理员）；执行器按游标分批、逐条检查取消、单条失败隔离、上限 5000 条，只建 pending 工单。验证：后端专项 13 项、全量 773 passed / 26 skipped；Agent 专项 18 项、全量 73 文件 624 项；ruff / lint-imports / typecheck / eslint 通过。未做真实模型全量联调，MySQL 并发归 T-18。

## 五、P4 MCP 外部接入

### 目标

让外部 Agent 可以安全、可运维地接入现有只读 MCP Server。

### 范围

- 凭证轮换与过期；每客户端限流；接入冒烟脚本；运维说明。
- 不开放管理写工具；管理类工具仍只建待确认申请。

### 默认方案

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 凭证 | 每客户端支持两个有效 token | 轮换期重叠，旧 token 到期自动失效 |
| 过期 | `expires_at` 可选 | 未配置视为长期，仍建议配置 |
| 限流 | 每客户端 60 次/分钟 | 进程内令牌桶，超限返回可解释错误 |
| 传输 | Streamable HTTP，仅本机监听 | 对外暴露由部署层反代 |
| 工具面 | 现有只读工具 | 不新增写工具 |

### 改动点

- 配置解析兼容单 token 旧格式，新增数组格式。
- 鉴权时跳过已过期 token；返回 401 不区分"不存在/过期"。
- 限流中间件放在鉴权之后、工具执行之前；限流拒绝写审计。
- `scripts/mcp-smoke.mjs`：ListTools + 三个只读工具 + 越权用例。
- `docs/` 补接入步骤与轮换流程。

### 验证

- 单测：双 token 有效、过期拒绝、限流边界、限流不触发工具执行。
- 冒烟脚本对本地实例跑通。
- 安全：错误响应不含 scope 列表、token 或内部路径。

### 验收与回滚

- 外部客户端在轮换窗口内无中断；超限得到明确中文错误。
- 回滚：恢复单 token 配置即可，无需迁移。

### 完成状态（2026-11-18）

已实现：`MCP_EXTERNAL_CLIENTS` 兼容旧单 `token` 与新的 `tokens` 数组（1～2 个，支持 `expires_at`/`expiresAt` 与 `external_key`）；鉴权跳过过期 token，过期与不存在统一 401；每客户端令牌桶限流（`MCP_RATE_LIMIT_PER_MINUTE` 默认 60，超限 429 并写 `mcp_request_rejected` 审计，不创建会话）；外部密钥与 MCP 凭证分离，轮换不改后端管理员密钥映射。新增 `scripts/mcp-smoke.mjs` 与 `npm run smoke:mcp`：ListTools、三个只读工具、未注册工具拒绝，`--in-process` 另验过期凭证 401。验证：MCP 专项 47 项、Agent 全量 74 文件 646 项、typecheck、eslint、`npm run smoke:mcp -- --in-process` 通过。工具面仍为只读，未新增写工具，未做真实外部客户端联调。
