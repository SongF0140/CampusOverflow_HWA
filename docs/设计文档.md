# CampusOverflow AI 设计文档

> 状态：草案，可继续微调  
> 本文档描述业务实现设计和技术边界。  
> 关键约束：Agent 使用 agent loop，不使用固定 workflow 作为核心抽象。

## 1. 总体架构

系统拆分为三个主要服务：

```text
frontend: Next.js + React 19 + TypeScript + Tailwind CSS
backend: FastAPI + SQLAlchemy + MySQL
agent: TypeScript + Vercel AI SDK
```

可选中间件：

```text
Redis: 缓存、限流、排行榜、Agent 任务状态
Nginx: 统一入口、反向代理、静态资源代理
Docker Compose: 本地和服务器多服务编排
OpenTelemetry: trace id 串联请求、Agent run、tool call 和审批记录
```

整体调用关系：

```text
Browser
  |
  v
Next.js Frontend / BFF / AI UI
  |
  | 普通业务 API
  v
FastAPI Backend
  |
  v
MySQL / Redis

Next.js Frontend / BFF / AI UI
  |
  | AI 请求
  v
TypeScript Agent Service
  |
  | tool calling
  v
FastAPI Backend
  |
  v
MySQL / Redis
```

核心边界：

- FastAPI 是业务权威层。
- MySQL 是核心数据唯一事实来源。
- Agent 是智能辅助层，不直接连接 MySQL。
- 前端只负责展示、交互和调用 API。
- 高风险动作必须通过 FastAPI 权限校验和人工确认。
- MCP Adapter 只存在于 Agent Runtime 内，不能绕过 FastAPI 修改核心业务数据。
- Agent 记忆、运行日志、工具日志和审批请求由 FastAPI 持久化到 MySQL。

## 2. 技术选型

| 模块 | 技术 | 选择理由 |
| ---- | ---- | -------- |
| 前端框架 | Next.js + React 19 | 更适合作品集展示、路由组织、BFF 聚合、AI 流式 UI 和服务端能力 |
| 前端语言 | TypeScript | 类型约束，方便复杂前端业务维护 |
| 样式 | Tailwind CSS | 快速构建现代 UI，便于统一设计 |
| 后端框架 | FastAPI | Python Web 主体，自动 OpenAPI，类型友好 |
| ORM | SQLAlchemy 2.x | 成熟 ORM，适合复杂关系模型 |
| 数据迁移 | Alembic | 管理 MySQL 表结构演进 |
| 数据库 | MySQL | 适合用户、课程、问答、投票等强关系数据 |
| Agent 服务 | TypeScript + Vercel AI SDK | 练习 TS Agent 能力，支持 tool calling、streaming、structured output |
| MCP Adapter | MCP SDK + 工具白名单 | 接入外部工具协议，同时保留权限和审计边界 |
| 持久化记忆 | MySQL + FastAPI 内部接口 | 保存 Agent 运行经验、课程上下文摘要和用户偏好 |
| 单 Agent Loop | TypeScript + task router | 不引入重框架，第一阶段用任务处理器承载 retrieval、moderation、doc、supervisor 等职责 |
| 可观测性 | OpenTelemetry + 业务日志 | 追踪 Next.js、FastAPI、Agent 和工具调用链路 |
| 人工确认 | approval_requests + 管理后台 | 展示 tool approval / 内容处理 / 文件写入确认能力 |
| 缓存/限流 | Redis | 适合排行榜、AI 限流、热点缓存 |
| 部署 | Docker Compose + Nginx | 适合课程展示和服务器部署 |
| 测试 | pytest + Vitest + Playwright | 覆盖后端、前端和端到端流程 |

## 3. 服务职责划分

### 3.1 Frontend

前端负责用户界面、BFF 聚合和 AI UI 交互。Next.js 不替代 FastAPI 的核心业务后端，也不替代独立 Agent Runtime。

主要职责：

- 登录、注册、课程、问题、回答、评论、通知等页面。
- 调用 FastAPI 业务接口。
- 调用 Agent 服务展示 AI 推荐结果。
- 展示 Agent 流式输出。
- 在 Route Handler 中做轻量 BFF 聚合和服务端转发。
- 管理本地 UI 状态。
- 对用户输入做基础校验。

不负责：

- 不保存密钥。
- 不直接连接数据库。
- 不执行核心权限判断。
- 不直接判定封禁或删除。
- 不承载长时间运行的 agent loop。

### 3.2 FastAPI Backend

FastAPI 是核心业务后端。

主要职责：

- 用户认证和 RBAC 权限控制。
- 用户、课程、问题、回答、评论、标签、投票、声誉、通知的 CRUD。
- MySQL 事务和数据一致性。
- OpenAPI 文档。
- 审核工单、快照、封禁、申诉管理。
- 为 Agent 暴露白名单工具 API。
- 持久化 Agent 记忆、运行日志、工具调用日志和审批请求。
- 记录审计日志。

不负责：

- 不直接承载复杂 Agent loop。
- 不让 AI 绕过权限修改核心数据。

### 3.3 TypeScript Agent Service

Agent 服务负责智能编排。

主要职责：

- 使用 Vercel AI SDK 调用模型。
- 维护 agent loop。
- 维护单 Agent Loop 与 task router。
- 通过 MCP Adapter 接入白名单 MCP Server。
- 读写持久化记忆，但必须经 FastAPI 内部接口。
- 根据任务选择工具。
- 调用 FastAPI 白名单接口获取上下文。
- 生成结构化建议。
- 流式输出 AI 辅助内容。
- 自检输出是否满足格式、来源和风险要求。
- 记录 Agent 运行日志。
- 生成 OpenTelemetry trace id 或透传上游 trace id。

不负责：

- 不直接连接 MySQL。
- 不直接删帖。
- 不直接封号。
- 不直接写核心业务表。
- 不访问密钥文件或非白名单目录。

## 4. Agent Loop 设计

本项目的 Agent 不是固定 workflow。Agent loop 是一个可持续运行的智能循环。

基本循环：

```text
1. Observe: 接收用户请求或系统事件
2. Classify: 判断任务类型和风险等级
3. Plan: 规划下一步需要哪些上下文和工具
4. Act: 调用白名单工具或模型
5. Reflect: 自检结果是否可靠、是否有来源、是否越权
6. Record: 写入 agent_runs 和 tool_call_logs
7. Respond: 返回建议、流式内容或创建待审核工单
```

生产化增强：

```text
8. Remember: 将可复用上下文写入持久化记忆
9. Trace: 将运行过程和工具调用挂到同一个 trace id
10. Approve: 对高风险工具调用创建人工确认请求
```

### 4.1 Agent 输入类型

| 输入类型 | 触发来源 | 示例 |
| -------- | -------- | ---- |
| 用户主动请求 | 前端按钮 | 推荐标签、推荐相似问题、生成辅助回答 |
| 系统事件 | FastAPI 事件通知 | 新问题、新回答、新评论 |
| 定时巡检 | Agent 定时循环 | 内容风险扫描、教师周报 |
| 管理员请求 | 后台操作 | 重新审核、生成报告、分析快照 |

### 4.2 Agent 任务类型

| 任务 | 风险 | 行为 |
| ---- | ---- | ---- |
| suggest_tags | 低 | 返回推荐标签 |
| similar_questions | 低 | 返回相似问题和原因 |
| answer_assist | 中 | 生成带来源的辅助回答 |
| moderation_scan | 高 | 创建审核快照和审核工单 |
| doc_draft | 中 | 生成文档草稿，等待确认 |
| weekly_summary | 中 | 生成教师周报 |
| mcp_tool_call | 中/高 | 调用白名单 MCP 工具，必要时触发审批 |
| memory_update | 低/中 | 写入用户偏好、课程上下文或任务经验 |

### 4.3 单 Agent Loop 设计

项目不引入 LangGraph/CrewAI。第一阶段 Agent Runtime 内部只保留一个 Agent Loop，通过 task router 把任务分发给不同处理器；这些处理器共享 loop、工具注册表、记忆层、审批策略和观测上下文。`agent/src/agents/` 仅作为第二阶段角色化扩展点。

| 任务处理器 | 职责 | 可调用工具示例 |
| ---------- | ---- | -------------- |
| supervisor | 判断任务类型、统一风险策略和自检 | classifyTask、createApprovalRequest |
| retrieval | 检索站内问题、课程上下文、记忆摘要 | searchQuestions、getQuestionDetail、readMemory |
| moderation | 内容风险判断、审核快照和工单建议 | createModerationSnapshot、createModerationCase |
| doc | ADR、Sprint 总结、教师周报草稿 | createDocDraft、readCourseContext |
| observer | 静默巡检站内事件，发现需处理事项 | listRecentEvents、enqueueAgentRun |

### 4.4 Agent 工具白名单

Agent 只能调用注册过的工具。

| 工具名 | 调用目标 | 用途 | 是否可写 |
| ------ | -------- | ---- | -------- |
| searchQuestions | FastAPI | 检索历史问题 | 否 |
| getQuestionDetail | FastAPI | 获取问题详情 | 否 |
| getCourseContext | FastAPI | 获取课程上下文 | 否 |
| listTags | FastAPI | 获取已有标签 | 否 |
| createModerationCase | FastAPI | 创建审核工单 | 是 |
| createModerationSnapshot | FastAPI | 保存审核快照 | 是 |
| createDocDraft | FastAPI 或文档服务 | 创建文档草稿 | 是 |
| getUserPublicProfile | FastAPI | 获取公开用户信息 | 否 |
| readMemory | FastAPI | 读取相关 Agent 记忆 | 否 |
| writeMemory | FastAPI | 写入可复用 Agent 记忆 | 是 |
| createApprovalRequest | FastAPI | 创建人工确认请求 | 是 |
| callMcpTool | MCP Adapter | 调用白名单 MCP 工具 | 视工具风险而定 |

高风险工具要求：

- 必须带操作者身份。
- 必须记录请求参数摘要。
- 必须记录模型判断原因。
- 不能执行永久删除。
- 不能直接执行封号。

### 4.5 MCP Adapter 设计

MCP Adapter 位于 Agent Runtime 内，负责连接白名单 MCP Server，并把 MCP 工具统一包装成受控工具。

设计规则：

- MCP Server 配置存放在 FastAPI/MySQL，由管理员维护。
- Agent 启动或刷新配置时读取已启用 MCP Server。
- 每个 MCP 工具必须映射风险等级和权限策略。
- MCP 工具调用必须写入 tool_call_logs。
- 高风险 MCP 调用必须创建 approval_requests，等待人工确认。
- MCP 不允许直接访问 MySQL，不允许绕过 FastAPI 执行业务写入。

### 4.6 持久化记忆设计

Agent 记忆保存在 MySQL，由 FastAPI 提供内部接口读写。

记忆类型：

| 类型 | 用途 | 示例 |
| ---- | ---- | ---- |
| user_preference | 用户偏好 | 常用标签、回答风格、常问课程 |
| course_context | 课程上下文 | 高频问题摘要、常见知识点、教师关注点 |
| task_experience | 任务经验 | 审核误判修正、标签推荐反馈 |
| system_note | 系统级约束 | 不同 Agent 的行为边界和策略摘要 |

记忆写入要求：

- 只能写摘要，不写敏感原文。
- 必须带来源对象和 agent_run_id。
- 用户相关记忆支持禁用或删除。
- 记忆读取按任务上下文筛选，避免无关记忆污染输出。

### 4.7 Human-in-the-loop 设计

高风险操作统一进入 `approval_requests`。

需要审批的动作：

- 删除或隐藏内容。
- 封禁或限制用户。
- 文件写入和文档发布。
- 外部 MCP 高风险工具调用。
- 可能影响用户权益的自动化建议。

审批状态：

```text
pending -> approved -> executed
pending -> rejected
pending -> expired
```

审批记录必须关联：

- agent_run_id
- tool_call_log_id
- 操作类型
- 风险等级
- 模型原因
- 证据快照
- 审批人
- 审批时间

## 5. 业务模块设计

> 本节接口路径省略 `/api` 前缀，实际部署路径以第 9.1 节为准（如 `/auth/register` → `/api/auth/register`）。

### 5.1 用户与权限

实体：

- User
- Role
- UserBan
- AuthSession
- AuditLog

关键设计：

- 密码哈希保存。
- RBAC 权限由 FastAPI dependency 实现。
- 管理操作统一写入 audit_logs。
- 封禁用户不能创建问题、回答、评论、投票。

主要接口：

- POST /auth/register
- POST /auth/login
- POST /auth/logout
- GET /users/me
- PATCH /users/me
- POST /admin/users/{id}/ban
- POST /admin/users/{id}/unban

### 5.2 课程

实体：

- Course
- CourseMember

关键设计：

- 问题必须绑定课程。
- CourseMember 记录用户在课程中的身份。
- 教师只能管理自己负责的课程。

主要接口：

- GET /courses
- GET /courses/{id}
- POST /courses/{id}/join
- GET /courses/{id}/questions

### 5.3 问题

实体：

- Question
- QuestionTag
- Tag

关键设计：

- 软删除通过 deleted_at 或 status 实现。
- Markdown 渲染前进行 XSS 清洗。
- 问题状态包括 open、resolved、closed、hidden、deleted。
- 创建问题后触发 Agent 风险扫描事件。

主要接口：

- POST /questions
- GET /questions
- GET /questions/{id}
- PATCH /questions/{id}
- DELETE /questions/{id}

### 5.4 回答

实体：

- Answer

关键设计：

- 一个问题只能有一个 accepted_answer_id。
- 采纳答案时开启事务，同时更新问题状态和声誉流水。
- 创建回答后触发通知和风险扫描。

主要接口：

- POST /questions/{id}/answers
- PATCH /answers/{id}
- DELETE /answers/{id}
- POST /answers/{id}/accept

### 5.5 评论

实体：

- Comment

关键设计：

- 评论可以挂在问题或回答下。
- 支持 parent_id 实现二级回复。
- 评论删除采用软删除。

主要接口：

- POST /questions/{id}/comments
- POST /answers/{id}/comments
- DELETE /comments/{id}

### 5.6 投票与声誉

实体：

- Vote
- ReputationLog
- UserReputation
- Badge

关键设计：

- Vote 表对 user_id + target_type + target_id 建唯一约束。
- 声誉变化必须写入 ReputationLog。
- UserReputation 保存聚合后的当前积分。
- 排行榜可由 MySQL 查询生成，后续用 Redis 缓存。

主要接口：

- POST /votes
- DELETE /votes/{id}
- GET /users/{id}/reputation
- GET /leaderboards

### 5.7 搜索与发现

关键设计：

- 第一阶段使用 MySQL LIKE 或 FULLTEXT。
- 按课程、标签、状态、时间、热度组合筛选。
- Agent 相似问题推荐先通过 FastAPI 检索候选集，再由模型排序和解释。

主要接口：

- GET /search/questions
- GET /tags/{id}/questions
- GET /courses/{id}/questions
- POST /agent/similar-questions

### 5.8 通知

实体：

- Notification

关键设计：

- 回答、评论、采纳、审核结果都会创建通知。
- 未读数第一阶段从 MySQL 查询，后续可用 Redis 缓存。

主要接口：

- GET /notifications
- POST /notifications/{id}/read
- POST /notifications/read-all

### 5.9 内容审核

实体：

- ModerationCase
- ModerationSnapshot
- Appeal

关键设计：

- Agent 负责发现风险和创建工单。
- 管理员或教师负责最终处理。
- 快照保存原内容、风险类型、触发规则、模型原因和时间。
- 审核操作写入 audit_logs。

主要接口：

- GET /admin/moderation/cases
- GET /admin/moderation/cases/{id}
- POST /admin/moderation/cases/{id}/resolve
- POST /appeals

### 5.10 Agent 运行治理

实体：

- AgentRun
- ToolCallLog
- AgentMemory
- ApprovalRequest
- McpServerConfig

关键设计：

- Agent 每次运行创建 AgentRun。
- 工具调用写入 ToolCallLog。
- 可复用上下文写入 AgentMemory。
- 高风险动作写入 ApprovalRequest。
- MCP Server 配置由管理员维护。

主要接口：

- GET /admin/agent/runs
- GET /admin/agent/runs/{id}
- GET /admin/agent/tool-calls
- GET /admin/agent/memories
- DELETE /admin/agent/memories/{id}
- GET /admin/agent/approvals
- POST /admin/agent/approvals/{id}/approve
- POST /admin/agent/approvals/{id}/reject
- GET /admin/agent/mcp-servers
- POST /admin/agent/mcp-servers

| /internal/agent/moderation/cases | POST | 创建审核工单 |
| /internal/agent/moderation/snapshots | POST | 创建审核快照 |
| /internal/agent/doc-drafts | POST | 创建文档草稿 |
| /internal/agent/runs | POST | 创建或更新 Agent 运行记录 |
| /internal/agent/tool-calls | POST | 写入工具调用日志 |
| /internal/agent/memories/search | GET | 检索相关 Agent 记忆 |
| /internal/agent/memories | POST | 写入 Agent 记忆 |
| /internal/agent/approvals | POST | 创建人工确认请求 |
| /internal/agent/mcp-servers | GET | 获取已启用 MCP Server 配置 |

内部接口要求：

- 使用服务间 token。
- 只返回 Agent 必要字段。
- 不返回密码、邮箱验证码、密钥、私密日志等敏感信息。
- 写接口必须记录 agent_run_id。
- 内部接口必须透传或生成 trace id。

## 8. 安全设计

### 8.1 权限边界

- 普通用户只能管理自己的问题、回答和评论。
- 教师只能管理负责课程下的部分内容。
- 管理员拥有全局治理权限。
- Agent 没有管理员身份，只能创建建议、草稿、工单和快照。

### 8.2 Agent 安全

- Agent 工具白名单注册。
- MCP Server 白名单注册。
- 工具调用记录日志。
- 高风险操作需要人工确认。
- Agent 不读取 .env、密钥、数据库备份和非白名单文件。
- Agent 输出需要结构化校验。
- AI 辅助回答必须标注来源和 AI 属性。
- 持久化记忆不能保存敏感原文和密钥。
- 所有审批请求必须可追溯到 AgentRun、ToolCallLog 和证据快照。

### 8.4 可观测性设计

可观测性分两层：

- 业务审计：agent_runs、tool_call_logs、approval_requests、audit_logs。
- 技术 tracing：OpenTelemetry trace id 串联 Next.js、FastAPI、Agent Runtime 和 MCP 调用。

最小要求：

- Next.js 发起 AI 请求时生成或透传 request id。
- FastAPI 接收 `/api/*` 和 `/internal/agent/*` 时记录 trace id。
- Agent 每次 loop 运行记录 agent_run_id 和 trace id。
- 每次工具调用记录 tool_call_log，并关联 trace id。
- 审批请求关联 agent_run_id、tool_call_log_id 和 moderation_snapshot。

### 8.3 内容安全

- 用户输入做长度限制。
- Markdown 输出做 HTML 清洗。
- 审核快照保留原始证据。
- 删除采用软删除，保留审计链路。

## 9. 部署设计

推荐 Docker Compose 服务：

```text
frontend
backend
agent
mysql
redis
nginx
```

### 9.1 访问入口与端口规划

学生端、教师端和管理员后台共享同一套 Next.js 前端服务，不拆成多个前端服务，也不为管理员后台单独启动 Python Web 端口。不同角色通过页面路径和 FastAPI RBAC 权限区分。

| 服务 | 开发端口 | 职责 |
| ---- | -------- | ---- |
| Next.js Frontend / BFF / AI UI | `3000` | 学生端、教师端、管理员后台、Agent 面板 |
| FastAPI Backend | `8000` | 核心业务 API、管理员 API、Agent 内部白名单 API |
| TypeScript Agent Runtime | `8787` | agent loop、tool calling、AI 流式响应 |
| MySQL | `3306` | 核心数据存储，仅内网访问 |
| Redis | `6379` | 可选缓存、限流、任务状态，仅内网访问 |
| Nginx | `80/443` | 生产统一入口 |

页面入口：

```text
/courses                 学生/教师课程空间
/questions               问答列表
/questions/[id]          问题详情
/users/me                个人中心
/admin                   管理员后台入口
/admin/users             用户治理
/admin/courses           课程治理
/admin/moderation        审核工单
/agent                   Agent 面板
```

后端接口：

```text
/api/*                   普通业务 API
/api/admin/*             管理员 API
/internal/agent/*        Agent 内部白名单 API
```

Agent 接口：

```text
/agent/*                 AI 增强能力与运行状态
```

Nginx 路由建议：

```text
/              -> frontend
/api/          -> backend
/agent/        -> agent
/docs/api      -> backend OpenAPI
```

`/internal/agent/*` 不通过 Nginx 对公网暴露。Agent Runtime 通过 Docker 内网服务名访问 FastAPI，并携带 `AGENT_SERVICE_TOKEN`。

环境变量：

- DATABASE_URL
- REDIS_URL
- AGENT_SERVICE_TOKEN
- LLM_API_KEY
- JWT_SECRET 或 SESSION_SECRET
- OTEL_EXPORTER_OTLP_ENDPOINT
- MCP_CONFIG_REFRESH_INTERVAL

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| ---- | ---- | ---- |
| Agent 范围过大 | 项目难以完成 | 第一阶段只做标签、相似问题、审核预警 |
| AI 误判内容 | 伤害用户体验 | AI 只预警，人工最终处理 |
| Agent 越权 | 安全风险 | 工具白名单、服务 token、日志审计 |
| 数据一致性复杂 | 积分和采纳出错 | 事务处理、积分流水、唯一约束 |
| 前后端服务过多 | 部署复杂 | Docker Compose 统一编排 |
| Redis 引入过早 | 增加负担 | 第一阶段可选，必要时再加 |
| MCP 工具越权 | 外部工具绕过业务权限 | MCP Adapter 白名单、风险策略、审批请求 |
| 记忆污染 | Agent 输出被错误历史影响 | 记忆分 scope、支持禁用、写入摘要而非原文 |
| 多 Agent 复杂化 | 任务分派失控 | 第一阶段只做单 Agent Loop + task router，角色化 Agent 留作第二阶段 |
| 可观测性过重 | 开发成本上升 | 第一阶段先做 trace id + 数据库日志，后续接 OTLP |
