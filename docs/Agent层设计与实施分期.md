## 目标架构

保持 Next.js、FastAPI、Agent 三服务分离，沿用 TypeScript、Hono、Vercel AI SDK、Zod，不在本批更换技术栈。

用户请求经 BFF 进入 Agent。FastAPI 校验真实登录态并提供用户身份与课程访问上下文。Agent 在可信上下文内生成计划，经工具注册表和确定性权限策略执行，再总结、自检和记录结果。数据查询、记忆、工单、Wiki 草稿与发布均经 FastAPI 白名单接口完成；MySQL 由后端统一管理。

外部内容、模型输出和客户端传入的角色、用户 ID 均不能授予权限。外部 Agent 接入、MCP 工具也不能绕过内部策略。高风险处置保持管理员确认、后端执行的边界。

## 首批：可信身份与受控运行主干（已确认方案）

### 范围和交付结果

首批交付从用户请求到运行结果的受控链路：身份校验、计划生成、工具权限检查、执行、总结自检与后端运行记录。以现有课程和问题检索工具验证主干，暂不在同一批引入 Wiki、后台调度或真实 MCP。

保留现有四类任务及其结果结构，修正默认检索客户端未传入任务上下文的问题。结构化推荐继续保留真实候选过滤与真实标签 ID 映射。已有聊天流式协议在兼容范围内复用；本批不新增面向用户的完整 AI 页面。

### 身份和授权

- BFF 从现有 HttpOnly 登录 Cookie 提取凭证并向 Agent 转发；Agent 经新增后端内部身份解析能力获取可信 principal，不共享 JWT 签名密钥。
- 内部身份解析同时要求有效服务凭证和用户登录凭证；无效、过期、封禁身份直接拒绝，不降级为匿名或管理员。
- 工具依赖从运行上下文取得用户身份，禁止接受模型生成的操作者角色和用户 ID 作为授权依据。
- 计划生成前只提供获准工具；执行前再次检查。数据范围由 FastAPI 复核，不只在 Agent 侧过滤。
- 本批接口不能把原有服务级检索直接暴露为任意用户的全站特权查询。查询范围遵守现有已登录读取、课程可见性和治理隐藏规则。

### PlanList 和执行

- 计划由结构化步骤组成，步骤至少包含唯一 ID、目标说明、工具名称与参数，整体经 Zod 校验。
- 首批采用顺序执行，每次执行都在固定工具白名单内。首轮计划最多 8 步；执行总预算最多 12 次工具调用，返工不得重置预算。
- 工具调用结果是后续步骤和总结的依据。后续参数需要使用前序结果时，由程序在当前上下文中解析和校验，不能执行字符串模板代码或任意表达式。
- 总结先做结构校验与确定性来源检查，再进行模型自检；自检不能提升权限或放宽来源检查。最多返工 1 次，仍未通过则失败，不返回未通过校验的最终建议。
- 工具名称未知、参数不合法或权限不足时拒绝该调用；权限错误不自动重试。首批只有只读工具，其他工具在各自批次接入审批与幂等策略后才能开放。
- 单次上游请求默认 60 秒超时，整次运行默认 180 秒；超时通过 AbortSignal 传播。取消、失败均写运行终态，取消和超时不被误记为成功。
- 首批不提供进程重启后自动恢复执行。持久化计划仅供追踪，不能把已有成功步骤自动重放。

### 记录和故障处理

- 使用统一的 agent_run_id 和 trace_id 关联运行、计划摘要、步骤、工具调用与结果摘要，HTTP 字段采用蛇形。
- 替换内存记录器，通过已有后端 runs/tool-calls 接口写入；若计划和步骤追踪需要新增字段或表，由 Alembic 增量迁移实现。
- 日志只记录受控、脱敏摘要，不存密码、凭证、原始思维过程或完整隐私原文。允许保存简短计划说明，不要求模型输出内部推理。
- 创建运行记录失败时，不进入模型或工具执行；执行过程中审计持久化失败时停止后续动作并报告失败，不能假报审计成功。
- 运行终态写入失败可能留下 running 记录，必须保留同一运行 ID 的错误日志并让调用方明确获知异常；后续运维收敛能力单列，不声称本批已解决所有崩溃恢复。

### 验证要求

Agent Vitest 覆盖伪造身份、工具越权、未知工具、参数错误、计划预算、返工预算、超时取消、来源检查、默认客户端注入与审计失败。后端 pytest 覆盖服务和用户双重鉴权、封禁、课程范围及记录归属。BFF 测试覆盖凭证和 trace_id 的正确转发、不向响应泄漏凭证。

按修改范围运行相关测试、各服务 lint 和类型检查；后端修改另跑分层契约，迁移在测试数据库验证。真实模型和真实数据库联调单独记录，mock 测试通过不代表已完成部署验收。

## 后续分期

1. 推荐任务和人工治理闭环：接通运行主干，风险扫描创建工单，管理员确认后由后端执行，保留既有决策白名单与状态机。
2. 个人记忆：本人作用域、授权自动更新、敏感过滤、来源记录、查看/禁用/删除以及管理员独立审计。
3. 公共 Wiki：AI 草稿、管理员审核发布、来源关联、版本历史和回滚；Tag 拆解、去重和评估围绕草稿工作流开展。
4. 教师周报、夜间值守和管理员开启的全量扫描：在已有权限、审计与幂等能力上增加调度、范围控制、进度和取消。
5. MCP 和外部 Agent：先 mock 验证，再接真实服务；统一策略不能由提示词或 skill 替代。

向量检索的存储和模型选择、周报交付方式、夜间时段、外部服务清单在相应批次开始前由用户定案，不阻塞首批运行主干设计。
