# 代码审查清单（人工审查节点用）

> 适配自 agentic-java-lab-reference 的 java-reviewer 审查员提示词，按本项目的分层基线（D-1~D-9）
> 与宪法条款本地化。用途：每个板块/任务完成后的"停下等审查"节点，按此清单逐项核对；
> 也可作为调用 TRAE-code-review 技能时的提示词基准。
>
> 立场：审查者与编写者相互独立，目标是**找出问题**而不是证明代码正确。

## 1. 审查步骤

1. 通读本次任务对应的 spec 条目（US/E/X 编号）与 tasks.md 完成判定，列出每条规则的期望实现要点。
2. `git log` + `git diff` 查看本次提交序列；逐条核对规则实现，要求给出"文件:行号"证据。
3. 核对审查记录三节是否齐全、验证记录是否为真实命令输出（可抽查复跑 `campus-overflow-ai/scripts/gate.sh`）。
4. 对每个疑点构造**具体反例输入**（参数、时序、角色组合），说明期望输出与实际输出。

## 2. 智能体常见缺陷排查（本项目高发项）

| 类别 | 排查点 | 规则依据 |
| ---- | ------ | -------- |
| 越权 | service 层是否遗漏权限判定（作者/管理员/提问者/任教教师/助教能力位）；权限判定是否写在 router 而非 domain | E-06、D-1 |
| 边界差一 | 截断上限 ±1、分页 offset、天数/次数的闭开区间 | E-02 |
| 双保险拆一 | domain 前置校验 + DB 约束兜底是否被"优化"掉一层（如 E-05 的 ensure_not_accepted + 唯一约束） | E-05 |
| 软删遗漏 | 列表/详情/统计/采纳候选是否都过滤 deleted_at；被删对象的关联引用是否悬空 | E-10 |
| 清洗顺序 | 是否先 bleach 清洗再截断；是否只清正文漏了标题 | X-03、E-02 |
| 事务边界 | commit 是否只在 service；repository 是否误用 commit；多表写入是否同一事务 | D-8 |
| 分层越界 | router 是否触碰 ORM；service 签名是否收 request schema；models 是否被跨模块 import | D-2/D-5/D-7/D-9 |
| 测试同义反复 | 新测试是否用被测代码自身常量算期望值；是否只断言"非空/状态码 200"；规则编号是否标注在 docstring | C-03 |
| 吞异常 | except 后是否静默返回默认值掩盖错误；IntegrityError 是否映射到领域异常 | 通用 |
| 提交完整性 | `git status` 是否干净；上次板块的增量是否全部入库（教训：T-04 的 3ec1d51 补提交） | 流程 |

## 4. 配套自动化（审查前置自检，机器先行）

| 检查 | 命令 | 拦截层 |
| ---- | ---- | ------ |
| 全量质量门禁 | `campus-overflow-ai/scripts/gate.ps1` | 任务收尾必跑 |
