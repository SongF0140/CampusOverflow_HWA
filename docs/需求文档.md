# CampusOverflow AI 需求文档

> 状态：草案，可继续微调  
> 项目定位：现代化校园问答平台 + 受控 AI Agent 增强层  
> 关键词：课程问答、知识沉淀、声誉激励、内容治理、agent loop、tool calling

## 1. 项目背景

高校课程答疑通常分散在微信群、QQ群、课堂口头提问和个人私聊中，问题难以沉淀，重复答疑成本高，学生也很难检索到历史高质量答案。

CampusOverflow AI 面向高校课程场景，提供一个类似 Stack Overflow 的课程问答平台。学生可以围绕课程提问、回答、评论、投票和采纳答案；教师和助教可以管理课程问答区、认证优质内容、查看学习热点；管理员可以进行用户、课程和内容治理。

在此基础上，系统引入受控 AI Agent。Agent 通过站内检索和工具调用辅助用户提问、回答、总结和审核，但不直接掌握核心业务数据的修改权。

## 2. 项目目标

### 2.1 业务目标

- 建立一个以课程为组织单位的校园问答社区。
- 将零散答疑沉淀为可搜索、可复用的课程知识库。
- 通过投票、采纳、声誉和徽章机制激励高质量回答。
- 为教师提供课程问题热点、学生参与度和典型问题沉淀能力。
- 为管理员提供内容审核、用户封禁、快照留存和申诉处理能力。

### 2.2 AI 增强目标

- 使用 Agent 帮助学生生成问题标签和优化标题。
- 使用 Agent 在提问前推荐相似历史问题，减少重复提问。
- 使用 Agent 基于站内内容生成辅助回答，并标明来源。
- 使用 Agent 静默监督新内容，发现高风险内容后创建审核工单。
- 使用 Agent 生成教师周报、Sprint 总结、ADR 草稿等辅助文档。
- 使用 agent loop 表达 AI 的持续感知、规划、工具调用、自检和记录能力。

### 2.3 工程展示目标

- 展示 FastAPI + MySQL 的完整业务后端能力。
- 展示 Next.js + React 19 + TypeScript 的现代前端、BFF 和 AI UI 工程能力。
- 展示 TypeScript + Vercel AI SDK 的 Agent 开发能力。
- 展示 Redis、Docker Compose、Nginx、CI/CD、测试和日志审计等工程能力。

## 3. 用户角色

| 角色 | 说明 | 主要诉求 |
| ---- | ---- | -------- |
| 游客 | 未登录用户 | 浏览公开问题、查看课程公开内容 |
| 学生 | 课程问答主要参与者 | 提问、回答、搜索、获得帮助、积累声誉 |
| 助教 | 课程答疑和辅助治理角色 | 回答问题、标记典型问题、协助审核 |
| 教师 | 课程空间负责人 | 管理课程、认证优质回答、查看周报和学习热点 |
| 管理员 | 平台治理角色 | 管理用户、课程、审核、封禁、系统配置 |
| AI Agent | 受控智能辅助角色 | 检索、建议、总结、预警、生成草稿 |

## 4. 核心业务模块

### 4.1 用户与权限模块

用户可以注册、登录、退出并维护个人资料。系统根据角色控制用户可访问的功能。

功能需求：

- 用户注册、登录、退出。
- 密码加密保存。
- 用户资料查看和编辑。
- 支持学生、助教、教师、管理员角色。
- 管理员可以禁用、解禁用户。
- 被封禁用户不能发帖、回答、评论或投票。
- 系统记录用户关键行为日志。

验收标准：

- 未登录用户访问受保护操作时被引导登录。
- 学生不能执行教师认证、管理员封禁等越权操作。
- 被封禁用户提交内容时系统拒绝并提示原因。

### 4.2 课程模块

课程是问答内容的主要组织单位。

功能需求：

- 展示课程列表和课程详情。
- 用户可以加入课程。
- 教师可以创建或维护自己负责的课程。
- 课程详情页展示课程问题、标签、活跃用户和高频问题。
- 问题必须归属于某一课程。

验收标准：

- 用户可以按课程查看问题。
- 教师只能管理自己负责的课程，管理员除外。

### 4.3 问题模块

问题模块承载平台最核心的提问行为。

功能需求：

- 学生、助教、教师可以发布问题。
- 问题包含标题、正文、课程、标签、状态、作者。
- 作者可以编辑自己的问题。
- 作者或管理员可以软删除问题。
- 问题详情页展示正文、回答、评论、投票、采纳状态。
- 支持 Markdown 内容。
- 系统应对问题内容进行安全清洗，避免脚本注入。

验收标准：

- 标题和正文为空时不能提交。
- 被软删除的问题不出现在普通列表中。
- 问题详情页可以完整展示问答闭环。

### 4.4 回答模块

回答模块用于围绕问题沉淀解决方案。

功能需求：

- 登录用户可以回答问题。
- 回答作者可以编辑自己的回答。
- 回答作者或管理员可以软删除回答。
- 提问者可以采纳一个最佳答案。
- 被采纳答案应在问题详情中突出展示。
- 采纳答案会触发声誉积分变更。

验收标准：

- 一个问题最多只能有一个被采纳答案。
- 用户不能采纳自己无权管理的问题答案。
- 采纳操作和积分变更必须保持一致。

### 4.5 评论模块

评论用于补充提问、追问和讨论。

功能需求：

- 用户可以评论问题。
- 用户可以评论回答。
- 支持二级回复。
- 作者可以删除自己的评论。
- 管理员可以删除违规评论。
- 评论发布后触发通知和审核检测。

验收标准：

- 评论为空时不能提交。
- 被删除评论在普通用户侧不可见。

### 4.6 标签模块

标签用于组织知识、筛选问题和辅助推荐。

功能需求：

- 问题可以绑定多个标签。
- 标签分为课程标签、技术标签和自定义标签。
- 用户发布问题时可以选择已有标签。
- Agent 可以推荐标签，但最终由用户确认。
- 支持按标签筛选问题。
- 展示热门标签。

验收标准：

- 同一问题不能重复绑定同一标签。
- AI 推荐标签不会自动写入，必须经用户确认。

### 4.7 投票与声誉模块

投票和声誉用于表达社区认可并激励高质量贡献。

功能需求：

- 用户可以对问题点赞或点踩。
- 用户可以对回答点赞或点踩。
- 用户可以取消或修改自己的投票。
- 系统防止重复投票。
- 回答被采纳、被点赞、被点踩时产生声誉流水。
- 用户主页展示声誉值和积分记录。
- 展示周榜、月榜或课程榜。

基础积分规则：

| 行为 | 积分变化 |
| ---- | -------- |
| 回答被采纳 | +15 |
| 回答被点赞 | +10 |
| 内容被点踩 | -2 |

验收标准：

- 同一用户对同一内容只能保持一个有效投票状态。
- 积分变化必须有流水记录，不能只改总分。

### 4.8 搜索与内容发现模块

内容发现帮助用户找到已有知识。

功能需求：

- 支持关键词搜索问题。
- 支持按课程、标签、时间、热度、未解决状态筛选。
- 支持查看相关问题。
- 支持热门问题列表。
- 提问前 Agent 可以推荐相似问题。

验收标准：

- 用户可以通过关键词找到标题或正文包含相关内容的问题。
- 筛选条件可以组合使用。

### 4.9 通知模块

通知让用户及时获知与自己相关的互动和审核结果。

功能需求：

- 有人回答我的问题时通知我。
- 有人评论我的问题或回答时通知我。
- 我的回答被采纳时通知我。
- 我的内容被审核处理时通知我。
- 管理员收到待审核工单通知。
- 用户可以标记通知已读。

验收标准：

- 通知数量和已读状态正确更新。
- 用户只能查看自己的通知。

## 5. Agent 增强模块

### 5.1 Agent 总体要求

Agent 是独立的 TypeScript 服务，使用 Vercel AI SDK 实现。Agent 不直接访问 MySQL，而是通过 FastAPI 提供的白名单接口获取业务上下文或提交建议。

Agent loop 的基本能力：

- 感知用户请求或系统事件。
- 判断任务类型和风险等级。
- 选择可用工具。
- 调用工具获取上下文。
- 调用模型生成结果。
- 对输出进行自检。
- 记录运行日志。
- 返回建议或创建待人工确认的操作。

### 5.2 智能标签推荐

用户发布问题时，Agent 根据标题、正文和课程推荐标签。

输入：

- 问题标题
- 问题正文
- 所属课程
- 已有标签列表

输出：

- 推荐标签列表
- 推荐理由
- 置信度

验收标准：

- Agent 只推荐，不直接绑定标签。
- 用户确认后由 FastAPI 写入标签关系。

### 5.3 相似问题推荐

用户提问前，Agent 检索历史问题并推荐可能重复或相关的问题。

输入：

- 当前问题标题
- 当前问题正文
- 所属课程

输出：

- 相似问题列表
- 相似原因
- 是否建议继续提问

验收标准：

- 推荐结果必须包含问题链接或问题 ID。
- 推荐依据应来自站内已有内容。

### 5.4 AI 辅助回答

Agent 根据站内已有问题、回答和课程资料生成参考答案。

要求：

- 明确标记为 AI 辅助参考。
- 给出引用来源。
- 不自动作为正式回答发布。
- 用户可以复制、修改或转为草稿。

验收标准：

- 没有检索来源时，Agent 应说明依据不足。
- AI 生成内容不能冒充教师或助教。

### 5.5 内容风险预警

Agent 静默检查新发布的问题、回答和评论，识别辱骂、垃圾内容、隐私泄露、恶意刷屏等风险。

处理方式：

- 低风险：记录标签。
- 中风险：创建审核工单。
- 高风险：创建审核工单并建议临时隐藏。
- 极高风险：建议紧急处理，必须人工复核。

验收标准：

- Agent 不能直接封号。
- Agent 不能直接永久删除内容。
- 每次风险判断必须保存快照和原因。

### 5.6 文档草稿生成

Agent 可以根据项目数据生成文档草稿。

允许生成：

- ADR 草稿
- Sprint 总结
- 教师周报
- 审核报告

验收标准：

- 文件写入仅限白名单目录。
- 写入前应生成可读预览。
- 文档状态默认为草稿。

## 6. 内容治理需求

内容治理采用 AI 预警 + 人工确认机制。

流程：

```text
用户发布内容
→ FastAPI 保存内容
→ Agent 静默检测
→ 命中风险时创建快照
→ 创建审核工单
→ 管理员或教师处理
→ 系统记录处理结果
→ 用户可查看通知或提交申诉
```

审核处理动作：

- 忽略风险
- 要求修改
- 临时隐藏
- 软删除
- 警告用户
- 限时封禁
- 永久封禁

封禁要求：

- AI 只能建议封禁。
- 管理员最终确认。
- 系统记录封禁原因、期限、操作者和证据快照。
- 用户可以提交申诉。

## 7. 非功能需求

### 7.1 安全

- 密码必须加密保存。
- API Key 和数据库密码不能出现在前端代码中。
- Agent 不允许访问密钥文件。
- 高风险工具调用必须经过权限校验。
- 所有管理操作必须记录审计日志。

### 7.2 可维护性

- 前端按功能模块组织。
- 后端按业务领域分包。
- Agent 工具必须白名单注册。
- 数据库结构变更必须通过迁移脚本。
- 关键架构决策需要写 ADR。

### 7.3 可测试性

- 用户认证、问答、投票、采纳、审核等核心流程需要测试。
- Agent 工具调用需要 mock 测试。
- 高风险审核逻辑需要边界测试。

### 7.4 可部署性

- 系统应支持 Docker Compose 一键启动。
- 前端、FastAPI、Agent、MySQL、Redis 可以独立容器化。
- Nginx 负责统一入口和反向代理。

## 8. MVP 范围

第一阶段必须完成：

- 用户登录注册与角色权限。
- 课程列表和课程问答区。
- 问题、回答、评论、标签。
- 采纳答案。
- 投票和基础声誉流水。
- 关键词搜索和筛选。
- Agent 智能标签推荐。
- Agent 相似问题推荐。
- Agent 内容风险预警和审核快照。
- Docker Compose 基础部署。

第二阶段可选增强：

- 教师周报。
- AI 辅助回答。
- 文档草稿生成。
- Redis 排行榜。
- 更完整的后台管理。
- 更细粒度的审计与申诉。

## 9. 待微调问题

- 前端是否只做 SPA，还是增加后台管理的独立页面布局。
- Agent 是否由前端直接调用，还是全部经 FastAPI 转发。
- Redis 是否第一阶段引入。
- 文件读写功能第一阶段是否实现。
- 内容审核高风险内容是否允许自动临时隐藏。
