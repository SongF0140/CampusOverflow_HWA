# G-04-B 计划/步骤与异步持久审计

日期：2026-10-22。依据：AG-R03、C-05/C-08、首批实施计划与后端分层基线。用户已通过 A（6f92c65）并授权继续。本块实现验证完成、人工待审查。

## 实现

新增 agent_run_events 追加表和双凭证 POST /internal/agent/user/runs/{agent_run_id}/events。事件为 plan、step_started、step_succeeded、step_failed；按父运行归属与锁校验，分配单调序号。计划最多 2 版、每版 8 步，调用准备跨计划累计最多 12 次，检查声明工具、步骤顺序、开始/结束配对。完成事件与已有 tool_call_logs 同事务写入，有未完成调用时不能标运行成功，终态不能追加。

Agent 通过请求级 audit-client/persistent-audit 等待创建、计划、准备、完成及终态记录。生产路由已替换内存单例，创建失败阻止模型，计划/准备失败阻止工具，完成记录失败阻止下一步和结果生成。普通工具故障仍可按任务语义降级，审计故障不能降级。终态写入失败不返回成功或 SSE done，也不再次改写终态以掩盖可能已提交的不确定性。

记录只包含运行类型、步骤 ID/工具名、状态、耗时等安全元数据，不记录输入、输出正文、参数值或模型 objective。客户端只走用户路径、双凭证只进请求头，响应校验 run/trace/用户归属与事件序号；异常日志仅含 run/trace/阶段，底层异常内容不输出。请求级审计对象持有客户端，RunContext 不持凭证。

## 决策与限制

step_started 表示调用前的准备记录，不证明外部调用一定发生；崩溃、取消或响应丢失可能留下未完成记录。若终态写入失败，调用方获得明确失败及 run/trace，后端可能仍为 running，或提交结果不确定；本块不提供自动恢复、重放或后台收敛。401/403 不回退服务身份，即使因此无法补写失败终态也保留脱敏错误日志。

审计采用安全元数据而非先保存原文再尝试过滤。内存类仅供独立辅助测试，HTTP 入口没有内存降级或测试模型绕过。app.ts 和前端未修改。

增量迁移、模型与网络测试均在隔离/模拟环境完成；未迁移业务数据库，不代表完整 MySQL 历史链、并发或真实模型联调已验收。G-05 的返工决策、整体超时取消与完整模型终态校验，以及 G-06 真实集成验证仍未完成。
