## 已核实的事实

1. Agent后台巡检使用服务级身份，经GET /internal/agent/patrol/contents读取清单、POST /internal/agent/patrol/cases建立旧pending工单；没有创建Workflow根任务或v2冻结申请。
2. POST /internal/agent/user/governance-requests/v2使用AgentAdmin依赖，绑定真实管理员或platform身份。FrozenGovernanceCall要求requester_id，审批来源只有admin/platform，不包含system；不能把后台服务伪装成某个管理员来复用。
3. Agent createGovernanceRequest/readApprovalWait要求用户authorization或externalKey。跨审批持久任务不能把原管理员JWT作为流程输入保存，也不能为续接自动签发管理员身份。
4. 原执行器claim扫描已有批准任务，未按workflow根任务过滤。新Workflow不能同时领取同一动作，须设计后端执行所有权和根任务关联。
5. 执行侧已有独立executor凭证、短期lease/epoch和原子回执，可复用；租约不能作为模型消息或持久恢复参数暴露。
6. WF-01明确完整loop最多5轮、同轮多动作不计轮；WF-02生产handler仍关闭。本次不改变这些行为。
