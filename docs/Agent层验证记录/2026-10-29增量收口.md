日期：2026-10-29。用户授权连续完成至 TW-02，并在过程中修订角色工具能力。代码已完成并本地验证，未推送、部署或迁移真实业务库。

## 设计依据与用户决策

已读取 AGENTS、宪法、spec/plan/tasks/analyze、Memory/RAG/Approvals 决策记录及编码/分层规则；沿用 FastAPI、Hono、既有工具规划与治理状态机，不迁移 Agent 框架。采用 brainstorming、writing-plans、TDD 和分块验证，独立模块由协作执行后在实际生产入口统一接线。

本批用户明确拍板并已落代码：

1. 审批默认等 7 天，管理员可以提前取消；只终止 Agent 续接，不撤销后端已执行处置。
2. 回答流程经验由 Agent 提交建议，老师确认后发布。工程上按负责课程隔离，未发布建议不进共享上下文，经验内容不能修改权限。
3. 助教不得认证自己的回答；教师限负责课程，助教可认证全站可见课程的其他学生回答，无需入课。
4. 学生 Agent 只问答，内部可检索/读取；教师和管理员可有受确认的角色工具。这替代早先“所有子 Agent 都只读”的宽泛表述，不改变学生平台原有手动回答/入课等业务。
5. 教师可将学生加入或移出本人负责班级；先展示学生/课程清单，由该负责教师确认后执行，不需管理员代审。
6. 管理员首批“更改”限定治理状态，已有隐藏、删除、警告、封禁；帖子/回答正文与账号资料修改另行设计。

原决策详见 Memory M-D10/M-D11、Approvals A-D07/A-D08/A-D09、TW-02 验证记录。暂无真实模型运行后的主观体验，不把 mock 测试冒充用户体验；后续反馈继续追加记录。

## 配置与运行

- 新迁移链：`tw02_assistant_cert → ap03_waits → ax_t_learning → ax_c_experiences → ax_role_commands`。在准备好的运行环境按既有部署流程应用；本轮没有改真实库。
- Agent 设置 `KNOWLEDGE_ROOT` 指向受控 Markdown 根目录；卡片放 `cards/`，三区格式见 `agent/src/knowledge/README.md`。`KNOWLEDGE_RECONCILE_MS` 默认60000，至少1000。未配置则目录明确未启用，不伪造教材资料。
- 先由负责教师维护课程可信标签来源，再在卡片元数据引用真实tag_id；正文只读，必须书签与双向链接。目录服务不捕获用户JWT，读取时仍验证当前用户课程入口。
- `MAIN_AGENT_RULES_PATH` 可指定受控JSON规则文件；缺省安全角色工具和教学行为规范。文件schema见 `memory/main-context.ts`，损坏文件失败关闭；私人会话不写此文件。
- 外部MCP在既有 `MCP_SERVER_ENABLED=true` 与 `MCP_EXTERNAL_CLIENTS` 配置下启用。管理员客户端需read/admin:query/admin:act相应scope；后端 `BACKEND_EXTERNAL_AGENT_KEYS` 为JSON数组，每项仅 `key_hash`（专属密钥SHA-256小写64位）、`user_id`（已存在管理员ID）、`enabled`。配置不得含重复hash、非法ID或额外字段；原始密钥只在专属客户端配置，不进提示或结果。
- 密钥配置变更按环境配置流程重启生效，角色/封禁变更在下一次调用从数据库重新查验。不把进程启动配置缓存描述为管理端实时密钥轮换界面。

## 决策与限制

- 审批续接当前是后端处置结果的幂等反馈；没有任意计划后半段、可执行脚本或跨进程模型栈的完整序列化恢复，不将其称为通用工作流引擎。现有管理端resolve分步提交边界未被本批重构。
- 全套教材RAG的embedding供应商、余弦混合召回、多查询融合、5→3精排、概念扩展与摘要合并尚是独立实施范围；本批目录/渐进读取不能代替这些算法。
- 教材与规则需实际配置，真实模型选择/调用、MySQL多连接锁与真实浏览器端到端仍待运行环境验收。本批测试使用mock模型/网络与隔离SQLite，未触发真实治理或外部服务发布。
- 个人记忆摘要采用受限摘录，手动维护、AI只读；浏览器历史不跨设备。清空不能撤回已发送数据，会取消在途并阻止后续再次注入。
- 认证来源目前为教师/助教类别位，尚无逐认证人独立历史表；不把类别认证解释为某个具体用户的签名证明。
