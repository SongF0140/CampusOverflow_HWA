# AP-01 管理员治理现状读取

日期：2026-10-28。实现验证通过，人工待审查。

## 设计依据

- 已读取 AGENTS.md、specs/constitution.md、specs 下的 spec/plan/tasks/analyze、.trae/rules/coding-style.md 与 conventions.md，以及 Approvals/Memory/RAG 三份设计记录。
- 用户确认治理前先查询后端现状、告知管理员，确认后复用后端 API；身份与权限由后端强制校验，等待不占连接、恢复不重复执行。
- 本块只落地 AX-R05 的现状查询基础，不把未来会话、MCP 管理员映射或审批等待实现计作完成。

## 实现

- GET /internal/agent/user/governance-targets/{target_type}/{target_id}/state。
- 服务 token 与管理员登录凭证同时必需，当前角色来自数据库；无凭证 401，非管理员/封禁管理员 403，非法类型或非正数 ID 按统一错误处理返回 400。
- target_type 支持 question/answer/comment/user；只返回目标类型、ID、current_state。内容 ready/missing/deleted/hidden；用户 active/banned/missing。
- governance/service_approvals.py 复用 qa/identity 公开 service；不 import 业务 models，不直查跨模块 ORM。带明确 response_model，不返回正文、邮箱、密码哈希或封禁原因。

## 决策说明与限制

- 复用既有内容状态探针；用户不调用 moderation_probe_user，该探针有惰性解禁副作用，改用只读 get_by_id 并显式抽取 status。
- 只报告目标自身状态；不代表父级可见、可操作动作全集或后续执行授权。操作时仍由现有治理接口重新核验，不用预览绕过审批。
- 暂未提供时间戳/版本令牌锁定、Agent 客户端适配、审批预览 UI、持久等待及恢复。user 状态报告不展开管理员角色保护等动作规则。
- 后续 AP-02 将基于现状生成可确认预览和固定动作快照，AP-03 才处理持久等待与幂等续接。
- 本批同步记录用户新决定：目录哈希增量+全量核对、加号新会话、匿名周报学习反馈、教材/教师可信标签和外部管理员凭证。均未误标代码交付。
