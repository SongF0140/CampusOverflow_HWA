## 设计依据

用户要求继续撰写 Agent 层。接续工作区已有未提交的正文接口、客户端、工具、doc_draft 与 moderation_scan 改动，保留 G-03 基础提交 02dc3bc/69354e9。依据 AG-R01/02/06、C-05/C-08、后端分层 D-2/D-5/D-9 及 plan/tasks 的 G-03-C 增量。

文档草稿可获取真实历史问题作为参考；风险扫描优先读取后端可见正文，不能假装已核验请求方摘录。正文通过 FastAPI 白名单接口获取，Agent 不直连数据库、不处置内容。目标及父级可见性必须与站内公开浏览一致。

## 实现内容

- 新增 fetchModerationTarget 白名单工具、用户/服务级正文读取接口与最小成功响应模型；客户端映射蛇形字段并校验目标类型和 ID。
- QA repository 在单次查询中筛选目标与父级可见性；回答要求父问题可见，评论要求所属问题/回答可见，二级回复还要求顶级评论可见。不存在、软删、隐藏统一 404。
- 正文查询不使用会增加浏览量的详情用例，无数据库写操作。鉴权继续由 FastAPI 复用服务 token 和当前用户依赖。
- doc_draft 执行单步只读参考计划，保留课程过滤，普通故障按无参考起草。
- moderation_scan 执行单步只读正文计划；没有原文时 reason 确定性追加“依据请求方摘录，未核验站内原文”。两类任务的 401/403 均直接失败，不调用后续模型。
- app.ts 没有修改；未重写现有计划执行器，未新增高风险执行通道。

## 决策与限制

不使用“先探针、再无条件读正文”的两段查询，避免漏掉父级可见性；实际内容查询统一加入条件。不可见正文允许使用用户自己提交的摘录做建议，但程序必须向用户标注来源，不能依赖模型自觉说明。保留现有风险分级和草稿输出结构，未引入发布或处置。

本块没有新表、新依赖或前端修改，不运行数据库迁移。测试采用 SQLite 与模拟模型/网络，不代表真实模型、MySQL 并发或部署联调通过。文档生成中的引文可靠性、模型统一规划、整体超时/返工以及持久化仍按后续计划收口；当前单步确定性计划和旧聊天循环不是完整目标架构。G-03 与本补充均保持人工待审查，不自动开始 G-04。
