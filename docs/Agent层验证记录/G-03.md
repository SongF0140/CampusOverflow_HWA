日期：2026-10-21。状态：实现与验证完成，人工待审查；本记录不代表人工批准。

## 设计依据

用户已确认 G-02 审查通过并授权进入 G-03。依据 AG-R02、C-05/C-06、Python/TS 分工边界、《Agent层设计与实施分期》“受控规划”一节与《Agent层首批实施计划》G-03。工具能力沿用 G-02 已接通的请求级注册表与三个只读低风险工具（searchCourses / searchQuestions / fetchTags），本块不新增工具、不新增数据库结构。

## 实现内容

- 计划契约集中在 `agent/src/types/plan.ts`：步骤上限 8、运行累计工具调用上限 12、步骤 ID 形如 s1、引用语法仅允许 `$input.字段` / `$s1.items[0].field`。
- 计划生成 `agent/src/loop/plan-generator.ts`：复用既有 structured output 通道产出 PlanList，生成后立即程序校验（步骤数、ID 唯一、工具白名单、必需工具、引用语法、拒绝模型指定身份字段）。
- 计划执行 `agent/src/loop/plan-executor.ts`：顺序执行；未知工具、非低风险工具、参数越权、非法引用、参数 schema 失败一律明确拒绝且不自动重试；工具运行期错误按步骤收集，由任务决定降级或失败；预算跨计划累计，返工不重置。
- 任务接入：similar_questions 经计划执行 searchQuestions 后再由模型挑选，候选 id/标题/链接仍取自站内结果；suggest_tags 使用确定性单步计划执行 fetchTags，词表命中 id 由 handler 精确匹配映射；两者均无客户端时保持原有“无依据/纯文本语义匹配”明确降级。
- moderation_scan 与 doc_draft 当前没有可用只读工具，PlanList 契约要求至少 1 步，故保持既有结构化生成，不构造空计划或虚假工具步骤；两者仍受同一任务分发、运行上下文与后续 G-04 持久化约束。
- 计划提示词集中在 `agent/src/prompts/planning.ts`，只暴露请求级注册表中已实现且低风险的工具。

## 决策与限制

计划生成仍调用模型，但执行只接受注册表白名单内的低风险工具，授权依据始终是运行上下文中的后端可信 principal，模型输出的用户/角色字段一律拒绝。suggest_tags 的工具链唯一且参数固定，因此采用确定性模板计划而不走模型生成计划，保证权限失效时零额外模型调用。首轮计划预算为 8 步、运行预算 12 次；返工与总结自检、超时取消、持久化归属分别归 G-05、G-04。测试使用模拟模型与模拟内部客户端，不代表真实三服务联调。
