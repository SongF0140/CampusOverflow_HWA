# G-05-B 超时、取消与有界收尾

日期：2026-10-22。依据 AG-R02/03、C-05/C-08、specs/plan.md 与 Agent 层首批实施计划。用户已通过 G-05-A（54bf498）；本块实现验证完成，人工待审查。

## 实现

请求级控制器连接原请求的 AbortSignal，身份解析后 beginRun 启动累计 180 秒预算；模型规划、工具、四类结构化任务、流式总结及后端 HTTP 复用运行信号。单次模型/工具/后端 HTTP（含响应体读取）默认最多 60 秒。可取消等待在上游忽略 abort 时也能退出，迟到结果不能启动后续工具或总结；SDK 传输重试关闭，取消/超时直接失败，不进入结构修复或普通工具读取降级。控制器只处理静态停止原因，不把原请求的异常正文交给模型或日志。

执行器在每步及异步审计后复查信号。中断中的调用可能只留下 step_started，失败终态允许保留这类未完成步骤，不将其伪造为工具成功。RunContext 只增加信号，不持凭证；app.ts 无改动。

取消返回 408、超时返回 504；聊天保留 meta/delta/done/error 协议，取消或超时不得发 done。SSE 读端取消也停止请求控制器；已输出片段不能撤回。失败沿用 failed 状态，error_summary 取静态的“任务已取消”“任务运行超时”“上游请求超时”。失败补写仅为同一双凭证客户端的终态 PATCH 覆写信号，最多 5 秒，后端继续检查身份、归属和状态；被 401/403 拒绝不重试、不回退服务身份。补写失败返回审计错误并留 run/trace/阶段日志。

成功终态提交中的取消可能结果不确定，返回审计异常，不盲目重写终态。成功终态确认后运行执行预算结束，之后客户端断开只影响消息送达；done/error 最多另等 5 秒，已断开则跳过，投递阻塞超时记元数据日志并关闭流，不改写已确认终态。执行预算 180 秒、失败审计最多另需 5 秒、终态消息投递最多再需 5 秒，收尾不允许继续模型或工具执行。
