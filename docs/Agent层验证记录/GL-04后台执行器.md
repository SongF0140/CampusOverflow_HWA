# GL-04 后台执行器与确定性续接

## 设计依据

GL计划第4～7节，GL-R01/02/04。仅恢复核对、反馈、完成，不恢复模型调用栈，不自行创建下一动作。新动作须重新建单人工批准；本阶段每根任务只执行一次批准，无自动连续提议。

## 验证记录

后端任务claim/report、租约过期换代、旧worker拒绝、无回执不报成功、未知转人工核对：新增4项。连同执行/批准/隔离SQLite迁移共51 passed；ruff、5分层契约通过。新增迁移gl04_job_resume只添加任务continuation字段，升级/降级/再升级通过；未操作真实库。MySQL专项仍未运行。

Agent后台与受控工具新增7项：恢复先查回执、响应丢失只核对同任务、3次核对后停止、Python/TS Unicode规范哈希一致、篡改/来源不符拒绝、缺少专用凭证零HTTP。类型和eslint通过，并运行全量回归。

## 决策说明

后端按批准→任务锁定，签发240秒不透明租约（仅存哈希），epoch防旧worker执行/覆盖。有效租约不重复领取；到期最多领取3次，超过转manual_review。已提交但未反馈的任务可再领取核对原回执。已上报未知或完成不再自动领取，report不能创造业务成功。

Agent默认每5秒串行领取1个任务，活动预算180秒。先读真实回执，未执行才调用高风险工具；失败/断线后最多按2/5/10秒核对，仍未知上报result_unknown。后台不持有JWT，关闭停止领取并取消本地在途，后端状态保留。v2创建由GOVERNANCE_EXECUTOR_ENABLED控制，读取兼容旧申请，v2不回退旧处置；模型/MCP没有批准或执行工具。

运行配置：后端BACKEND_GOVERNANCE_EXECUTOR_ENABLED=true及独立BACKEND_GOVERNANCE_EXECUTOR_TOKEN；Agent GOVERNANCE_EXECUTOR_ENABLED=true、GOVERNANCE_EXECUTOR_TOKEN与后端专用凭证一致，AGENT_SERVICE_TOKEN仍是普通服务凭证。默认不启用，部署前须完成GL-06及MySQL验收。
