## 本次实现

- 审批中心和治理申请面板识别v2，展示后端冻结的目标、动作、期限、原因、影响、参数哈希和目标版本。管理员明确确认弹窗后才提交approve，关闭弹窗不批准；不再调用旧resolve。v1保留原操作。
- 批准仅显示“已批准，等待后台执行”；领取、真实执行、未知、失效、阻断、取消、过期分别展示。未知结果只提供核对入口，不凭超时宣称失败/成功或创建替代动作。
- 人类JWT管理员可取消未执行批准；服务/执行器凭证不能取消。取消和执行共用锁顺序，已提交动作不能撤回。读取过期申请会关闭其待审授权。时间戳按UTC输出，前端按上海时区展示。
- 查询与弹窗绑定账号及申请，切换/退出停止旧请求；迟到轮询不能覆盖批准响应。提交响应丢失后继续核对原UUID，并从服务端识别v2契约，不回退旧处置。
- 受控计划明确返回waiting；高风险执行工具不进入模型/MCP工具表。hook拒绝写固定原因和关联标识，不写参数/正文；onError区分未发送、结果未知、已有执行回执，提交后的输出检查失败不得引导重放。
- 补充GL-07安全边界：记忆、会话标题/正文中的凭证格式拒绝保存；首次空会话使用幂等标识。管理员/中台目录隔离、版本比较与旧浏览器显式导入保持。

## 决策说明与交付边界

1. UI只请求后端批准/拒绝/取消，业务执行仍由专用worker工具调用后端原子接口；不让浏览器接触lease或执行器凭证。
2. 默认关闭新执行器，不在本任务启动真实治理。启用配置见GL-04验证记录：后端BACKEND_GOVERNANCE_EXECUTOR_ENABLED与专用token，Agent GOVERNANCE_EXECUTOR_ENABLED与对应token；普通服务token仍独立。
3. 私人存储需BACKEND_PRIVATE_CONTEXT_ROOT；中台映射需稳定UUID client_id，详见GL-07验证记录。未配置时明确不可用，不静默回退本地或上传旧数据。
4. 续接范围是固定核对/反馈/结束，没有自动下一轮模型治理建议，也不恢复原聊天PlanList/闭包。任何后续治理仍须新申请和人类批准；领取和结果核对均有固定上限。
