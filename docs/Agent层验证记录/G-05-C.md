## 实现与决策

生产任务与聊天共用 runReviewed：候选生成 → 程序结构/来源检查 → 无工具结构化模型审查 → 再次程序检查。程序核对真实问题 ID/标题/规范相对链接、标签 ID/名称；文本里的站内问题路径不得引用本轮未命中的 ID，编码/绝对站内来源、未知相对链接、HTML href/src 链接不能交给审查器放行。正常泛型代码不会被当作 HTML 链接。外部链接不视为已验证站内依据，程序检查不证明任意自然语言事实；切题、完整和语义依据由模型审查，不能宣称模型审查保证事实正确。

审查器只输出 passed 与固定问题代码，严格禁止多余字段；无工具、无修改结果或授权能力。反馈只用这些代码进入新计划和最终生成提示。RunContext.repairBudget 同时约束结构修复与重新规划，合计最多 1 次；每版计划最多 8 步，累计工具最多 12 次，运行总计 180 秒和取消信号保持不变。执行器在调用准备记录之前检查剩余预算，不能制造第 13 次开始事件。每次新规划重新收集证据，不能用上轮成功结果伪装本轮来源；新计划仍逐次校验课程、目标、用户权限与工具白名单。

只有来源失败或否定审查会重新规划；结构修复消耗同一预算。401/403、取消/超时、审计失败、非法计划和异常模型结束直接失败；网络错误不伪装成结构修复。审查器自身结构不合法不重试。结果仍失败时不返回未验证建议，终态沿用 failed，审计只写静态的自检/结构/工具预算错误摘要，不记录模型输出或审查原文。

聊天候选先缓冲（最多 20000 字符），通过检查后才发送 delta，保留 meta/delta/done/error 事件与标识字段。首段文本需等模型生成及审查完成，不能声称仍有逐 token 的即时展示。异常结束或检查失败的候选不会流到客户端；成功终态/消息送达规则沿用 B。app.ts、后端和前端代码均未修改，无迁移。
