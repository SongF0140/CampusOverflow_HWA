# RAG 评测标注规范

创建日期：2026-11-17。
适用范围：D-028 的 pilot 与后续扩展评测集。
状态：规范草案，配合 D-022／D-023／D-028 使用；尚未建立任何评测数据，本规范不代表已有实验结论。

## 1. 目的

为"召回 N → 融合去重 → 精排 K"提供可复算的证据标注，使 Recall@N、精排损失率、nDCG@K 等指标有统一定义，避免标注粒度不一致造成的假性漏召回。

本规范只定义标注口径，不定义检索实现，也不构成对 D-023 参数正确性的证明。

## 2. 术语与单元

| 术语 | 含义 |
| --- | --- |
| 教材 | 一本已登记且固定版本的原始资料 |
| chunk | 按章节或语义边界切分后的正文片段，是唯一的证据单元 |
| 卡片 | 领域名称、元数据、摘要三板块构成的检索入口 |
| 返回单元 | 卡片摘要 + 该卡片定位到的正文 chunk（D-022） |
| gold | 能够直接支撑答案的正文 chunk |
| distractor | 形似但不应作为证据的 chunk，如旧版本、其他课程、形近概念 |

关键约束：

- **gold 只能标在 chunk 上**，不得标在卡片摘要、章节标题或整章上。
- 摘要可以作为召回入口，但不能作为支撑答案的证据。
- 返回单元里的摘要部分不参与 Recall 计算。

## 3. chunk_id 规范

```text
<book_id>#<version>#<chapter_path>#<seq>
```

示例：

```text
cs101-ds#2024-3e#ch03/3.2#004
```

字段要求：

- `book_id`：教材登记 ID，小写字母、数字与连字符。
- `version`：教材版本标识，与登记信息一致，不使用"最新"等模糊值。
- `chapter_path`：章节路径，用 `/` 分隔；空格替换为 `-`。
- `seq`：章节内切块序号，三位数字，从 `001` 开始。

每个 chunk 另存两个字段：

- `chunk_hash`：正文归一化（去空白、统一标点）后的 SHA-256 前 12 位。
- `char_range`：在原始文档中的起止位置，用于人工复核。

规则：

1. 同一版本内 chunk_id 必须唯一且稳定；重新切块属于新版本，必须重新生成。
2. 评测集同时绑定 `chunk_id` 与 `chunk_hash`。hash 不一致说明语料漂移，该题必须重新核对。
3. 不得用随机 UUID 作为 chunk_id，否则无法人工定位。

## 4. 题目数据结构

评测集使用 JSON Lines，一行一题。

```json
{
  "query_id": "Q0001",
  "question": "为什么链表的随机访问比数组慢？",
  "sub_questions": [
    { "sub_id": "Q0001-S1", "text": "数组的随机访问为什么是常数时间" },
    { "sub_id": "Q0001-S2", "text": "链表的访问为什么需要遍历" }
  ],
  "type": "cross_chunk",
  "gold": [
    {
      "sub_id": "Q0001-S1",
      "chunk_id": "cs101-ds#2024-3e#ch02/2.1#003",
      "chunk_hash": "a1b2c3d4e5f6",
      "necessity": "required",
      "supports": "说明数组元素连续存储、按下标可直接计算地址"
    },
    {
      "sub_id": "Q0001-S2",
      "chunk_id": "cs101-ds#2024-3e#ch03/3.2#004",
      "chunk_hash": "0f9e8d7c6b5a",
      "necessity": "required",
      "supports": "说明链表节点分散存储、访问需沿指针遍历"
    }
  ],
  "distractors": [
    {
      "chunk_id": "cs101-ds#2023-2e#ch03/3.2#004",
      "reason": "旧版本教材中的同类段落"
    }
  ],
  "notes": "",
  "status": "agreed",
  "annotator": "A",
  "reviewer": "B"
}
```

字段约束：

- `sub_questions` 至少一条。D-023 按子问题独立召回，gold 必须能归属到具体 `sub_id`。
- `gold[].sub_id` 必须存在于 `sub_questions`。
- `necessity` 只允许 `required` 或 `supporting`。
- `supports` 必填，用一句话说明该 chunk 支撑了答案的哪一部分，禁止写"相关内容"。
- `distractors` 可为空，但版本混淆题必须至少一条。
- `status` 只允许 `draft`、`agreed`、`disputed`。指标计算只使用 `agreed`。
- 不得出现 gold 与 distractor 指向同一 `chunk_id`。

## 5. necessity 判定

| 取值 | 判定标准 | 是否进入主指标 |
| --- | --- | --- |
| `required` | 缺少该 chunk 就无法得出正确结论 | 是，Recall 只按 required 计算 |
| `supporting` | 有助于论证完整，但缺少它答案仍正确 | 否，单独作为辅助覆盖率报告 |

判定顺序：

1. 假设只给模型这一个 chunk，能否独立支撑正确结论？能则 `required`。
2. 不能，但能补全某个限定条件或对比项？则 `supporting`。
3. 两者都不满足，则不是 gold。

## 6. 题型与标注规则

| 题型 | 定义 | 标注要求 |
| --- | --- | --- |
| `single_chunk` | 一个问题只需一个正文块 | 恰好 1 个 required |
| `cross_chunk` | 需要多个块联合才能回答 | ≥2 个 required，且至少分布在 2 个章节 |
| `version_confusion` | 同一知识点存在新旧版本或不同课程表述 | 正确版本标 required，干扰版本标 distractor |
| `negation` | 含"除了""不包括""不需要"等否定条件 | 必须标出否定条件所在块，避免只标结论块 |
| `no_answer` | 教材内确实没有答案 | gold 为空数组，notes 写明检索验证过程 |

补充规则：

- 多子问题题的每个子问题都要有覆盖：至少一个 required，或显式标注"该子问题无需证据"。
- 跨块题不得把同一章节的相邻块拆成多个 required 来凑数；只有语义上独立承担论证的块才算。
- 版本混淆题的干扰块必须真实存在于语料中，不能虚构。
- 否定条件题如果答案是否定结论，必须同时标出被否定的前提所在块。

## 7. 无答案题

目的：检验系统是否会硬凑证据。

要求：

1. gold 为空数组，`type` 为 `no_answer`。
2. `notes` 必须记录：查过哪些关键词、检查过哪些章节、为什么确认无答案。
3. 数量占评测集 10%~15%，不得集中在同一本教材。
4. 指标的"拒答正确"指：回答明确表示资料不足，且未给出无依据结论；引用任意 chunk 即判为错误。

## 8. 标注流程

1. 冻结语料版本，生成 chunk 清单（含 chunk_id、chunk_hash、char_range、章节路径）。
2. 出题人命题并完成初标。
3. 独立标注人只看到问题与 chunk 清单，不查看初标结果。
4. 双方结果按 chunk 粒度比对，计算 Cohen's kappa。
5. kappa < 0.6 时先修规则与标注口径，不进入实验；0.6~0.8 可接受；>0.8 良好。
6. 分歧题由第三人仲裁，记录仲裁理由，写入 `notes`。
7. 全部定稿后置 `status` 为 `agreed`，锁定题集版本号。

一致性计算口径：

- 只对候选池内的 chunk 计算，不对全部语料计算，避免大量未相关项把 kappa 抬高。
- 把"某题是否把某 chunk 标为 gold"作为二分类单元。
- 分别报告整体 kappa 与分题型 kappa。

## 9. 质量检查清单

提交评测集前逐项确认：

- [ ] 每个 `chunk_id` 都能在 chunk 清单中解析到。
- [ ] 每个 `chunk_id` 与 `chunk_hash` 配对一致。
- [ ] 除 `no_answer` 外，每题至少一个 `required`。
- [ ] 每个 `sub_id` 都有 gold 覆盖或显式说明无需证据。
- [ ] `supports` 全部非空且具体。
- [ ] 无重复 `chunk_id`，无 gold 与 distractor 冲突。
- [ ] `no_answer` 占比在 10%~15%。
- [ ] 题型覆盖五类，且跨块题不少于 20%。
- [ ] 抽 10% 由第三人复核。
- [ ] 题集版本号、语料版本、切块参数已写入清单头部。

## 10. 禁止事项

- 不得用模型生成的答案反推 gold。
- 不得因为"检索结果里有这个块"就标为 gold，这是循环论证。
- 不得把卡片摘要、标题或整章标为 gold。
- 不得只标最终结论块而忽略限定条件、版本和否定前提。
- 不得在实验中途修改题集；如需修改，必须升版本并重跑全部配置。

## 11. 示例：无答案题

```json
{
  "query_id": "Q0037",
  "question": "本教材使用的编译器是哪个版本？",
  "sub_questions": [
    { "sub_id": "Q0037-S1", "text": "教材是否声明编译器及版本" }
  ],
  "type": "no_answer",
  "gold": [],
  "distractors": [],
  "notes": "检索关键词：编译器、gcc、clang、版本；检查 ch01、ch09 与附录，均只出现示例命令，未声明具体版本。",
  "status": "agreed",
  "annotator": "A",
  "reviewer": "B"
}
```
