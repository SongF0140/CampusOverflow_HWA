# CampusOverflow AI 后端架构说明

> 状态：v3（2026-09-22，分层基线微调：每模块新增 domain.py 纯规则层 + ORM 不上浮 + DomainError 收口，详见 [分层架构设计基线.md](./后端架构/分层架构设计基线.md)；v2（2026-09-20）轻量适配版，取代 plan.md 第 3/7 节中的模块组织方案）
> 原则：参照教学方案 DDD 与 news-headline 参考实现，但**不做 1:1 复刻**；以项目规模、团队情况、16 周交付节奏做取舍；不过度工程化。
> 本期范围：只做业务后端。Agent 服务不搭建（仅留接口前缀与事件钩子），前端只留接口。
> 按端拆分的接口文档见 [docs/后端架构/](./后端架构/)（学生端 / 教师端 / 管理员端三端接口文档 + Agent 预留）。

## 1. 设计原则

1. **参照而非模板**：教学方案的 DDD 四层是教学载体；news-headline 的薄三层缺少业务层。本项目取两者之间——保留分层与模块边界，砍掉对小团队纯亏的抽象。
2. **模块化单体**：单进程 FastAPI + 单库 MySQL。不拆服务、不引消息队列、不引 Redis（Q-04 已决策）。
3. **边界靠规则不靠框架**：Python 没有 Maven 的物理隔离，用可检查的 import 规则代替（见第 2.3 节）。
4. **演进留门不预建**：agent、治理逻辑只留扩展点（接口前缀、事件钩子注释位），不写任何提前实现。

## 2. 总体分层与依赖方向

### 2.1 分层方式（4.5 层：domain/service 为基座）

> 设计哲学（2026-09-22 用户定调）：**domain/service 是基座，设计好就不改、低耦合；router/schemas/models 是易变外圈**。依赖只能向内。完整规则见 [分层架构设计基线.md](./后端架构/分层架构设计基线.md)。

```text
router（接口层）     入参出参校验、权限依赖注入、调 service、返回统一响应
    ↓
service（业务层）    用例编排、事务边界、跨模块协作、发布事件钩子          ← 事务只在这一层
    ↓                      ↓
repository（数据层）  domain（规则层）   状态机、不变量、规则常量、领域异常 ← 零框架依赖，设计后冻结
    ↓
models（ORM 层）     SQLAlchemy 模型 + Alembic 迁移
```

每个模块内部统一为 **5 个文件 + 1 个可选文件**：

| 文件 | 职责 | 约束 |
| ---- | ---- | ---- |
| `router.py` | APIRouter、Pydantic 入参、Dependencies | 不写业务，不 import models，函数体不超过 10 行 |
| `service.py` | 用例编排、事务、授权决策、跨模块调用 | 事务边界唯一所在地；不 import models；不抛 HTTPException（抛 domain 领域异常）；不写规则数字 |
| `domain.py` | 纯规则：状态机、不变量、规则常量、领域异常 | **零框架依赖**（禁 import fastapi/sqlalchemy/pydantic），不起 I/O 可直接单测 |
| `repository.py` | 查询/写入函数，第一个参数恒为 `db: Session` | 仅被本模块 service 调用；**模块内唯一允许 import models 的文件** |
| `models.py` | SQLAlchemy 模型 | 不 import 本模块其他层 |
| `schemas.py` | Pydantic 入参/出参（蛇形字段） | 与 ORM 字段对应，含示例值；内部查询模型（如 UserAuthInternal）不得作为接口出参 |

### 2.2 core 横切层（复用 news-headline 的部分）

```text
core/
├── config.py         # pydantic-settings，环境变量
├── security.py       # JWT 签发/校验 + bcrypt（T-02 已有）
├── permissions.py    # 依赖注入：get_current_user / require_roles("teacher") / require_graduate_assistant
├── response.py       # Result / PageResult 统一响应（借鉴 news-headline common/）
├── errors.py         # 全局异常处理器：DomainError → 统一响应（422 归一 400）
├── domain_error.py   # DomainError 纯异常基类（零框架依赖，供各模块 domain.py 继承）
└── logging.py        # 关键行为日志
```

### 2.3 依赖方向规则（可检查，违规即返工）

1. `router` 只能调用**本模块**的 service；接口层的跨模块协作一律由 service 完成。
2. `service` 可调用本模块 repository，以及**其他模块 service 的显式函数**；跨模块传参只传 ID、标量与 schemas，不传 ORM 对象。
3. `repository` 仅本模块可见；**models 只被本模块 repository import**（分层基线 D-2，lint-imports 强制）。只读例外：`discovery.service`（纯读模块，无 repository）与 `core.permissions`（文档化豁免）。
4. `core` 被所有层使用；core **不得** import 任何 modules（`core.permissions → identity.models` 为唯一文档化豁免）。
5. 检查方式：`uv run lint-imports`（import-linter 三条契约，见 pyproject.toml [tool.importlinter]）——domain 零框架依赖、service/router 不得触碰任何 models、repository 不依赖 Web 框架。**T-03+ 新模块落地时必须同步更新契约 source_modules。**

## 3. 模块划分与职责边界

| 模块 | 职责 | 主要模型 | 对外接口前缀 | 依赖 |
| ---- | ---- | -------- | ------------ | ---- |
| `identity` | 注册登录、三角色 RBAC、个人资料、**研究生身份认证**（能力位来源） | User | `/api/auth` `/api/users` | 无 |
| `courses` | 课程列表/详情/加入、课程成员、教师课程管理（仅本人课程 E-06） | Course、CourseMember | `/api/courses` | identity |
| `qa` | 问题/回答/评论/标签、采纳、课程问答区、**助教推荐标记**（研究生专属） | Question、Answer、Comment、Tag、QuestionTag | `/api/questions` `/api/answers` `/api/comments` `/api/tags` | identity、courses |
| `interaction` | 投票、声誉流水与榜单、通知中心（三者都是"内容的衍生写"，合并避免碎包） | Vote、ReputationLog、Notification | `/api/votes` `/api/reputation` `/api/notifications` | qa、identity |
| `discovery` | 关键词搜索、组合筛选、相关推荐（纯读，无独立表） | 无（读 qa/courses models） | `/api/search` | qa、courses、identity |
| `governance` | 审核工单、申诉（**本期仅建表 + 路由占位**，逻辑随 agent 一起延后） | ModerationCase、Appeal | `/api/governance`（占位） | qa、identity |

> 与上一版（五上下文）的差异：`reputation` 并入 `interaction`（投票、声誉、通知共享"内容事件"数据流，拆开会产生三条一样的依赖边）；`discovery` 从"上下文"降级为"读模块"。

## 4. 关键数据流

### A. 发布问题（单模块）

```text
POST /api/questions
→ qa.router（QuestionCreate 校验，get_current_user 注入）
→ qa.service.publish_question(db, user, data)
   1. require 未封禁（E-07）、课程存在
   2. 标题/正文非空（E-01）、长度截断（E-02）
   3. bleach 清洗 Markdown（X-03）
   4. 开事务：repository.save(question)
   5. 【事件钩子】# TODO(agent): 此处发布 QuestionPosted，治理订阅
→ 返回 Result.success(question_out)
```

### B. 采纳闭环（跨模块，一个事务）

```text
POST /api/answers/{id}/accept
→ qa.service.accept_answer(db, user, answer_id)
   1. user 必须是提问者（E-06）
   2. 该问题无已采纳答案（E-05，repository.count_accepted 锁行校验）
   3. 同一事务内顺序执行：
      a. question.accept(answer_id) + 状态改 resolved
      b. interaction.service.grant_reputation(db, user_id=回答者, delta=+15, source="accept", ref=answer_id)
      c. interaction.service.notify(db, user_id=回答者, type="accepted", ref=answer_id)
   4. 任一步失败整体回滚 —— 保证"采纳与积分一致"（T-05 完成判定）
```

### C. 治理与 agent 预留（不实现，只留位）

- `governance` 建表（ModerationCase/Appeal）+ 路由返回 501 占位。
- qa/interaction 的 service 中以 `# TODO(agent)` 注释标出事件发布点（QuestionPosted / AnswerPosted / ContentFlagged），未来 agent 以订阅者接入，不改动现有函数签名。
- `/internal/agent/*` 前缀在 main.py 预留注释，不注册路由。

## 5. 技术选型及理由

| 决策 | 选型 | 理由 |
| ---- | ---- | ---- |
| 分层方式 | 4.5 层（router/service/domain/repository/models）：每模块设轻量 domain.py 放纯规则与领域异常，**不做聚合/ORM 双模型映射** | 课程项目双模型映射维护成本 > 收益；但规则需要"单点、可冻结、免 DB 单测"的家——domain.py 以纯函数承载不变量与规则常量，聚合仍用 ORM 模型（关键方法如 `Question.can_accept()` 上模型） |
| 模块划分 | 6 个领域包 + core，Python 包隔离 | 与教学方案"限界上下文"对齐，但用 import 规则替代 Maven 物理隔离 |
| 接口约定 | RESTful + `/api/<模块>` 前缀 + `Result{code,message,data}` 统一响应 + Pydantic schema 命名 `XxxCreate/XxxOut` | 借鉴 news-headline 的 Result；前端按前缀即可理解全站接口 |
| 权限 | FastAPI Depends：角色（student/teacher/admin）+ 能力位（`require_graduate_assistant`） | 助教并入学生端：研究生认证通过 → 解锁助教板块接口；非研究生 403，前端不渲染入口 |
| 事务 | service 显式 `with db.begin()` / commit-rollback | 跨模块协作（B 流程）需要明确回滚边界，不引入 saga/UoW 框架 |
| 跨模块协作 | service 显式函数调用，无事件总线 | 进程内单体可追踪、可打断点；事件钩子只留 TODO 注释位 |
| 认证 | JWT 无状态（T-02 已完成） | 优于 news-headline 的 token 查库：少一张表、少一次查询 |
| 迁移 | Alembic | 替代手写 database.sql，支持演进 |
| 测试 | pytest + Testcontainers（可选 SQLite 内存跑单测） | 覆盖不变式（E-01~E-11）与跨模块事务（B 流程） |

## 6. 偏离参考设计的权衡清单

| # | 偏离点 | 参照做法 | 本项目做法 | 权衡说明 |
| --- | ------ | -------- | ---------- | -------- |
| 1 | 纯 domain 层 | 教学：聚合与 ORM 双模型 | 轻量 domain.py（纯规则函数 + 领域异常），聚合仍用 ORM 模型 | 兼顾"规则单点可冻结、免 DB 单测"与"不做双模型映射"；v2 曾整体放弃 domain 层，2026-09-22 分层基线改回轻量版（见 [分层架构设计基线.md](./后端架构/分层架构设计基线.md) D-1） |
| 2 | Repository 接口抽象 | 教学：domain 定义接口 + infra 实现 | repository.py 普通函数 | 单库单体换库概率≈0，YAGNI；函数签名已隔离了数据访问细节 |
| 3 | 领域事件总线 | 教学：领域事件 + Outbox | 显式函数调用 + TODO 钩子 | 单进程内调用栈即调用链，可调试性最好；agent 接入时再升级为进程内发布器（半天工作量） |
| 4 | 助教角色 | 教学：独立角色 | 学生 + 研究生能力位 | 用户决策；权限校验从"查角色表"变"查身份字段"，少一张关联表 |
| 5 | Redis 缓存 | news-headline：缓存混在 crud | 不引入（Q-04） | 榜单/热点内存实现；缓存职责二期归 core/cache.py，不进 service |
| 6 | 多服务 | 原 plan：三服务分离 | 本期单体 + agent 占位 | 用户决策；模块化单体保证未来按包拆服务的可能性（依赖规则已就位） |
| 7 | CORS | news-headline：allow_origins=["*"] | 白名单 + 环境变量 | 安全底线 |
| 8 | 统一响应 | news-headline：Result/PageResult | 保留该设计 | 这是参考实现里最值得搬的部分 |
| 9 | ORM 上浮 | 常见写法：service/router 直接用 ORM 对象 | models 只被 repository import，service 出入参一律 schemas（D-2） | 换表/换库只动两层；代价是 repository 需提供命令式小方法（如 set_banned）并做 ORM↔schema 转换 |
| 10 | HTTPException 使用范围 | service 内随处 raise HTTPException | 仅接口层（router/permissions）可用；service/domain 抛 DomainError，main.py 统一映射（D-3） | 业务错误语义与 HTTP 协议解耦；未来加内部接口（/internal/agent/*）时复用同一套异常 |
| 11 | 工作单元（UoW）抽象 | 教学：SqlAlchemyUnitOfWork + async with uow | service 保留 `db: Session` 直接控制事务（D-4） | 彻底抽象对课设过重；Session 参数视为"事务上下文"，记录为已知耦合点，二期评估 |
