# 依赖说明

> 状态：草案，可继续微调  
> 本文档只解释依赖包为什么存在，以及它们属于哪个服务边界。具体版本以各服务的 `package.json` / `pyproject.toml` 为准。

## 1. 依赖分层原则

本项目不按“前端技术、后端技术、AI 技术”简单堆栈，而按服务边界拆依赖：

```text
frontend  = Next.js 前端 / BFF / AI UI
backend   = FastAPI 核心业务后端
agent     = TypeScript Agent Runtime
infra     = MySQL / Redis / Nginx / Docker
```

核心规则：

- Next.js 负责页面、BFF 聚合和 AI UI，不负责核心业务事务。
- FastAPI 负责用户、课程、问答、声誉、审核等核心业务。
- Agent Runtime 负责 agent loop、tool calling、模型调用和自检。
- MySQL 是核心业务数据源。
- Redis 是可选中间件，不是主数据库。
- Agent 不直接连接 MySQL，只通过 FastAPI 的 `/internal/agent/*` 白名单接口访问业务上下文。

## 2. Frontend 依赖

目录：`campus-overflow-ai/frontend/`

安装方式：

```bash
cd campus-overflow-ai/frontend
npm install
npm run dev
```

### 2.1 运行时依赖

| 包 | 归属 | 用途 |
| ---- | ---- | ---- |
| next | 前端框架 / BFF | App Router、页面路由、服务端渲染、Route Handlers、轻量接口聚合 |
| react | UI 运行时 | React 19 组件模型 |
| react-dom | UI 运行时 | 浏览器 DOM 渲染 |
| zustand | 客户端状态 | 用户会话、通知未读数、局部 UI 状态 |
| react-markdown | 内容展示 | 渲染问题和回答中的 Markdown 内容 |
| @ai-sdk/react | AI UI | 消费 Agent 的流式响应，构建 AI 辅助回答、标签推荐等交互 |

### 2.2 开发依赖

| 包 | 用途 |
| ---- | ---- |
| typescript | 类型检查 |
| eslint | 通用 Lint |
| eslint-config-next | Next.js 专用 Lint 规则 |
| tailwindcss | 样式系统 |
| @tailwindcss/postcss | Tailwind v4 的 PostCSS 集成 |
| vitest | 前端逻辑和组件测试 |
| jsdom | 测试环境中的 DOM 模拟 |
| @testing-library/react | React 组件测试 |
| @testing-library/jest-dom | DOM 断言扩展 |

### 2.3 Frontend 不应引入的依赖

| 依赖/能力 | 原因 |
| ---- | ---- |
| MySQL 驱动 | 前端和 BFF 不直接访问数据库 |
| 后端 ORM | 数据模型和事务属于 FastAPI |
| 长运行任务队列 | 长时间 agent loop 不放在 Next.js 请求生命周期里 |
| 模型 provider 密钥直连浏览器 | API Key 不能进入浏览器环境 |

## 3. Backend 依赖

目录：`campus-overflow-ai/backend/`

安装方式：

```bash
cd campus-overflow-ai/backend
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"
```

Linux/macOS 激活虚拟环境：

```bash
source .venv/bin/activate
```

### 3.1 运行时依赖

| 包 | 归属 | 用途 |
| ---- | ---- | ---- |
| fastapi | Web 框架 | 业务 API、管理员 API、Agent 内部白名单 API |
| uvicorn[standard] | ASGI 服务器 | 本地开发和容器运行 |
| sqlalchemy | ORM | MySQL 数据模型、查询、事务 |
| alembic | 数据迁移 | 表结构版本管理 |
| pymysql | MySQL 驱动 | 第一阶段使用同步 SQLAlchemy + PyMySQL |
| cryptography | 数据库连接支持 | MySQL 8 认证兼容 |
| pydantic | 数据校验 | 请求/响应模型 |
| pydantic-settings | 配置管理 | 环境变量和配置对象 |
| pyjwt | 登录鉴权 | JWT 签发和校验 |
| bcrypt | 密码安全 | 密码哈希 |
| python-multipart | 表单/文件 | 表单提交、文件上传 |

### 3.2 开发依赖

| 包 | 用途 |
| ---- | ---- |
| pytest | 后端测试 |
| pytest-cov | 测试覆盖率 |
| httpx | FastAPI TestClient 和接口测试 |
| ruff | Python Lint 和 import 排序 |

### 3.3 可选依赖

| 包 | 引入时机 | 用途 |
| ---- | ---- | ---- |
| redis | 第一阶段可不启用；需要缓存/限流时再启用 | AI 限流、排行榜缓存、热点问题缓存、任务状态 |

说明：Redis 可以出现在依赖文件里，但业务代码必须允许 Redis 未启动时降级运行，直到团队决定把 Redis 纳入第一阶段必需服务。

### 3.4 Backend 不应引入的依赖

| 依赖/能力 | 原因 |
| ---- | ---- |
| Vercel AI SDK | Agent 能力属于独立 TypeScript Agent Runtime |
| React / Next.js | 后端不负责页面渲染 |
| 任意 MCP 文件系统工具 | 后端文件写入必须走明确业务接口和权限控制 |

## 4. Agent Runtime 依赖

目录：`campus-overflow-ai/agent/`

安装方式：

```bash
cd campus-overflow-ai/agent
npm install
npm run dev
```

### 4.1 运行时依赖

| 包 | 归属 | 用途 |
| ---- | ---- | ---- |
| ai | Vercel AI SDK 核心 | 模型调用、tool calling、streaming、structured output、agent loop 基础能力 |
| @ai-sdk/openai | 模型 provider | 对接 OpenAI 或兼容接口 |
| zod | Schema 校验 | 工具入参、模型输出、自检结构 |
| hono | HTTP 服务 | 暴露 `/agent/*` 接口，适合轻量服务和 SSE |
| @hono/node-server | Node 运行时 | 在 Node.js 中运行 Hono 服务 |
| dotenv | 配置加载 | 加载 LLM_API_KEY、AGENT_SERVICE_TOKEN 等环境变量 |

### 4.2 开发依赖

| 包 | 用途 |
| ---- | ---- |
| typescript | 类型检查和构建 |
| tsx | 开发期直接运行 TypeScript |
| vitest | Agent 工具、自检、风险策略测试 |
| @types/node | Node.js 类型定义 |
| eslint | Lint |

### 4.3 Agent 不应引入的依赖

| 依赖/能力 | 原因 |
| ---- | ---- |
| MySQL 驱动 | Agent 不直连数据库 |
| ORM | Agent 不维护业务数据模型 |
| 管理员密钥 | Agent 不能伪装管理员执行高风险操作 |
| 任意文件系统写入能力 | 文件读写必须限制在白名单目录和草稿场景 |

## 5. Infra 依赖

Infra 不是某个语言包，而是运行环境依赖。

| 组件 | 用途 | 第一阶段是否必需 |
| ---- | ---- | ---- |
| MySQL | 核心业务数据存储 | 必需 |
| Redis | 缓存、限流、排行榜、Agent 任务状态 | 可选 |
| Nginx | 生产统一入口、反向代理 | 部署阶段必需 |
| Docker Compose | 本地/服务器多服务编排 | 建议必需 |

推荐端口：

| 服务 | 端口 | 说明 |
| ---- | ---- | ---- |
| Next.js | `3000` | 学生端、教师端、管理员后台、Agent 面板 |
| FastAPI | `8000` | 业务 API、管理员 API、Agent 内部 API |
| Agent Runtime | `8787` | Agent loop 和 AI 流式接口 |
| MySQL | `3306` | 仅 Docker 内网访问 |
| Redis | `6379` | 可选，仅 Docker 内网访问 |
| Nginx | `80/443` | 生产统一入口 |

## 6. 包版本协同

| 依赖组 | 协同规则 |
| ---- | ---- |
| `ai` / `@ai-sdk/react` / `@ai-sdk/openai` | 保持同代大版本，避免消息协议和 provider API 不兼容 |
| `next` / `react` / `react-dom` | 保持官方兼容版本组合 |
| `sqlalchemy` / `pymysql` | 第一阶段使用同步连接模型，不混用 async 驱动 |
| `tailwindcss` / `@tailwindcss/postcss` | Tailwind v4 使用 PostCSS 插件方式 |

升级规则：

- 升级 AI SDK 大版本前先查迁移指南，并单独提交依赖升级。
- 从同步 SQLAlchemy 切换到 async SQLAlchemy 时，需要同步修改驱动、session、repository 和测试。
- Redis 从可选变必需时，需要同步更新 Docker Compose、环境变量、健康检查和 README。
- 任何依赖变更都要同步更新本文档、对应 `package.json` 或 `pyproject.toml`。

## 7. 第一阶段推荐依赖边界

第一阶段最小可运行版本建议：

```text
frontend: next + react + tailwind + @ai-sdk/react
backend: fastapi + sqlalchemy + alembic + pymysql + pyjwt + bcrypt
agent: ai + @ai-sdk/openai + hono + zod
infra: mysql + docker compose
```

Redis、排行榜缓存、复杂任务队列、文件写入 MCP、向量数据库都不进入第一阶段必需范围。
