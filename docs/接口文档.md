## 0. 通用约定（写任何条目都先看这里）

1. **路径口径**：下表的路径是**后端 / Agent 服务口径**。前端实际调用时统一加 BFF 前缀：
   - 业务接口：后端 `/api/questions` → 前端 `/api/backend/api/questions`；
   - Agent 接口：Agent `/agent/similar-questions` → 前端 `/api/agent/similar-questions`。
   （[接口设计指南](./接口设计指南.md) 第 1 节已定：浏览器永远不直连 8000 / 8787。）
2. **响应格式固定三层**：`{ code: number, data: T, message: string }`。错误码只用 6 个：`200` 成功、`400` 参数错误、`401` 未登录/token 失效、`403` 无权限、`404` 不存在、`500` 服务器错误。
3. **字段命名**：一律小驼峰（`createdAt`、`courseId`、`pageSize`）；路径用名词复数，动作靠 HTTP 方法表达。
4. **列表接口必带分页**：请求 `?page=1&pageSize=20&sort=latest|hot|votes`；响应 `data: { items: [...], total, page, pageSize }`。
5. **鉴权**：登录态由 BFF 以 HttpOnly Cookie + `Authorization: Bearer <JWT>` 转发到后端；Agent 请求透传同一登录态。前端组件不直接读 token。
6. **链路追踪**：前端每次请求生成 request id，随 `x-trace-id` 透传，后端 / Agent 原样带回，管理端 P-A08 可据此排障。
7. **页面反馈统一口径**（所有条目共用，不再逐条重复）：

   | 后端返回 | 前端行为 |
   | -------- | -------- |
   | `200` | 按条目写的"页面反馈"执行（跳转 / 刷新 / Toast） |
   | `400` | 表单字段行内红字提示 `message`，保留用户已填内容（E-01、E-02） |
   | `401` | 跳 `/auth/login?returnTo=<当前路径>`（E-08） |
   | `403` | 行内"无权限"提示；整页级越权跳 `/403`（E-06、E-07 提示原因） |
   | `404` | 列表项移除 + 提示"内容不存在或已删除"；详情页跳 `/404`（E-10） |
   | `500` | 提示"服务暂时不可用，请稍后重试"，表单场景保留草稿（X-01） |

## 2. 前端调用条目（逐条四问）

> 每条格式：调用方与权限 → 请求 → 响应 → 错误与页面反馈 → 前端封装位置 → 对应图节点。通用错误码处理见 §0.7，条目中只写"本条特有"的部分。

### 2.1 认证与用户（API-01 ~ API-06）

#### API-01 `POST /api/auth/register` —— 注册（US-02 / T-02）

- 谁调用：游客；已登录用户访问该页直接跳回默认落地页。
- 传什么：`{ email: string(必填,邮箱格式), nickname: string(必填,2~20 字), password: string(必填,8~32 位,含字母+数字), role: "student" }`（教师角色由管理员分配，不允许自助注册）。
- 回什么：`{ code:200, data:{ id, email, nickname, role:"student", createdAt }, message:"ok" }`。
- 错了怎么办：邮箱重复或格式错误 → 400（邮箱字段行内红字）；弱密码 → 400；500 → 提示稍后重试并保留已填内容。
- 页面反馈：成功后自动登录并跳 `/`（有 `returnTo` 则回 `returnTo`）；提交中按钮 loading 且禁用。
- 前端封装：`features/auth/auth-api.ts#register`；BFF：`src/app/api/backend/[...path]/route.ts`。
- 对应图节点：F-03 → API-01 → F-04。

#### API-02 `POST /api/auth/login` —— 登录（US-02 / T-02）

- 谁调用：游客；被 401 拦截后由登录页发起。
- 传什么：`{ account: string(必填,学号或邮箱), password: string(必填) }`。
- 回什么：`{ code:200, data:{ user:{ id, nickname, role, status } }, message:"ok" }`；JWT 由 BFF 写入 HttpOnly Cookie，不进前端内存。
- 错了怎么办：账号或密码错误 → 401（统一提示"账号或密码不正确"，不区分是哪一项）；账号被封禁 → 403（提示原因，并提供"去申诉"入口 → P-S16）。
- 页面反馈：成功 → 有 `returnTo` 回 `returnTo`，否则按角色落地（学生 `/`、教师 `/teacher`、管理员 `/admin`）。
- 前端封装：`features/auth/auth-api.ts#login`，配 `useAuth()` 刷新当前用户。
- 对应图节点：F-02 → API-02 → F-04 / F-18 / F-24。

#### API-03 `POST /api/auth/logout` —— 退出（US-02 / T-02）

- 谁调用：已登录用户的顶栏用户菜单。
- 传什么：无 body。
- 回什么：`{ code:200, data:null, message:"ok" }`（后端清 Cookie）。
- 错了怎么办：401 视为已退出，仍按成功处理（幂等）。
- 页面反馈：跳 `/`，清空前端缓存的当前用户信息与未读通知数。
- 前端封装：`features/auth/auth-api.ts#logout`。
- 对应图节点：F-02 → API-03 → F-04。

#### API-04 `GET /api/users/me` —— 当前用户（US-02 / T-02）

- 谁调用：所有受保护页面的服务端守卫、学生端顶栏、`useAuth()`。
- 传什么：无参数。
- 回什么：`{ code:200, data:{ id, email, nickname, avatarUrl, role:"student|assistant|teacher|admin", status:"active|banned", reputation, createdAt }, message:"ok" }`。
- 错了怎么办：401 → 跳登录（带 `returnTo`）；500 → 页面显示错误态并可重试。
- 页面反馈：决定顶栏入口显隐（教师端 / 管理端切换入口）、按钮级权限（采纳 / 编辑 / 删除）；被封禁时全站顶部展示封禁横幅。
- 前端封装：`features/auth/use-auth.ts`（Context 缓存，避免每页重复请求）。
- 对应图节点：F-01 → API-04 → 按角色进入 F-04 / F-18 / F-24。

#### API-05 `PATCH /api/users/me` —— 修改资料（US-02 / T-02）

- 谁调用：P-S10 个人中心的资料表单（登录用户本人）。
- 传什么：`{ nickname?: string(2~20), avatarUrl?: string(可选), bio?: string(≤200) }`。
- 回什么：`{ code:200, data:{ id, nickname, avatarUrl, bio, updatedAt }, message:"ok" }`。
- 错了怎么办：400 字段非法（行内提示）；401 跳登录；500 保留输入内容。
- 页面反馈：保存成功 Toast"已保存"，顶栏昵称 / 头像即时刷新。
- 前端封装：`features/auth/auth-api.ts#updateProfile`。
- 对应图节点：F-13 → API-05 → F-13。

#### API-06 `GET /api/users/{id}` —— 用户公开主页（US-08 / T-08）

- 谁调用：P-S09 用户主页；管理端 P-A02 用户详情抽屉。
- 传什么：路径参数 `id`。
- 回什么：`{ code:200, data:{ id, nickname, avatarUrl, role, reputation, questionCount, answerCount, acceptedCount, badges:[…], joinedAt }, message:"ok" }`。
- 错了怎么办：404 → 展示"用户不存在或已注销"；500 → 错误态 + 重试。
- 页面反馈：公开信息与声誉一并渲染；不返回邮箱、手机号等隐私字段（前端也不展示）。
- 前端封装：`features/reputation/reputation-api.ts#getUserProfile`。
- 对应图节点：F-12 / F-25 → API-06。

### 2.2 课程（API-07 ~ API-14）

#### API-07 `GET /api/courses` —— 课程列表（US-01/10 / T-03）

- 谁调用：P-S02 课程列表；P-T02 我的课程；P-A03 课程管理。
- 传什么：`?keyword=&term=&page=1&pageSize=20`；教师端额外 `?mine=true` 只回自己负责的课程。
- 回什么：`{ code:200, data:{ items:[{ id, name, code, term, teacher:{ id, nickname }, memberCount, questionCount }], total, page, pageSize }, message:"ok" }`。
- 错了怎么办：400 分页参数非法（回退默认值重发）；500 错误态 + 重试。
- 页面反馈：卡片列表 + 分页；空态文案"暂时没有课程，稍后再来看看"；教师端空态带"新建课程"按钮（仅教师可见）。
- 前端封装：`features/courses/course-api.ts#listCourses`。
- 对应图节点：F-05 / F-19 / F-26 → API-07。

#### API-08 `GET /api/courses/{id}` —— 课程详情（US-10 / T-03）

- 谁调用：P-S03 课程问答区；P-T03 课程管理详情。
- 传什么：路径参数 `id`；可选 `?include=stats` 返回统计块。
- 回什么：`{ code:200, data:{ id, name, code, term, description, teacher, memberCount, questionCount, hotQuestionCount, tags:[{ id, name, count }], joined: true|false }, message:"ok" }`。
- 错了怎么办：404 → 课程不存在（跳 `/404`）；500 → 错误态 + 重试。
- 页面反馈：`joined` 决定"加入课程 / 退出课程"按钮文案；未加入时点"我要提问"提示先加入课程（否则后端 403）。
- 前端封装：`features/courses/course-api.ts#getCourseDetail`。
- 对应图节点：F-06 / F-20 → API-08。

#### API-09 `GET /api/courses/{id}/active-users` —— 课程活跃用户（US-10 / T-03）

- 谁调用：P-S03 右栏"活跃用户"区块。
- 传什么：`?limit=10`。

- 前端封装：`features/agent-assist/memory-api.ts#setMemoryEnabled`。
- 对应图节点：F-14 → API-55。

#### API-56 `DELETE /api/users/me/memories/{id}` —— 删除记忆（US-17 / T-14）

- 谁调用：P-S11 记忆项删除入口（本人）。
- 传什么：无 body。
- 回什么：`{ code:200, data:{ id, deletedAt }, message:"ok" }`。
- 错了怎么办：403 非本人；404 不存在；500 提示稍后重试且不改变列表。
- 页面反馈：二次确认弹窗（Q-01）→ 从列表移除，Toast"已删除该记忆"。
- 前端封装：`features/agent-assist/memory-api.ts#deleteMemory`。
- 对应图节点：F-14 → API-56。

### 2.12 Agent 流式接口（API-57 ~ API-59）

> 流式统一约定：`text/event-stream`，事件类型 `start | delta | source | approval-needed | done | error`；BFF 原样透传不缓冲。前端用 `@ai-sdk/react` 渲染，**三种状态必须有**：生成中、失败重试、待人工确认。

#### API-57 `POST /agent/similar-questions` —— 相似问题推荐（US-12 / T-13）

- 谁调用：P-S04 提问页（输入标题 / 正文后 800ms 防抖触发；未登录也可调用，但只返回站内公开问题）。
- 传什么：`{ title: string, body: string, courseId?: string }`。
- 回什么（SSE 流，最后一帧为汇总）：`data: { items:[{ questionId, title, similarity, reason }], suggestion:"continue|check_first" }`；无站内依据时 `items:[]` 且 `message:"未找到站内相似问题"`。
- 错了怎么办：Agent 服务不可用 / 超时 → 卡片隐藏或提示"AI 建议暂不可用"，**不阻塞提问**（X-02）；400 缺标题且正文过短 → 前端不发请求。
- 页面反馈：生成中显示骨架与"正在检索站内问题…"；命中时展示标题 + 相似度 + 理由，点击跳 P-S05（返回保留草稿）；失败显示"重试"按钮；`suggestion=check_first` 时温和提示"先看看这些是否已解决"。
- 前端封装：`features/agent-assist/agent-api.ts#similarQuestions`、`useSimilarQuestions`、`SimilarQuestionsCard`。
- 对应图节点：F-07 → API-57 → F-32 → F-08。

#### API-58 `POST /agent/suggest-tags` —— 标签推荐（US-11 / E-09 / T-13）

- 谁调用：P-S04 问题提交成功后自动触发一次（提问者本人）；结果只做建议。
- 传什么：`{ questionId: string, title: string, body: string, courseId: string, existingTagIds: string[] }`。
- 回什么（SSE 流，最后一帧为汇总）：`data: { items:[{ tagId?, name, reason, confidence }] }`。
- 错了怎么办：Agent 不可用 → 卡片隐藏（主流程已完成，不受影响）；400 缺 `questionId` → 不展示卡片。
- 页面反馈：展示"标签 + 理由 + 置信度"，用户逐个勾选后点"确认添加"才调用 API-35；**未确认绝不写入**（E-09）；确认后再展示"已添加"状态；跳过则卡片收起。
- 前端封装：`features/agent-assist/agent-api.ts#suggestTags`、`useSuggestTags`、`SuggestTagsCard`。
- 对应图节点：F-08 → API-58 → F-33 → API-35。

#### API-59 `GET /agent/events/poll` —— 事件轮询兜底（US-13/15 / T-13）

- 谁调用：第一阶段**前端不调用**（通知走 API-39 轮询）；保留给管理端 P-A08 在无 WebSocket 时获取运行事件，以及后续 Agent 事件推送。
- 传什么：`?since=<ISO 时间>`（可选 `?agentRunId=`）。
- 回什么：`{ code:200, data:{ events:[{ id, type:"moderation_case_created|approval_created|run_finished", agentRunId, traceId, targetType, targetId, createdAt }], nextSince }, message:"ok" }`。
- 错了怎么办：Agent 不可用 → 管理端退回手动刷新（不弹全局错误）。
- 页面反馈：若有新事件，P-A08 顶部提示"有新的运行事件，点击刷新"（不自动打断用户阅读）。
- 前端封装：`features/agent-assist/runs-api.ts#pollEvents`（当前仅做封装与开关，默认关闭）。
- 对应图节点：F-31（可选回路）。

### 2.13 与《全量业务拆解与增量开发蓝图.md》接口分组的一致性说明（需 SM 确认）

团队新提交的《全量业务拆解与增量开发蓝图.md》第 9 节把接口分成 9 组，其中两处与本文档（沿用[接口设计指南](./接口设计指南.md) 的口径）不同，**必须先定一套，不能两套并存**：

| 分歧点 | 蓝图第 9 节写法 | 本文档当前写法 | 建议 |
| ------ | --------------- | -------------- | ---- |
| 公开浏览 | 独立前缀 `/public/*`（或公开 `GET /api/*`） | 公开 `GET /api/*`（游客可看） | 采用"公开的 `GET /api/*`"，暂不引入 `/public/*`，避免同一份课程 / 问题数据出现两套路径 |
| 教师运营 | 新增 `/api/teacher/*`（课程热点、典型问题、课程待审） | 分散在 `/api/courses/*` 与 `/api/admin/moderation/cases?mine=true` | 采纳 `/api/teacher/*` 承载教师端聚合查询（P-T01 工作台、P-T03 课程热点、P-T04 待审列表）；治理动作仍走 `/api/admin/*`，避免教师直接调用管理接口 |
| 治理与审计 | `/api/admin/*` | `/api/admin/*` | 一致，无需改动 |
| AI 能力 | `/agent/*` + `/internal/agent/*` | `/api/agent/*`（BFF）→ `/agent/*`（Agent 服务）+ `/internal/agent/*` | 一致，无需改动 |

影响面（定稿后一次性改，不要零散改）：本文档 §1 清单中的 API-07 / API-08 / API-42 / API-43 等条目、前端 `features/courses/course-api.ts` 与 `features/moderation/moderation-api.ts` 的调用路径。

另：蓝图第 3 节里教师端的"AI 协同（查看 AI 风险原因与摘要、调整课程关注点、反馈误判）"和管理端的"AI 策略（风险阈值、自动处置规则、MCP 工具白名单）"，本文档暂未给出接口，列为待确认项 Q-F6 / Q-F7（见 [前端页面设计与跳转级联](./前端业务拆分/前端页面设计与跳转级联.md) §6.6），第一阶段可先做只读展示，不做写入口。
