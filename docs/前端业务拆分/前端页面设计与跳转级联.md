## 1. 三端划分

### 1.1 为什么"一个应用 + 三套布局"

[spec.md](../../specs/spec.md) 澄清记录 Q-02 已定：**统一 Web 端，后台管理作为应用内的独立页面区域，不拆成多个前端项目**。但群里的任务要求按"学生端 / 教师端 / 管理员端"分别设计页面与跳转，因此前端做法是：

- 一个 Next.js 16（App Router）应用，端口 3000；
- 用 **Route Group + 路由前缀** 分成三套布局（学生端顶栏、教师端侧栏、管理端侧栏），互不干扰；
- 用**角色守卫**决定哪些端可见，越权直接展示 403 页，不发起请求。

这样做同时满足"一套代码、三端体验"和"三个端各自独立设计排版与跳转"两个要求。

### 1.2 三端对照表

| 端 | 使用角色 | 路由前缀 | 布局形态 | 主要职责 | 默认落地页 |

| 管理端 | 仅管理员 | `/admin` | 左侧边栏 + 顶栏 + 主内容区 | 用户与课程治理、审核队列、审批中心（七种处置动作）、申诉复核、Agent 运行记录与 AGENTLOOP 实时监控 | `/admin`（治理总览） |

规则落地位置：**粗粒度**（未登录 → 登录页；角色前缀不匹配 → 403 页）放 `src/middleware.ts`；**细粒度**（按钮显隐，如"采纳"仅提问者可见、"新建课程"仅教师可见）放组件内，由 `useAuth()` 的当前角色判断。前端权限只做"呈现"，真正的权限判定仍在后端 service 层（[接口设计指南](../接口设计指南.md) 第 2.5 条）。

### 1.4 端间切换规则

- 顶栏右侧用户菜单提供"切换到教师端 / 管理端"入口，**只在该角色允许时出现**（教师看到教师端入口，管理员看到两个入口，学生看不到）。
- 教师端 / 管理端侧边栏底部同样提供"回到学生端"入口。
- 端间跳转一律走整页导航（`<Link>`），不做局部状态保留；跨端时清空端内筛选条件，避免把学生端筛选串到管理端列表。
- 被封禁用户登录后落到学生端 `/`，顶部展示封禁横幅，内容操作按钮全部禁用并提示原因（对应 E-07）。

### 2.4 页面三态与交互态（每页必须齐）

| 状态 | 呈现要求 | 说明 |
| ---- | -------- | ---- |
| 加载中 | 骨骼屏（列表用卡片骨架，详情用行骨架），不用整页转圈 | 首屏 SSR 数据不闪白 |
| 空状态 | 文案说明"为什么空 + 下一步做什么"，带一个主操作按钮 | 例：课程问答区无问题 → "还没有人提问，去提第一个问题" |
| 错误态 | 简短中文说明 + 重试按钮；`500` 提示"服务暂时不可用，请稍后重试"并保留草稿（X-01） | 不展示堆栈（X-04） |
| 权限态 | `401` → 跳登录（带 `returnTo`）；`403` → 403 页或行内"无权限"（E-06、E-08） | 不做静默失败 |
| AI 三态 | 生成中（流式打字/骨架）、失败重试（保留已输入内容）、待人工确认（`approval-needed`，展示确认卡片，未确认绝不写入，E-09） | AI 不可用时卡片整体隐藏，主流程不受影响（X-02） |

### 2.5 五类页面模板（排版复用）

1. **列表页**：`筛选栏（课程/标签/时间/热度/未解决） → 列表卡片 → 分页`；筛选条件全部写进 URL query，刷新可回填（US-09 验收要求）。
2. **详情页**：`面包屑 → 主体（正文 + 回答 + 评论） → 右栏（相关/相似问题、作者信息、操作入口）`。
3. **表单页**：`面包屑 → 表单卡片（字段分组） → 粘底操作条（取消 / 提交）`；提交前后都保留用户输入。
4. **工作台**：`指标卡行 → 待办列表 → 快捷入口`；指标卡点进去必须落到对应列表页并带上筛选条件。
5. **处置页（管理端专用）**：`左侧队列列表（可按风险/状态/类型筛） → 右侧详情 + 动作表单`；动作表单选动作类型 + 填说明，提交前弹确认框。

| L-04 | 任意请求 | 返回 403 | 403 页或行内无权限提示 | 不做静默失败（E-06） |
| L-05 | 任意请求 | 返回 404 / 500 | 404 页 / 500 页（保留草稿） | X-01、X-04 |
| L-06 | 三端侧栏/顶栏 | 点"切换端" | 另一端的默认落地页 | 仅角色允许时显示入口 |
| L-33 | 学生端 | 被封禁后发帖 / 评论 | 行内提示原因 + 申诉入口（P-S16） | E-07 → US-16 |
| L-34 | 任意 AI 卡片 | Agent 服务不可用 | 卡片隐藏或提示"暂不可用" | 主流程不受影响（X-02） |

### 6.2 登录与鉴权级联

```text
访问任意页面
  ├─ 公开页面（/、/courses、/questions/[id]、/users/[id]、/rankings）→ 直接渲染
  └─ 受保护页面
       ├─ 未登录 → /auth/login?returnTo=…  → 登录成功 → returnTo（无则按角色默认页）
       ├─ 已登录但角色不匹配（如学生访问 /admin）→ 403 页（不请求接口）
       └─ 已登录且角色匹配 → 渲染页面
```

- 登录态来源：`GET /api/users/me`（BFF 转发 `GET /api/users/me`，前端 `useAuth()` 缓存结果）。
- token 存放：由 BFF 写入 HttpOnly Cookie，前端组件不直接读 token（安全设计要求，前端不保存密钥类信息）。
- 退出：`POST /api/auth/logout` 后清 Cookie 并跳 `/`。

### 6.3 层级导航与返回策略

- 学生端：层级浅（列表 → 详情），保留浏览器返回即可；列表 → 详情的筛选条件写在 URL query，返回时自动回填。
- 教师端 / 管理端：层级深（工作台 → 列表 → 详情 → 处置），**每页必须有面包屑**，且提供"返回列表"按钮（带原筛选条件，如 `?status=pending`）。
- 弹窗类操作（删除、封禁、解封、处置）一律：操作 → 二次确认弹窗（Q-01）→ 提交 → 结果 Toast → 列表局部刷新；不整页跳转。
- 跨端跳转（教师/管理员 → 学生端问题详情）时，在 URL 带上 `from=teacher|admin`，页面顶部显示"返回教师端/管理端"入口，保证不会"回不去"。

### 6.5 BFF 与请求流向（前端侧口径）

```text
浏览器（同源 :3000）
  ├─ 页面数据（Server Components 直接 fetch）→ /api/backend/**  → FastAPI :8000
  ├─ 交互请求（features/<域>/xxx-api.ts）   → /api/backend/**  → FastAPI :8000
  └─ AI 请求（features/agent-assist/**）    → /api/agent/**     → Agent :8787（SSE 透传）
                                  ↑
                        BFF 统一附带 Cookie 鉴权信息、透传 x-trace-id
```

- 浏览器永远不直连 8000 / 8787，只调同源 `/api/backend/**` 与 `/api/agent/**`。
- BFF 只做转发、鉴权上下文透传、SSE 透传，不写业务规则（在 [接口设计指南](../接口设计指南.md) 第 1 节规则内）。
- 前端每个 AI 请求生成 request id，随 `x-trace-id` 透传，便于在 P-A08 按 trace 排障（可观测性要求）。
