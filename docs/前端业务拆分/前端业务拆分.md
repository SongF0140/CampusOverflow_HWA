# 前端业务拆分（按模块）

> 状态：v1（2026-09-07，依据 specs/tasks.md v1 + specs/plan.md v2 + docs/项目骨架分析.md）
> 范围：仅 `campus-overflow-ai/frontend/`（Next.js 16 App Router + React 19 + TS 5 + Tailwind 4 + @ai-sdk/react）
> 用途：把 tasks.md 中与前端相关的工作按业务模块拆分，便于分工与逐模块落地。

## 0. 通用约定（所有模块必须遵守）

- 路由放 `src/app/**`，页面默认 Server Components；仅表单交互、浏览器 API、流式 UI、局部状态需要时加 `"use client"`。
- 业务 UI、hooks、client API 封装放 `src/features/<域>/`；`src/app/api/**` 只做 BFF 转发、鉴权上下文传递和 SSE 透传，不写核心业务规则。
- 后端统一响应格式 `{ code, data, message }`，前端按 `code` 判定成功/失败（200 成功，400/401/403/404/500 对应提示）。
- 每个页面必须提供加载、空状态、错误状态；涉及 AI 流式输出必须能显示生成中、失败重试和人工确认。
- 界面文案全部简体中文；样式用 Tailwind，避免行内样式；禁大面积蓝紫渐变与"AI 产品模板感"。
- 状态管理：简单状态用组件内 state，服务端数据封装 fetch hooks，必要时 Zustand；不引入 TanStack Query。
- 测试用 vitest，文件命名 `*.test.ts(x)`；每个模块的 hooks 与关键交互组件需覆盖测试。
- 401 统一引导登录，403 统一展示无权限，不做静默失败。

## 2. 模块详细拆分

### M0 全局骨架与共享基础（T-01，已完成）

- 现状：目录骨架、`layout.tsx`、`page.tsx`、`/api/health`、vitest、eslint 已就绪。
- 待补（随其他模块逐步落地）：
  - `shared/components/`：Button、Input、Card、Modal、EmptyState、ErrorState、LoadingSpinner、Pagination、MarkdownRenderer（渲染前 XSS 清洗）。
  - `shared/hooks/`：`useFetch` 基础封装（统一 `{ code, data, message }` 解析、401 跳登录、错误提示）。
  - `shared/types/`：API 响应泛型 `ApiResponse<T>`、通用分页类型。
  - `shared/utils/`：日期格式化、文本截断。
- 完成判定（前端侧，T-01 已验收）：lint 零 error、vitest 通过、`/api/health` 联通三服务。

### M1 认证与权限（T-02）

- 目标：注册、登录、退出、资料查看编辑；按学生/助教/教师/管理员角色控制可见路由与操作入口。
- 页面与文件：
  - `/auth/login/page.tsx`：登录表单（学号/邮箱 + 密码），校验与错误提示。
  - `/auth/register/page.tsx`：注册表单（角色选择：学生/教师；字段校验）。
  - 全局：顶栏用户菜单（登录/退出/资料入口）、未登录访问受保护页引导登录。
  - `features/auth/`：`useAuth`（当前用户上下文，存 token）、`auth-api.ts`（BFF 封装）、表单组件。
  - `src/app/api/auth/**`：BFF 转发登录/注册/退出，Cookie 或 header 传递鉴权上下文。
- 权限呈现规则：管理员见后台入口；教师见课程管理入口；越权访问路由展示禁止页（不请求接口）。
- 完成判定（前端部分）：未登录访问受保护操作被引导登录；越权操作展示 403 状态；表单空提交被拦截。

### M2 课程（T-03）

- 目标：课程列表/详情/加入课程；教师管理自己负责的课程；课程页展示问题、标签、活跃用户、高频问题。
- 页面与文件：
  - `/courses/page.tsx`：课程列表（搜索、分页，Server Component）。
  - `/courses/[id]/page.tsx`：课程详情页，含课程内问题列表、标签云、活跃用户、高频问题区块。
  - 加入课程：详情页内交互按钮（学生加入/退出）。
  - `/admin/courses/page.tsx`：教师管理自己课程（创建/编辑、成员查看）；管理员可管理全部。
  - `features/courses/`：`course-api.ts`、`useCourses`、`useCourseDetail`、加入/退出交互组件。
- 完成判定（前端部分）：教师看不到他人课程的"管理"入口；课程页各区块有空状态；加入课程即时反馈。

### M3 问题与搜索（T-04、T-09）

- 目标：问题发布/编辑/软删除；Markdown 渲染前 XSS 清洗；列表关键词搜索 + 课程/标签/时间/热度/未解决状态组合筛选；相关问题和热门列表。
- 页面与文件：
  - `/page.tsx`：首页 = 问题列表（默认最新/热度），顶部搜索框与筛选器。
  - `/questions/new/page.tsx`：发布问题（标题、正文 Markdown 编辑器、选课程、选标签、AI 推荐入口接 M9）。
  - `/questions/[id]/page.tsx`：问题详情（Markdown 渲染 + XSS 清洗，展示状态、作者、标签、投票接 M7、回答接 M4、评论接 M5）。
  - `/questions/[id]/edit/page.tsx`：编辑问题（作者本人；软删除入口带确认弹窗）。
  - `features/questions/`：`question-api.ts`、`useQuestions`（筛选参数组合）、`useQuestionDetail`、MarkdownEditor、QuestionCard、StatusBadge、SearchFilterBar。
- 交互约束：空标题/空正文禁止提交并提示；超长输入截断提示；软删除二次确认；已删除问题从列表消失。
- 完成判定（前端部分）：筛选条件可组合且 URL 可回填；关键词命中标题或正文的结果正确展示；脚本内容渲染前被清洗。

### M4 回答与采纳（T-05）

- 目标：回答发布/编辑/软删除；提问者采纳最佳答案；采纳答案突出展示。
- 页面与文件：
  - `/questions/[id]` 页内回答区：回答列表（按采纳/时间/票数排序）、回答表单（登录后可见）、编辑/删除入口（作者本人）。
  - 采纳按钮：仅提问者可见；采纳后该回答置顶并高亮标识"已采纳"。
  - `features/answers/`：`answer-api.ts`、`useAnswers`、AnswerCard、AnswerForm、AcceptButton。
- 完成判定（前端部分）：非提问者看不到采纳按钮；一个问题仅展示一个已采纳答案；采纳操作成功后列表刷新且积分提示一致。

### M5 评论（T-06）

- 目标：评论问题/回答，支持二级回复；作者删自己的评论，管理员删违规评论；评论触发通知（通知由后端产生，M8 展示）。
- 页面与文件：
  - `/questions/[id]` 页内评论组件（挂在问题与每个回答下）：一级评论列表 + 二级回复折叠展开。
  - `features/comments/`：`comment-api.ts`、`useComments`、CommentList、CommentForm、CommentItem（删除入口按权限显示）。
- 交互约束：空评论禁止提交；删除二次确认；被删评论普通用户不可见（管理员可见占位或审计视图）。
- 完成判定（前端部分）：二级回复正常收起/展开；权限不符者看不到删除入口；删除后列表即时更新。

### M6 标签（T-07）

- 目标：课程/技术/自定义标签展示与选择；问题多标签绑定；按标签筛选与热门标签；AI 推荐标签须经用户确认后写入。
- 页面与文件：
  - 标签选择器（嵌入 M3 发布/编辑问题页）：搜索已有标签、多选、新建自定义标签入口。
  - 标签云与热门标签（嵌入课程详情页与首页筛选器）。
  - AI 推荐标签确认卡片（数据来自 M9）：展示标签 + 理由 + 置信度，用户逐个勾选确认后才提交写入。
  - `features/tags/`：`tag-api.ts`、`useTags`、TagSelector、TagList、AiTagSuggestion（仅确认 UI，请求发起在 M9）。
- 交互约束：重复绑定提交时展示后端 400 提示；未勾选确认的 AI 推荐绝不发起写入请求。
- 完成判定（前端部分）：未确认的 AI 推荐不产生任何写入；按标签筛选列表正确。

### M7 投票与声誉（T-08）

- 目标：问题/回答点赞点踩（可修改、取消）；用户主页展示声誉；周/月/课程榜单。
- 页面与文件：
  - 投票按钮组件（嵌入问题详情页与每条回答）：当前票数、已投状态高亮、重复投票时更新而非新增。
  - 用户主页 `/users/[id]`：声誉值、积分变动摘要（近期流水）。
  - 榜单页 `/rankings`（或首页侧栏区块）：周榜/月榜/课程榜切换。
  - `features/reputation/`：`vote-api.ts`、`reputation-api.ts`、`useVotes`、VoteButtons、ReputationPanel、RankingTabs。
- 完成判定（前端部分）：同一内容同一用户仅呈现一个有效投票状态；投票后票数即时更新；榜单切换正确请求对应参数。

### M8 通知（T-10）

- 目标：被回答/被评论/被采纳/审核结果/待审核工单通知；标记已读；仅本人可见。
- 页面与文件：
  - 顶栏通知铃铛：未读数徽标、下拉最近通知。
  - 通知列表页 `/notifications`：全部/未读切换、点击跳转来源、全部已读与单条已读。
  - `features/notifications/`：`notification-api.ts`、`useNotifications`、NotificationBell、NotificationList。
- 完成判定（前端部分）：通知仅展示当前用户自己的；已读后未读数减少；点击可正确跳转来源页。

### M9 AI 助手（T-13，联调 T-11/T-12）

- 目标：提交问题前推荐相似问题（含链接）；提交后推荐标签（含理由与置信度）；结果仅建议，用户确认后由后端写入。
- 页面与文件：
  - 相似问题推荐卡片：嵌入 `/questions/new`，输入标题/正文时触发（防抖），展示相似问题标题 + 链接；无站内依据时明确提示"未找到站内相似问题"。
  - 标签推荐卡片：问题提交成功后展示推荐标签 + 理由 + 置信度，用户确认后调用后端写入（写入动作在后端，前端只发确认请求）。
  - `features/agent-assist/`：`agent-api.ts`（走 `src/app/api/agent/**` BFF）、`useSimilarQuestions`、`useSuggestTags`、SimilarQuestionsCard、SuggestTagsCard。
  - `src/app/api/agent/**`：BFF 透传 Agent 服务流式/JSON 响应，不缓冲 SSE。
- 流式 UI 要求（`@ai-sdk/react`）：必须有生成中（loading）、失败重试（retry）、需要人工确认（approval-needed）三种状态展示。
- 完成判定（前端部分）：推荐展示不阻塞提问主流程；未确认不写入；Agent 服务不可用时优雅降级为隐藏卡片。

### M10 管理后台（T-15、T-16）

- 目标：审批中心处理动作（忽略/修改/临时隐藏/软删除/警告/限时封禁/永久封禁）；封禁记录与申诉复核；内容审核；用户管理；Agent 运行记录查看。
- 页面与文件：
  - `/admin/moderation/page.tsx`：审批工单列表（按风险等级/状态/类型筛选）；工单详情展示快照、原因、关联 agent_run_id；处置动作表单（选择动作 + 填写说明，提交后由 FastAPI 执行）。
  - `/admin/moderation` 申诉区：封禁记录列表（原因/期限/操作者/快照）、申诉提交入口（用户侧）与复核操作（管理员侧）。
  - `/admin/users/page.tsx`：用户管理（搜索、查看状态、封禁/解封，管理员权限）。
  - `/admin/courses/page.tsx`：课程管理（见 M2，管理后台入口）。
  - `/agent/runs/page.tsx`：Agent 运行记录（按 trace id / agent_run_id 检索，展示状态、输入输出摘要、失败原因、关联 tool call 与审批工单）。
  - `/agent/drafts/page.tsx`：Agent 生成的草稿列表（doc-draft，占位页，随 T-15/后续任务填充）。
  - `features/moderation/`：`moderation-api.ts`、`useApprovalRequests`、ApprovalList、ApprovalDetail、AppealForm、BanRecordList。
  - `features/agent-assist/` 补充：`runs-api.ts`、`useAgentRuns`。
- 权限：整组 `/admin/**`、`/agent/runs` 仅管理员/教师角色可见，M1 的路由守卫统一处理。
- 完成判定（前端部分）：处置动作提交后工单状态更新并留痕展示；按 trace id 可查完整调用链页面；所有列表有筛选与空状态。

## 3. 建议实施顺序

  └─ M1 认证 ──> M2 课程 ──> M3 问题+搜索 ──> M4 回答采纳 ──> M5 评论

                    │              ├─> M6 标签（可先做选择器，AI 部分等 M9）
                    │              └─> M7 投票声誉 / M8 通知（可并行）

## 4. 与后端/Agent 的对接注意点

- 所有请求经 `src/app/api/**` BFF 转发到 FastAPI（8000），Agent 请求转发到 Agent 服务（8787，经 `/agent/` 路由），前端不直连数据库、不直连 MySQL。
- BFF 透传 `x-trace-id`，页面侧如有需要可读取展示（便于 M10 排障）。
- 流式接口（Agent）在 Route Handler 中透传 SSE，不缓冲（plan 风险 T-04）。
- 后端接口路径以 docs/项目骨架分析.md 第 9 节为准（`/api/auth/*`、`/api/questions/*` 等）；Agent 面向前端接口为 `/agent/suggest-tags`、`/agent/similar-questions`、`/agent/answer-assist`、`/agent/runs/{id}`、`/agent/events/poll`。
