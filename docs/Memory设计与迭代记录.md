## M-D01：账号隔离与渐进式上下文（用户已确认）

- 用户原话：“每个人单独账号访问的时候会把记忆+到他访问的上下文中，而这里上下文是渐进式披露的”。
- 用户访问时，读取当前账号自己的个人记忆，加入其访问场景的上下文。
- 上下文采用渐进式披露，不把所有个人记忆一次性加载给模型。
- 继续遵守浏览器按账号隔离与清空要求；用户未改变当前记忆存储位置，也未要求个人记忆改存公共 Markdown 知识库。
- 用户未在本条授权自动新增、更新或删除个人记忆；产生与维护方式仍需沿用已确认边界或另行设计。

## M-D02：三层渐进披露方案（用户已确认）

用户于 2026-10-28 回复“是这样的设计”，确认前一轮提出的三层披露方案：第一层相关偏好/主题/索引，第二层按课程、问题或任务展开摘要，第三层在需要时读取具体条目。披露指模型实际收到的内容逐步增加，而非界面折叠。

| 层 | 披露内容 | 目的 |
| --- | --- | --- |
| 第一层 | 与当前场景相关的简短偏好、记忆主题或条目索引 | 用较少上下文判断哪些记忆值得展开 |
| 第二层 | 与当前课程、问题或任务相关的记忆摘要 | 为当前回答选择必要背景 |
| 第三层 | 仅对仍需细节的条目展开具体内容 | 补足证据或偏好细节，避免全量读取 |

以下为衔接与实现注意事项，不能将本轮对三层方案的确认扩大为具体协议、自动记忆写入或所有工程细节已定案：

- 披露的“层”指模型收到的内容，不只是页面折叠；不能先把完整记忆发给模型，再声称只披露摘要。
- 访问账号及其权限来自可信登录链路，不能根据记忆文本指定账号。浏览器命名空间隔离是产品行为，不应宣称抵御同源脚本或恶意篡改的安全隔离。
- 建议建立上下文装配职责，将账号记忆、当前会话和有权查看的教材/认证问答来源分别标识；个人记忆不是站内知识证据，也不能授予访问或工具权限。
- 若需多轮按需读取浏览器条目，应明确前端与 Agent 的披露协议；当前单次发送最新 20 条的接口不自动具备按需回取能力。
- 清空后后续请求不再注入；账号切换应同时丢弃上一账号在客户端及服务端会话中的已装配缓存。已发送上下文的在途运行如何取消或失效，需要单独明确，不能声称浏览器删除能撤回已发数据。

### M-D04：用户“线程”为隔离的逻辑会话（用户已确认）

- 用户原先以“主agent的子进程里面新建一个线程”描述用户访问方式。

## 2026-10-28 主 Agent 记忆范围、规则与子 Agent 权限

### M-D07：主 Agent 记忆限定范围（用户已确认）

- 用户原话：“主agent记忆只包括知识领域，道德skill的披露和回答流程的经验，工具调用的规则（子agent的工具权限由主agent决定）。以及优质回答的链接（这个也是卡片渐进式披露，加载到了直接给子agent一个链接回答跳转）”。
- 主 Agent 记忆限于：知识领域目录；道德/行为规范 skill 的披露信息；回答流程经验；工具调用规则及子 Agent 工具分配依据；优质认证回答的链接卡片。
- 此范围替代对“主 Agent 记住所有知识点”的宽泛理解：教材正文与完整领域知识仍由 RAG 提供，个人记忆/私人会话不进入主 Agent 共享记忆。
- 优质回答链接采用卡片渐进式披露；命中可复用的认证问答时向子 Agent 提供真实可定位链接，用于回答跳转，沿用 D-016 的极相似问题直达分支，不自动重新生成认证答案。
- 不能仅因卡片被加载就认定内容适用；认证状态、目标存在/可见和问题条件仍要核验，不制造题目或答案链接。

### M-D08：主 Agent 分配能力，子 Agent 只读（用户已确认）

- 用户明确子 Agent 只有读、搜索等受限功能，工具集由主 Agent 决定。
- 与已确认后端强校验边界衔接：主 Agent 在后端身份/角色及工具白名单允许范围内裁剪子 Agent 能力，不能突破后端授权或启用子 Agent 写操作。
- 执行侧必须强制检查“后端可授权能力 ∩ 主 Agent 分配能力 ∩ 子 Agent 只读能力”；不能只在提示词写不许调用。模型提出的工具选择仍要由程序验证。
- 子 Agent 不直接创建/修改/删除业务内容，不执行治理或修改身份；需要处置时交主 Agent 的审批协调路径，由管理员确认后复用后端 API。
- 外部 MCP 的管理员主体不自动把普通用户子 Agent 改成可写治理 Agent，两个调用角色需分别建模。
- 道德 skill 提供行为指导，权限边界继续由后端与工具执行器强制检查；skill 的文字内容不构成权限授予。

### M-D09：领域知识与规则变化触发更新（用户已确认）

- 用户原话：“领域知识更新和规则更新是触发主agent更新方式”。
- 领域知识变化触发主 Agent 知识目录/入口更新；规则变化触发 skill 披露信息与工具规则更新。
- 领域更新沿用哈希增量+定期核对；规则与目录更新应有版本，避免一个执行单元读取一半新一半旧的内容。
- 更新触发来自受控资料/规则来源，不把用户提问或不可信检索正文中的指令当成规则更新。
- 规则收紧或后端权限变化应在工具执行前复核，不能以会话旧快照维持已撤销能力。
- 回答流程经验的来源、筛选、确认及更新触发尚未确定；不从本条推断模型可自动把任意会话写成全局经验或修改权限规则。

以上为目标设计，主 Agent/子 Agent 的运行对象、版本更新与能力分配尚未接入生产代码。
