# 教师端接口文档

## 1. 课程管理（courses）

> T-03 已落地（2026-09-30）：本节字段按 2026-09-20 定案统一为**蛇形**。

### POST /api/courses —— 创建课程（US-10）

1. 谁调用？`require_roles(teacher)`；学生 / 管理员（经本接口）→ 403。
2. 传什么？

   | 字段 | 类型 | 必填 | 说明 |
   | ---- | ---- | ---- | ---- |
   | name | string | 是 | 课程名，≤ 50 字 |
   | code | string | 是 | 课程编码，全局唯一 |
   | description | string | 否 | 课程简介，≤ 500 字 |
   | semester | string | 否 | 学期标识，≤ 20 字（T-03 定案：自由字符串，精确匹配筛选） |

3. 回什么？`{ code: 200, data: { id, name, code, description, semester, teacher_id, created_at, updated_at }, message: "课程创建成功" }`；创建者自动写入 `teacher_id`。
4. 错了怎么办？课程编码重复 → 400；非教师 → 403；缺必填 → 400。

### PATCH /api/courses/{id} —— 编辑课程（US-10、E-06）

1. 谁调用？**仅本课程负责教师**（管理员走同一接口不受此限）；他人课程的教师 → 403（E-06）。
2. 传什么？`{ name?, description?, semester? }`（部分更新，None 表示不修改；**编码不在可编辑字段内**——T-03 定案，编码是课程标识，接口原"编码改为重复值 → 400"随之作废）。
3. 回什么？`{ code: 200, data: { id, name, code, description, semester, teacher_id, created_at, updated_at }, message: "课程更新成功" }`
4. 错了怎么办？非本人课程 → 403（E-06）；课程不存在 → 404。

### GET /api/courses/{id}/members —— 成员列表（US-10）

1. 谁调用？本课程教师 / 管理员；他人课程教师 / 学生 → 403（E-06）。
2. 传什么？query：`page`、`page_size`。
3. 回什么？`{ items: [{ user_id, username, joined_at }], total, page, page_size }`
4. 错了怎么办？课程不存在 → 404；无权查看 → 403。

## 2. 课程问答区与学习热点（courses + discovery，纯读）

### GET /api/courses/{id}/questions —— 课程问答区（US-10、US-09）

1. 谁调用？登录用户（教师与学生共用同一接口，教师无额外写权限）。
2. 传什么？query：`page`、`page_size`、`sort=latest|hot`（`hot` 即学习热点 / 高频问题）、`unresolved?`、`tag_id?`。
3. 回什么？`{ items: [问题卡片], total }`；课程页四个聚合区块复用本接口 + GET /api/courses/{id}。
4. 错了怎么办？课程不存在 → 404；未登录 → 401。

## 3. 研究生助教认证审核（identity，Q-07 / US-20 前置）

> 路径已于 2026-09-30 随 T-02a 实施落定（原为建议值），并回填 `plan.md` 第 5 节；归属 identity 模块（`/api/users` 前缀）。

### GET /api/users/assistant-certifications —— 认证申请列表（已落地，T-02a）

1. 谁调用？`require_roles(teacher)`。
2. 传什么？query：`status=pending|approved|rejected`（默认 pending）、`page`、`page_size`。
3. 回什么？统一响应信封的 `data` 为 `{ items: [{ user_id, username, certification_status, applied_at }], total, page, page_size }`（申请者均为研究生身份，不含证件等隐私原文）。
4. 错了怎么办？非教师 → 403；未登录 → 401。

### POST /api/users/{id}/assistant-certification/review —— 审核认证（已落地，T-02a）

1. 谁调用？`require_roles(teacher)`；未登录 → 401。
2. 传什么？`{ action: "approve"|"reject", comment? }`。
3. 回什么？`{ code: 200, data: { id, username, assistant_cert_status: "approved"|"rejected", ... }, message: "审核完成" }`；**approve 即时置位助教能力位** → 该用户学生端助教板块接口（`require_graduate_assistant`）立刻放行；reject 维持 403。
4. 错了怎么办？目标用户不是研究生 → 400；目标不存在 → 404；重复审核（非 pending）→ 400。审核动作写审计日志（操作者 / 时间 / 对象 / 结果，comment 仅入日志）。

## 4. 治理接口（governance，一期占位）

### /api/governance/* —— 审批中心（US-13、US-14）【第二阶段】

第一期所有 `/api/governance/*` 路由返回 **501**；ModerationCase / Appeal 表已建。第二阶段随 T-15 交付真实逻辑：待确认工单列表 / 详情 / 七类处置动作（忽略 / 要求修改 / 临时隐藏 / 软删除 / 警告 / 限时封禁 / 永久封禁），全部处置留审计。

## 5. 接口总览

| 接口 | 方法 | 说明 | 权限 | 阶段 |
| ---- | ---- | ---- | ---- | ---- |
| /api/courses | POST | 创建课程 | require_roles(teacher) | 一期 |
| /api/courses/{id} | PATCH | 编辑课程（仅本人课程，E-06） | 本课程教师 | 一期 |
| /api/courses/{id}/members | GET | 课程成员列表 | 本课程教师 / 管理员 | 一期 |
| /api/courses/{id}/questions | GET | 课程问答区 / 学习热点（sort=hot） | 登录 | 一期 |
| /api/users/assistant-certifications | GET | 助教认证申请列表（建议路径） | require_roles(teacher) | 一期（随 T-02a） |
| /api/users/{id}/assistant-certification/review | POST | 助教认证审核（approve 置位能力位） | require_roles(teacher) | 一期（随 T-02a） |
| /api/answers/{id}/certify | POST / DELETE | 优质内容认证 / 取消（仅本人任教课程内的回答） | require_roles(teacher) | 一期（随 T-05） |
| /api/governance/* | 任意 | 审批中心占位 | — | 一期 501（逻辑二期 T-15） |
