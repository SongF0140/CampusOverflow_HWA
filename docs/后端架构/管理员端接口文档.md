# 管理员端接口文档

## 1. 用户治理（identity，US-02、E-07 —— T-02 已实现）

> 路径挂在 users 模块（`/api/users` 前缀），**不使用** `/api/admin/*` 前缀，以 T-02 实现为准。

### GET /api/users —— 用户列表（T-02 已实现）

1. 谁调用？`require_roles(admin)`；学生 / 教师 → 403；未登录 → 401。
2. 传什么？query：`page`（≥1，默认 1）、`page_size`（1~100，默认 20；query 参数名与代码一致为蛇形）。
3. 回什么？`{ code: 200, data: { items: [{ id, username, email, role, status, ban_reason, reputation_score, bio, avatar_url, created_at }], total, page, page_size } }`（完整信息，含邮箱与封禁原因）。
4. 错了怎么办？非管理员 → 403；未登录 → 401；分页参数越界 → 当前由 FastAPI 返回 422，统一异常处理时归一为 400（已知偏差，见第 5 节）。

### POST /api/users/{id}/ban —— 封禁用户（US-02、E-07，T-02 已实现）

1. 谁调用？`require_roles(admin)`；学生 / 教师 → 403。
2. 传什么？

   | 字段 | 类型 | 必填 | 说明 |
   | ---- | ---- | ---- | ---- |
   | reason | string | 是 | 封禁原因，≤ 200 字，落库 `ban_reason` |

   无期限字段：封禁为**无限期**，直至解禁（期限支持见 1.5 差距表）。
3. 回什么？`{ code: 200, data: { id, status: "banned", ban_reason, ... }, message: "用户已封禁" }`
4. 错了怎么办？目标用户不存在 → 404；目标为管理员账号 → 400（"不能封禁管理员账号"）；非管理员 → 403；reason 缺失 / 超长 → 422（归一说明同上）。

### POST /api/users/{id}/unban —— 解禁用户（US-02，T-02 已实现）

1. 谁调用？`require_roles(admin)`；非管理员 → 403。
2. 传什么？无 body。
3. 回什么？`{ code: 200, data: { id, status: "active", ban_reason: null, ... }, message: "用户已解禁" }`
4. 错了怎么办？用户不存在 → 404；非管理员 → 403；对未封禁用户调用幂等成功（status 置 active、原因清空）。

### 1.4 封禁的全局效果（E-07 联动）

当前实现比 spec E-07 的"四类写互动被拒"语义**更严格**：

- **登录即拒**：`POST /api/auth/login` 对 status=banned 返回 403"账号已被封禁，请联系管理员"。
- **旧 token 一并失效**：`get_current_user` 对 banned 用户一律 403，所有需登录接口（含只读浏览）均不可用。
- **公开信息脱敏**：`GET /api/users/{id}`（无需登录）不返回 email 与 ban_reason。

T-03+ 实施时若按 spec 放宽为"可读不可写"，需同步回改本节与[学生端接口文档](./学生端接口文档.md)对应约定。

### 1.5 与需求的差距（实现现状，待后续任务澄清）

| 需求表述 | T-02 实现现状 | 处理建议 |
| ---- | ---- | ---- |
| 记录原因、期限、操作者 | 仅 reason 落库（ban_reason）；无期限字段；操作者经 JWT（require_roles 依赖）追溯，未单独落审计表 | 期限字段与独立审计日志表随后续任务评估补齐，或修订需求表述 |
| 所有治理动作可回答"谁在什么时候对什么做了什么" | 封禁时间可由数据行变更追溯，无不可删改的审计日志 | 同上；二期审批中心（T-15）处置审计必须先补审计基建 |

## 2. 内容治理追溯（qa，E-10 —— 随 T-04 落定）

> 建议路径形态，实施时落定并回填 `plan.md` 第 5 节；归属 qa 模块（复用 `/api/questions` 等前缀，不新开 `/api/admin/*`）。

### GET /api/questions?status=deleted —— 软删内容追溯（建议形态）

1. 谁调用？`require_roles(admin)`——`status=deleted` 仅对管理员放行；其他用户携带该值 → 403。
2. 传什么？query：`status=deleted`（普通用户不传或传 published）、`page`、`courseId?`。
3. 回什么？`{ items: [问题卡片，含 deletedAt、deletedBy], total }`；回答 / 评论追溯采用同形态（`/api/answers`、`/api/comments` 管理员参数）。
4. 错了怎么办？非管理员 → 403；未登录 → 401。

验收口径（E-10）：管理员列表接口可查已软删内容；普通用户列表与详情接口不可见（返回 404 或不出现于列表）。
