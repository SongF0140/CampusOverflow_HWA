## 1. 认证与用户（identity）

### POST /api/auth/register —— 注册（US-02）

1. 谁调用？未登录访客。
2. 传什么？

   | 字段 | 类型 | 必填 | 说明 |
   | ---- | ---- | ---- | ---- |
   | username | string | 是 | 用户名，唯一，3~50 字符 |
   | email | string | 是 | 邮箱，唯一，格式校验 |
   | password | string | 是 | 6~100 位（T-02 实现约束）；bcrypt 哈希存储，日志不落明文 |
   | role | string | 是 | `student` / `teacher`（管理员不由注册产生）；**当前 T-02 实现固定注册为 student，role 入参随后续任务与 spec 对齐** |

3. 回什么？`{ code: 200, data: { id, username, role }, message: "ok" }`
4. 错了怎么办？邮箱 / 用户名重复或格式错误 → 400；缺字段 → 400。

### POST /api/auth/login —— 登录（US-02）

1. 谁调用？未登录访客。
2. 传什么？`{ account, password }`（account 支持用户名或邮箱，T-02 实现）。
3. 回什么？`{ code: 200, data: { access_token, token_type: "bearer", user: { id, username, role, reputation_score, ... } } }`；助教能力位标识（字段随 T-02a 落定）。
4. 错了怎么办？凭证错误 → 401（"账号或密码错误"）；被封禁 → 403（"账号已被封禁，请联系管理员"）；缺字段 → 400。

### POST /api/auth/logout —— 退出（US-02，紧凑条目）

登录用户；无 body；回 `{ code: 200 }`；未登录 → 401。

### GET /api/users/me —— 当前用户信息（US-02）

1. 谁调用？登录用户（页面鉴权依赖此接口）。
2. 传什么？无（JWT 即凭证）。
3. 回什么？统一响应信封的 `data` 为 `{ id, username, email, role, status, reputation_score, identity_type, assistant_cert_status, bio, avatar_url, created_at }`（`identity_type` 为 undergraduate/postgraduate，`assistant_cert_status` 为 none/pending/approved/rejected；接口字段均为蛇形）。
4. 错了怎么办？未登录 / token 失效 → 401。

### PATCH /api/users/me —— 资料编辑（US-02，紧凑条目）

登录用户；body 传可改字段（昵称 / 头像等，密码修改需 `oldPassword`）；回更新后 user；邮箱改为重复值 → 400；未登录 → 401。

### POST /api/users/me/assistant-certification/apply —— 申请助教认证（US-20 / Q-07，T-02a）

1. 谁调用？登录学生（能力位仅学生角色的附加能力位）。
2. 传什么？无 body；申请即声明研究生身份（`identity_type` 置 postgraduate）并进入待审核，教师审核把关。
3. 回什么？更新后的 user（`identity_type=postgraduate`，`assistant_cert_status=pending`）。
4. 错了怎么办？非学生角色申请 → 400；已是 pending / approved 时重复申请 → 400；rejected 可重新申请；未登录 → 401。

### GET /api/users/{id}/reputation —— 用户公开声誉（US-08）

1. 谁调用？登录用户。
2. 传什么？路径参数 `id`。
3. 回什么？`{ user_id, username, reputation_score, question_count, answer_count }`（**不含积分流水**，E-11；回答计数仅排除回答自身软删，不额外受父问题软删限制）。
4. 错了怎么办？用户不存在 → 404。

### GET /api/users/{user_id}/questions —— 用户问题列表（契约适配）

1. 谁调用？登录用户，可读取指定用户的可见问题，不限本人。
2. 传什么？路径 `user_id`；query `page=1`、`page_size=20`，page ≥ 1，page_size 为 1～100。
3. 回什么？统一响应 data `{ items: [§3问题卡片], total, page, page_size }`，包含真实 `course_name` 和当前浏览者 `my_vote`；仅该用户创作的未软删问题，按创建时间降序、id 降序。空用户内容或超出末页返回空 items；total 是过滤后的总数。
4. 错了怎么办？未登录 → 401；用户不存在 → 404；非法路径/分页参数 → 400。不返回邮箱、积分流水或其他用户私有资料。
5. 分层：路径归用户命名空间，由 interaction service 调用 identity/qa 公开 service 并批量装配票态，QA 不反向依赖 interaction。

### GET /api/users/{user_id}/answers —— 用户回答列表（契约适配）

1. 谁调用？登录用户，可读取指定用户的可见回答，不限本人。
2. 传什么？路径 `user_id`；query `page=1`、`page_size=20`，边界同上。
3. 回什么？统一响应 data `{ items: [{ id, question_id, question_title, body, vote_score, is_accepted, recommended_by_assistant, certified_by_teacher, created_at }], total, page, page_size }`。body 为入库后已清洗内容；只读该用户回答，同时排除软删回答及父问题软删的回答；按回答创建时间降序、id 降序。`is_accepted` 严格由父问题 `accepted_answer_id == 回答id` 判定，不以问题状态或教师/助教标记代替。
4. 错了怎么办？未登录 → 401；用户不存在 → 404；非法路径/分页参数 → 400；无内容或超出末页为空 items。
5. 与公开声誉 answer_count 区分：本列表额外过滤父问题软删；§1 公开声誉计数原契约不变。由 QA service 调用 identity 公开 service 校验用户，回答与父问题查询只在 QA repository 内完成。

## 2. 课程（courses）

> T-03 基础已落地（2026-09-30）：字段统一为**蛇形**；四聚合区块与 question_count 当前仍空数组/0，US-10 一期交付缺口纳入 T-09 补交，设计待批准。推荐由 discovery 承载课程 GET 视图，courses 保留基础读写；不让 courses 依赖 qa。
>
> 待批四聚合：hot_questions/frequent_questions 都用本课程 `sort=hot` 前10问题卡片；tags 为 `{id,name,type,question_count}`，可见问题绑定数降序/id升序前10；active_users 为 `{user_id,username,activity_count}`，累计可见课程提问数+归属可见本课程问题的可见回答数降序/user_id升序前10存在用户，不计评论/投票，不限角色/成员。该活跃窗口及“高频=热门”均为新增推荐，不是原 US-10 已定统计规则。课程列表 question_count 为真实可见问题数；空课程为空数组/0。

### GET /api/courses —— 课程列表（US-10）

1. 谁调用？登录用户。
2. 传什么？query：`page=1`、`page_size=20`（1～100）、`keyword?`（名称 / 编码模糊）、`semester?`（精确）、`mine=false`。`mine=true` 仅返回 `teacher_id == 当前用户id` 的负责课程，不是已加入课程；学生即使已加入也不会因此命中 mine。筛选同时作用于 items 和 total，可组合使用。
3. 回什么？`{ items: [{ id, name, code, teacher_name, member_count, question_count, joined, created_at }], total, page, page_size }`。joined 是当前用户真实成员状态，按本页课程一次批量装配；负责教师不自动视为已加入。
4. 错了怎么办？未登录 → 401；非法分页/mine 参数 → 400；无匹配课程返回空 items 和 total=0。

### GET /api/courses/{id} —— 课程详情（US-10）

1. 谁调用？登录用户。
2. 传什么？路径参数 `id`。
3. 回什么？`{ id, name, code, description, semester, teacher_name, joined, is_owner, can_post, aggregates: { hot_questions, tags, active_users, frequent_questions }, created_at }`。joined 为当前用户真实加入状态，`is_owner = teacher_id == 当前用户id`，`can_post = is_owner or joined`，与发布问题课程资格一致。负责教师未加入仍可发布；非负责且未加入者不可发布。can_post 只表达课程资格，不替代接口 JWT/封禁检查；聚合问题卡片同样包含真实 course_name。
4. 错了怎么办？课程不存在 → 404；未登录 → 401。

### GET /api/courses/{id}/questions —— 课程问答区（US-10，T-09 待批未实现）

登录用户；query 与问题列表一致：`keyword?`、`tag_id?`、`sort=latest|hot`、`unresolved?`、`created_from?`、`created_before?`、`page=1`、`page_size=20`（1～100）；course_id 固定取路径，不接受覆盖。回 `{items:[问题卡片],total,page,page_size}`，包含真实本人 my_vote；课程不存在404，空课程返回空列表。时间与排序契约见§7，热门复用sort=hot，不另建高频算法。

### POST /api/courses/{id}/join —— 加入课程（US-10）

1. 谁调用？登录学生（教师 / 管理员 → 403，已落地 T-03）。
2. 传什么？无 body。
3. 回什么？`{ code: 200, data: { joined: true }, message: "已加入课程" }`
4. 错了怎么办？已加入 → 400；课程不存在 → 404；未登录 → 401。

### DELETE /api/courses/{id}/members/me —— 退出课程（US-10，紧凑条目）

登录学生（仅本人）；回 `{ joined: false }`；未加入 → 400；课程不存在 → 404。

## 3. 问题与标签（qa）

> T-04 已落地问题部分（2026-09-30）：字段按蛇形定案；**T-07 已落地标签部分（2026-10-02）**：发布 tag_ids / 列表 tag_id 筛选 / tags 字段均为真实值，tags 元素为 `{ id, name, type }`；vote_score / my_vote 已接入真实投票状态（my_vote 为当前用户票向 1/-1，未投为 0）；T-08 架构整改及验收仍未完成。内容上限定案：标题 ≤ 100 字、正文 ≤ 20000 字（超长截断并在 message 提示，E-02）。发布资格：课程负责教师可直接发，其余用户须已加入课程。

### POST /api/questions —— 发布问题（US-03、E-01/E-02/E-07、X-03）

1. 谁调用？登录用户；未登录 → 401；被封禁 → 403（E-07）。
2. 传什么？

   | 字段 | 类型 | 必填 | 说明 |
   | ---- | ---- | ---- | ---- |
   | title | string | 是 | 最长 100 字，超长截断（E-02） |
   | body | string | 是 | Markdown 正文；入库前 bleach 清洗（X-03）；≤ 20000 字，超限截断提示（E-02） |
   | course_id | int | 是 | 已加入的课程（负责教师除外） |
   | tag_ids | int[] | 否 | 已有标签 id，最多 5 个（T-07 已落地；同请求重复 → 400 E-03，未知 id → 400） |

3. 回什么？`{ code: 200, data: { id, title, status: "published", created_at }, message: "发布成功" }`
4. 错了怎么办？空标题 / 正文 → 400（E-01）；未加入课程 → 403；课程不存在 → 404。含脚本的 body 被清洗后正常入库，不报错（X-03）。

> 事件钩子：service 内 `# TODO(agent): QuestionPosted`（一期仅注释，已落地）。

### GET /api/questions —— 问题列表（US-03、US-09）

1. 谁调用？登录用户。
2. 传什么？query：`page`、`page_size`、`course_id?`、`tag_id?`（T-07 已落地）、`sort=latest|hot`、`unresolved?`、`keyword?`（命中标题或正文）。
3. 回什么？`{ items: [{ id, title, course_id, course_name, author, tags, status, vote_score, my_vote, answer_count, view_count, has_accepted, created_at }], total, page, page_size }`；course_name 通过 courses 公开批量 service 读取真实课程名，搜索、相关问题、课程问答区和聚合卡片共用同一装配（已软删内容不出现在结果中，E-10；tags 为该问题绑定标签 `{ id, name, type }` 按绑定时间正序；sort=hot 按投票分降序、创建时间降序）。
4. 错了怎么办？未登录 → 401；非法 sort 值 → 400。

### GET /api/questions/{id} —— 问题详情（US-03）

1. 谁调用？登录用户；浏览数 +1。
2. 传什么？路径参数 `id`。
3. 回什么？`{ id, title, body(已清洗文本), course_id, course_name(真实课程名), author, tags, status, vote_score, my_vote, accepted_answer_id, view_count, created_at, updated_at }`（回答 / 评论经 §4、§5 接口分页获取）。
4. 错了怎么办？不存在或已软删 → 404（E-10）。

### PATCH /api/questions/{id} · DELETE /api/questions/{id} —— 编辑 / 软删除（US-03，紧凑条目）

仅作者（DELETE 另允许管理员）；body 同发布（可部分字段）；DELETE 无 body；软删除后普通列表与详情不可见（E-10）；非作者 → 403；不存在 → 404。删除需前端二次确认（Q-01，前端二期实现）。

### GET /api/tags —— 标签列表（US-03，T-07 已落地）

1. 谁调用？登录用户。
2. 传什么？query：`keyword?`（名称模糊）、`hot?`（true=热门：按可见问题绑定数降序取前 10，只含有绑定的标签，T-07 定案审查可调）。
3. 回什么？`{ items: [{ id, name, type, question_count }] }`（type=course/tech/custom，T-07 定案；question_count 只统计未软删问题，E-10；不带分页）。
4. 错了怎么办？未登录 → 401。

### GET /api/tags/{tag_id} —— 标签详情（契约适配）

登录用户；路径 tag_id；无 query/body；统一响应 data `{ id, name, type, question_count }`。question_count 仅统计未软删问题的绑定数，零绑定或绑定问题全部软删时仍返回标签详情和 question_count=0；标签不存在 → 404，未登录 → 401，非法路径参数 → 400。详情是资源读取，与发布/绑定请求体引用未知标签返回 400 的原契约明确区分；不产生标签或绑定写入。

### POST /api/questions/{id}/tags —— 问题绑定标签（US-03、E-03/E-09，T-07 已落地）

1. 谁调用？问题作者（增量追加语义，非全量替换）。
2. 传什么？`{ tag_ids: [int | str] }`——int 为已有标签 id；str 为新自定义标签名（内联创建，type=custom，名称全局唯一，同名复用）。每问题标签总数上限 5（T-07 定案，审查可调）。
3. 回什么？`{ code: 200, data: { tags: [{ id, name, type }] }, message: "绑定成功" }`（绑定后该问题的完整标签集，按绑定时间正序）。
4. 错了怎么办？重复绑定（与既有重复或同请求内重复）→ 400（E-03）；标签 id 不存在 → 400；标签名为空 → 400；非作者 → 403；问题不存在或已软删 → 404；未登录 → 401。

> AI 推荐标签：用户确认后才调用本接口写入（E-09）；后端无任何自动绑定路径（发布入参与本接口是仅有的两个写入点）。推荐本身为二期 Agent 能力（T-13），本期不实现。

## 4. 回答与采纳（qa）

> T-05 已落地（2026-09-30）；2026-10-03 核验：字段按蛇形定案，vote_score / my_vote 已接入真实投票状态；回答正文上限复用 20000 字（超长截断并提示，E-02）；`certified_by_teacher` 为优质内容认证标记（D9 定案）。采纳已接入问题侧写入（置采纳 + 状态 resolved）及回答者 +15 总分与流水，共用 Session 提交；通知仍随 T-10 回填。工作区已完成T-08单向编排与异常回滚本地整改，不等于人工审查通过；真实MySQL并发验收仍未完成。

### GET /api/questions/{id}/answers —— 回答列表（US-04）

登录用户；query `sort=latest|votes|accepted`、`page`、`page_size`；回 `{ items: [{ id, author, body(已清洗), vote_score, my_vote, is_accepted, recommended_by_assistant, certified_by_teacher, created_at }], total, page }`；问题不存在 / 已删 → 404；软删回答不可见（E-10）；sort=accepted 将被采纳回答置顶突出展示；sort=votes 按投票分降序、创建时间降序、回答 id 降序。

### POST /api/questions/{id}/answers —— 回答问题（US-04、E-07）

1. 谁调用？登录用户（任何登录用户可回答可见问题，无课程成员限制）；被封禁 → 403（E-07，get_current_user 统一拦截）。
2. 传什么？`{ body }`（Markdown，入库前清洗 X-03；≤ 20000 字，超限截断提示 E-02）。
3. 回什么？`{ code: 200, data: { id, status: "published", created_at }, message: "回答成功" }`
4. 错了怎么办？空内容 → 400（E-01）；问题不存在 / 已删 → 404。

> 事件钩子：service 内 `# TODO(agent): AnswerPosted`（一期仅注释，已落地）。

### PATCH /api/answers/{id} · DELETE /api/answers/{id} —— 编辑 / 软删除（US-04，紧凑条目）

仅作者（DELETE 另允许管理员）；软删除（E-10）；非作者 → 403；不存在 / 已删 → 404；空正文 → 400（E-01）。**已采纳回答被删除时，同一事务撤销问题采纳并回退 published，但不冲销历史采纳 +15 积分及流水**（E-10，既定政策）。

### POST /api/answers/{id}/accept —— 采纳（US-06、E-05/E-06）

1. 谁调用？**仅提问者**；未登录 → 401；其他用户 → 403（E-06）。
2. 传什么？无 body。
3. 回什么？`{ code: 200, data: { accepted: true, question_status: "resolved" } }`；采纳后问题详情 `status=resolved`、`accepted_answer_id` 回填；顺序重复采纳被拒绝（E-05）；采纳列唯一约束不能证明同一问题并发采纳不同回答安全，真实 MySQL 并发验收待完成。
4. 错了怎么办？非提问者 → 403（E-06）；该问题已有采纳 → 400（E-05）；回答不存在 / 已删 → 404。
5. 声誉与通知：采纳仅给回答者 +15，已写入总分及流水；允许自采纳。通知仍为 T-10 TODO，不代表主链路通知已实现。

### POST /api/answers/{id}/recommend —— 助教推荐回答标记（US-20、E-12/E-13）

1. 谁调用？**`require_graduate_assistant`**：研究生身份且助教认证通过；本科生 / 未认证研究生 → 403（E-12）。
2. 传什么？`{ recommended: boolean }`（true 标记 / false 取消）。
3. 回什么？`{ code: 200, data: { answer_id, recommended_by_assistant } }`；**仅展示标记**：不改问题状态、不影响采纳权（E-13，已测试验证）。
4. 错了怎么办？无助教能力位 → 403；回答不存在 / 已删 → 404。（路径已按本节落地，plan 第 5 节为二期接口规划不冲突）

### POST /api/answers/{id}/certify · DELETE /api/answers/{id}/certify —— 优质内容认证 / 取消（D9 定案，紧凑条目）

1. 谁调用？**`require_roles(teacher)` 且回答所在课程的负责教师**；其他教师 / 管理员 → 403（E-06）。
2. 传什么？无 body（POST 置位 / DELETE 取消，重复调用幂等）。
3. 回什么？`{ code: 200, data: { answer_id, certified_by_teacher } }`；仅展示标记，不影响采纳权与问题状态。
4. 错了怎么办？非任教教师 → 403；回答不存在 / 已删 → 404。

## 5. 评论（qa）

> T-06 已落地（2026-10-02）：字段按蛇形定案；评论正文上限 1000 字（超长截断并在 message 提示，E-02）；入库前 bleach 清洗（X-03）；二级规则——父评论必须与评论同目标且为顶级评论（回复的回复 400）；列表分页只作用于顶级评论，二级回复全量归组进 `replies`（回复不再重复作为顶级条目）；删除顶级评论时同一事务级联软删其直接回复（避免回复孤儿化，实现补充语义）；被封禁用户评论 403（E-07，get_current_user 统一拦截）；被评论通知随 T-10 回填（service 内留 TODO 钩子）。

### GET /api/questions/{id}/comments · GET /api/answers/{id}/comments —— 评论列表（US-05）

登录用户；query `page`、`page_size`；回 `{ items: [{ id, author, body, parent_id, created_at, replies: [{ id, author, body, parent_id, created_at }] }], total, page, page_size }`（顶级评论按创建时间正序分页；`replies` 为该条顶级评论的全部可见二级回复；软删评论与回复不可见，E-10）；目标不存在或已删 → 404。

### POST /api/questions/{id}/comments · POST /api/answers/{id}/comments —— 发表评论（US-05、E-01/E-07）

1. 谁调用？登录用户；被封禁 → 403（E-07）。
2. 传什么？`{ body, parent_id? }`（parent_id 给定时为二级回复：须为同目标的顶级评论，否则 400）。
3. 回什么？`{ code: 200, data: { id, parent_id, created_at }, message: "评论成功" }`；超长截断时 message 附提示（E-02）。
4. 错了怎么办？空评论 → 400（E-01）；父评论不存在/已删/跨目标/超二级 → 400；目标不存在或已删 → 404。成功后触发被评论者通知（§8，随 T-10 落地）。

### DELETE /api/comments/{id} —— 删除评论（US-05，紧凑条目）

仅作者（管理员可删违规评论）；软删除（E-10）；删除顶级评论时级联软删其直接回复；非作者且非管理员 → 403；不存在 → 404。

## 6. 投票与声誉（interaction）

### POST /api/votes —— 投票（US-07、E-04）

1. 谁调用？登录用户；未登录 → 401；被封禁 → 403；允许自投。
2. 传什么？`{ target_type: "question"|"answer", target_id, value: 1|-1 }`。
3. 回什么？`{ code: 200, data: { target_type, target_id, vote_score, my_vote }, message: "投票成功" }`；my_vote 为 1/-1，未投或取消为 0。toggle 语义：重复同方向 = 取消并冲销旧票积分；反方向 = 先冲销旧票再记新票。问题赞不加分且无流水，回答赞给作者 +10，问题或回答被踩给作者 -2；非零积分变动写流水，允许负分（US-08）。
4. 错了怎么办？target_type / target_id / value 非法 → 400；目标不存在或自身已软删 → 404；回答投票不额外受父问题软删限制（E-10）。同一用户对同一内容仅一条有效投票（E-04，唯一约束）；MySQL 并发一致性仍待验证。

### GET /api/reputation/me —— 我的积分与流水（US-08、E-11）

1. 谁调用？登录用户，仅查询 JWT 对应本人流水（E-11），无他人 user_id 入参。
2. 传什么？query `page?`（默认 1）、`page_size?`（默认 20，最大 100）。
3. 回什么？统一响应的 data 为 `{ score, logs: [{ delta, reason, ref_type, ref_id, created_at }], total, page, page_size }`；score 为持久化总分，logs 为本人分页流水。
4. 错了怎么办？未登录 → 401；非法分页参数 → 400。

### GET /api/reputation/rank —— 积分榜单（US-08）

1. 谁调用？登录用户。
2. 传什么？query：`period=week|month|all`（默认 all）、`course_id?`。
3. 回什么？统一响应的 data 为 `{ items: [{ user_id, username, score }] }`；数据库查询实现，无 Redis（Q-04）。week / month 按当前时间向前滚动 7 / 30 天流水聚合；课程过滤按流水 course_id 快照。全站 all 读持久化总分并包含零分用户，课程 all 聚合该课程全部流水；score 降序、user_id 升序，最多 10 名存在的有效用户（指用户记录存在，不新增账号状态过滤）。工作区已采用最多100候选一批的有界装配，不代表聚合扫描成本有界；真实MySQL验收及性能证据仍缺失。
4. 错了怎么办？非法 period → 400；未登录 → 401。

## 7. 搜索（discovery，纯读；T-09 待人工批准、未实现）

### GET /api/search —— 综合搜索（US-09，待审草案）

1. 谁调用？登录用户；未登录401。
2. query 全蛇形：`q`（必填，标题或正文匹配）、`course_id?`、`tag_id?`、`sort=latest|hot`（默认latest）、`unresolved=false`、`created_from?`、`created_before?`、`page=1`、`page_size=20`（1～100）；全部筛选组合。q 去空白后1～100字及按普通文本匹配（%/_不当通配符）为新增推荐待批，不是当前已实现行为。
3. 统一响应 data：`{items:[§3问题卡片],total,page,page_size}`，真实本人my_vote；共用问题查询/计数，排除软删。热门用 `GET /api/questions?sort=hot`，不要求热门必须带q，不另建热门接口。
4. 时间为问题创建时间UTC半开区间 `[created_from,created_before)`，可单侧；带Z或明确偏移的ISO 8601归一UTC，无时区/非法格式/双侧相等或倒置400。例如from=`2026-10-01T00:00:00Z`、before=`2026-10-02T00:00:00Z`仅含UTC 10月1日。历史库时间口径待核验，不宣称已支持。
5. 缺q/空白q、非法分页/sort/时间400，无命中为空items/total0。待批稳定排序：latest 创建时间降序/id降序；hot 票分降序/创建时间降序/id降序。问题列表保留keyword，并补同一created_from/created_before及排序，现有§3未包含的时间能力均未实现。

### GET /api/questions/{id}/related —— 非 AI 相关问题（T-09 路径及排序推荐待批）

登录用户，路径id；无分页或可扩大限额。回data `{items:[§3问题卡片]}`，最多10，真实本人票态；按共有标签数降序、票分降序、创建时间降序、id降序，排除自身、软删、无共同标签，去重。跨课程候选是新增推荐待批；源无标签/无候选为空items，源不存在或已删404；不增加浏览数、不做AI/复杂推荐，不替代二期US-12。

## 8. 通知（interaction；T-10 待人工批准、未实现）

### GET /api/notifications —— 我的通知（US-15、E-11，待审草案）

1. 仅JWT本人；无recipient_id/user_id入参，未登录401。
2. query：`unread_only=false`、`page=1`、`page_size=20`（1～100）。
3. 统一响应data `{items:[{id,type,title,link,is_read,created_at}],unread_count,total,page,page_size}`；按created_at降序/id降序。total为本人本次筛选总数；unread_count恒为本人全部未读数，非当前页或筛选结果（空页亦如此）。type推荐为answered/commented/accepted；治理结果和待审核工单通知二期。
4. 被回答给提问者、被采纳给回答者；评论给目标作者；二级回复给目标作者与父评论作者，去重且剔除操作者。自采纳仍+15但不发自通知；编辑/删除不生成通知。内容/通知及采纳积分必须整体成功或整体失败。
5. 新增推荐待批：固定纯文本title“你的问题收到新回答”/“你的内容收到新评论”/“你的回答被采纳”；link由后端生成站内 `/questions/{question_id}#answer-{answer_id}` 或 `#comment-{comment_id}`，不接受任意URL/HTML，不保存内容正文。通知在内容删除后保留，点击仍受原可见性规则约束；前端锚点体验二期确认。

### POST /api/notifications/{id}/read · POST /api/notifications/read-all —— 已读（待审草案）

登录用户；无body；统一响应data `{unread_count}`，是本人全部未读数。单条不存在或非本人404（不泄露归属）；本人已读重复成功。read-all仅标本人全部未读，重复或原无未读均成功；计数反映请求读取时状态，不承诺并发新增通知后的永久数值。非法id/分页400。

> 写路由编排推荐：回答POST与问题/回答评论POST迁入interaction，QA prepare返回已校验内部快照且只flush，interaction同Session写通知再提交、失败全回滚；采纳通知置于已有外层事务提交之前。URL/响应/鉴权及既有二级规则不变，QA不依赖interaction；模型/索引与安全Alembic方案见plan。
