## 1. 设计哲学

一句话：**依赖只能向内，越内越稳定。**

- 外圈（router / schemas / models）：随需求常改，允许重画；
- 基座（domain / service）：设计好就不改，低耦合、少框架依赖；
- 判据：一个改动应该只波及一层；波及两层以上说明东西放错了位置。

## 2. 分层与职责（每模块统一结构）

| 文件 | 职责 | 允许 import | 禁止 |
| ---- | ---- | ---- | ---- |
| router.py | 接 HTTP、取当前用户、调 service、回响应；**不写业务** | fastapi、schemas、service、core.permissions | 直接操作 ORM、写业务规则、写 SQL |
| schemas.py | API 契约：入参校验 + 出参声明（蛇形字段） | pydantic | import models、import service |
| service.py | 编排用例：取数 → 问规则 → 写数 → 提交事务；授权决策；跨模块协调 | domain、repository、schemas、sqlalchemy.orm.Session（事务边界让步）、其他模块 service | import models、raise HTTPException、写业务规则数字、写 SQL |
| domain.py | 纯规则：状态机、不变量、规则常量、领域异常；**零框架依赖** | 标准库 | fastapi / sqlalchemy / pydantic / 任何 I/O |
| repository.py | 增删改查动作，无业务判断；**唯一 import models 处**；出参一律 schemas | models、schemas、domain 常量、sqlalchemy | 业务规则、fastapi、跨模块调用 |
| models.py | 表结构定义（SQLAlchemy） | sqlalchemy、app.db.base | import 本模块其他层 |

例外约定：
- `core/permissions.py` 是 FastAPI 依赖注入（接口层性质），允许用 HTTPException；`core → identity.models` 的豁免一期保留，二期改轻量身份对象。
- `discovery` 是纯读模块，只有 router / service / schemas 三个文件（沿用原约定）；`governance` 一期仅 models + router(501)。

## 3. 依赖方向图

```
router ──→ service ──→ domain（到此为止，domain 不再向外依赖）
   │           │
schemas       └──→ repository ──→ models ──→ MySQL
跨模块：只准调用对方 service 的公开函数（如 identity_service.get_public）
```

## 4. 关键设计决策

| 编号 | 决策 | 理由 | 放弃的替代方案 |
| ---- | ---- | ---- | ---- |
| D-1 | 每模块新增 domain.py，零框架依赖 | 规则单点、毫秒级单测、基座可冻结 | 规则写 service（改分值要动编排层） |
| D-2 | ORM 不上浮：models 只被 repository import | 换表/换库只动两层 | service 返回 ORM（现状的泄漏点） |
| D-3 | service/domain 只抛 DomainError，HTTP 映射收口在 main.py | 业务语义与 HTTP 协议解耦 | BizException 继承 HTTPException（半成品） |
| D-4 | service 保留 `db: Session` 承担事务边界 | 彻底抽象 UoW 对课设过重；写入权衡清单 | 仓储 Protocol + FakeUoW（二期再评估） |
| D-5 | 跨模块只调对方 service 顶层函数 | 轻量替代"公开 API 包"；lint 可检查 | 各模块 api.py（模块数少，暂不需要） |
| D-6 | import-linter 两条契约进 CI | "设计好就不改"必须机器强制，否则是口号 | 仅靠评审人眼 |

## 7. 边界示例（防止放错层的判据）

| 逻辑 | 放哪 | 反例（错误位置） |
| ---- | ---- | ---- |
| "一个问题最多一个采纳答案" | domain.ensure_can_accept | 写在 service if 里 / 写在 router 里 |
| "采纳 +15、被赞 +10" | domain.REPUTATION_RULES | 写在 service 字面量 |
| "先查问题再查回答，一个事务提交" | service | 写进 repository |
| "学号唯一索引" | models | —— |
| "用户名 3-50 字符" | schemas | domain 里校验请求长度（入参校验属契约层） |
| "SELECT ... WHERE username = ?" | repository | service 里写查询 |
