## 1. 骨架设计原则

项目包含前端、业务后端、Agent 服务和部署配置。目录应让团队成员一眼看清每个服务的职责边界。

原则：

- 前端、后端、Agent 服务物理分离。
- 核心业务代码按领域模块组织（后端 6 模块、前端按业务域 features）。
- Agent 工具、循环、提示词和日志独立组织。
- Agent 的 MCP、记忆、审批、观测和多角色分工独立组织。
- 文档、部署、脚本和测试放在固定位置。
- 不把 AI 能力散落在普通 CRUD 模块里。

## 2. 推荐顶层目录

工作区根目录存放文档、规格与工程规则；代码服务统一放在 `campus-overflow-ai/` 总目录下。

```text
│   ├── frontend/          # Next.js + React 19 + TypeScript 前端/BFF/AI UI
```

## 3. Frontend 骨架（2026-09-20 已落地，页面实现为第二阶段）

三端共用一个 Next.js 应用：学生端用根路由 + 顶栏布局，教师端 `/teacher`、管理端 `/admin` 用侧栏布局；所有请求经同源 BFF 转发，前端代码中不存在直连 8000 / 8787 的地址。

```text
frontend/
├── package.json
├── next.config.ts
├── tsconfig.json
├── postcss.config.mjs
├── next-env.d.ts
└── src/
    ├── app/                        # App Router：页面 + BFF Route Handlers
    │   ├── layout.tsx / page.tsx / globals.css
    │   ├── auth/{login,register}/          # 登录、注册
    │   ├── courses/[id]/                   # 课程列表 / 课程详情（问答区）
    │   ├── questions/{new,[id],[id]/edit}/ # 发布 / 详情 / 编辑问题
    │   ├── tags/[id]/                      # 标签详情
    │   ├── rankings/                       # 周/月/课程排行榜
    │   ├── users/[id]/                     # 用户主页
    │   ├── me/{memories}/                  # 个人中心 / 我的 AI 记忆
    │   ├── notifications/                  # 通知中心
    │   ├── appeals/new/                    # 封禁申诉
    │   ├── teacher/                        # 教师端（侧栏）：工作台、courses/[id]、moderation、certify
    │   ├── admin/                          # 管理端（侧栏）：治理总览、users、courses、
    │   │                                   #   moderation/{cases,approvals,appeals}、agent/runs/[id]
    │   └── api/                            # 仅 BFF 转发，不放业务逻辑
    │       ├── health/                     # 三服务聚合健康检查（T-01 已有）
    │       ├── backend/[...path]/route.ts  # → FastAPI :8000，附加登录态与 trace id
    │       └── agent/[...path]/route.ts    # → Agent :8787，SSE 不缓冲
    ├── features/                   # 按业务域组织组件
    │   ├── auth/  courses/  questions/  answers/  comments/  tags/
    │   ├── reputation/  notifications/  moderation/  agent-assist/
    ├── shared/{components,hooks,utils,types}/
    ├── api/                        # backend / agent 请求客户端封装
    └── styles/
```

页面清单与跳转级联见 [前端服务需求文档](./前端架构/前端服务需求文档.md) 第 3.2 节（学生端 P-S01~S13、教师端 P-T01~T05、管理端 P-A01~A08）。

### 3.1 前端状态建议

第一阶段可以不引入复杂状态库。Next.js 负责路由、布局和服务端渲染能力，复杂业务状态仍然放在客户端组件或领域 hooks 中。

- 登录用户信息：Context 或轻量状态库。
- 服务端数据：优先用 Next.js 服务端 fetch 或封装客户端 hooks。
- 表单状态：组件内部状态。
- Agent 流式结果：独立 hook 管理。

客户端交互复杂度上升后再考虑 TanStack Query。

```text
├── alembic.ini
```

## 5. Agent 骨架【第二阶段参考，本期不实施】


### 7.1 端口与访问入口

| 服务 | 端口 | 说明 |
| ---- | ---- | ---- |
| frontend | `3000` | Next.js，承载学生端、教师端、管理员后台、Agent 面板 |
| backend | `8000` | FastAPI，业务 API、管理员 API、Agent 内部 API |
| agent | `8787` | TypeScript Agent Runtime（第二阶段） |
| mysql | `3306` | 仅 Docker 内网访问 |
| nginx | `80/443` | 生产环境统一入口（可选） |

内部路由：`agent → backend:8000/internal/agent/*`，只允许服务间访问，不对公网开放。

## 10. 已定微调决策

- ~~monorepo 包管理工具~~ → 不引入，三个服务独立 install；多服务联调用根目录脚本。
- ~~前端 TanStack Query~~ → 第一阶段不引入，用 fetch hooks；复杂度上升再评估。
- ~~后端 async SQLAlchemy~~ → 使用同步 SQLAlchemy + PyMySQL，稳定优先。
- ~~Agent 服务框架~~ → 选定 Hono（轻量、原生支持 SSE、边缘友好）。
- Agent 独立任务队列 → 不需要，站内事件同步消费；量级上来再引入。
- MCP Adapter → 第一阶段（二期任务）只做骨架和一个 mock MCP 工具，真实外部工具再接入。
- Observability → 先做 trace id + 数据库日志，再接 OpenTelemetry exporter。
- ~~Redis 进入 docker-compose~~ → 不进入，榜单/热点内存实现（Q-04）。
- 管理后台 → 复用主前端布局（`app/admin/**`），不单独开端口/服务。
