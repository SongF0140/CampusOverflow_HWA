## 决策说明

1. **domain 层未动**：筛选是查询参数透传，不含业务规则（枚举合法性由 router 的 Query pattern 白名单承担），符合"domain/service 基座尽量不动、api 与查询层可改"的用户偏好。
2. **keyword 不做 LIKE 通配符转义**：与 courses/标签列表搜索既有先例保持一致。SQLAlchemy 参数化查询无注入风险，未转义仅意味着用户输入 `%`/`_` 会被当作通配符（匹配语义放大），属列表搜索可接受行为；全文搜索（T-09 /api/search）场景才转义。放弃方案：为三处列表搜索统一抽 escape_like 工具——超出本板块最小范围，留待搜索行为需要统一时一并处理。
3. **枚举非法值返回 400**：role/status 用 `pattern="^(student|teacher|admin)$"` / `^(active|banned)$` 白名单，非法值走 FastAPI 422 → 项目统一异常处理归一 400，与管理员端接口文档既有"422 归一"口径一致。
4. **前端不改**：`AdminUsersView.tsx` 的本地过滤与 TODO 注释保留，前端改传服务端参数属前端补完批次（A-17/A-23），符合"只改后端"的硬约束。
5. **遗留限制**：keyword 仅按用户名匹配（前端本地过滤还支持按用户 ID 检索，该行为保留在页内）；keyword 对 `%`/`_` 不转义（见决策 2）。
