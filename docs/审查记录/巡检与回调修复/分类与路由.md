# P-01 巡检错误分类与HTTP路由

## 设计依据

依据本批specs/spec.md、plan.md、tasks.md与analyze.md，落实用户授权的审计修复。维持C-05业务边界、C-06人工审批及5轮预算。根任务UUID是资源标识，和JWT认证无关。

## 验证记录

- 先补反例：后端3项失败、17项通过；Agent4项失败、6项通过，复现未区分409原因的问题。
- 修复后后端巡检根任务、真实HTTP路由、恢复与审批相关38项通过；ruff与5项分层契约通过。
- Agent巡检、客户端错误解析、派发与治理step相关17项通过；typecheck、lint通过。
- 真实loopback Uvicorn加载完整FastAPI应用及测试库：GET /scan/page与确认页POST均200，创建后GET UUID资源200；缺段/scan触发UUID校验，由全局错误处理归一为400。

## 决策说明

静态/scan/page包含两个路径段，不会被单段/{task_id}匹配，无需挪动路由。保留真实HTTP回归防止未来改动破坏路径。

仅明确missing/hidden/deleted产生专用领域错误及可选顶层reason_code；其他错误响应维持原结构。Agent仅从根任务创建POST解析白名单原因码，仅该原因的409可跳过；未知409、旧中文消息及混合失败页不确认游标。旧后端缺少原因码时保留页，建议后端先升级。没有数据库迁移，未修改JWT或会话模型。
