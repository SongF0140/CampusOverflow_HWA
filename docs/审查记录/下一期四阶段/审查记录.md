### 决策说明

- **外部密钥与 MCP 凭证分离**：若不分离，轮换凭证必须同时修改后端 `BACKEND_EXTERNAL_AGENT_KEYS`，轮换窗口内会出现凭证可用但管理员工具 401 的断档。未配置 `external_key` 时回退为首个凭证，保持旧部署行为不变。
- **过期与不存在统一 401**：避免通过状态码或文案枚举“哪个 token 存在过”，与既定不暴露能力信息一致。
- **限流按客户端名共享额度**：主/备凭证属于同一客户端，按 token 分别计数会在轮换期放大额度。
- **限流拒绝独立审计事件**：工具未执行，不应记为 `mcp_tool_call`；独立事件便于运维区分限流与业务失败。
- **非法配置启动失败**：沿用既有 fail-fast 风格，避免限流配置笔误静默变成“无限流”。
- **不引入 Redis**：P4 不新增基础设施依赖，进程内令牌桶满足单实例接入；多实例一致性归 T-18。

### 限制

- 令牌桶随进程重启清零，多实例各自计数，不共享额度。
- 额度按 HTTP 请求计，`initialize`、`tools/list` 与 SSE GET 同样消耗；客户端频繁重建会话会比预期更早触发限流。
- 过期凭证需在配置中显式移除，系统不自动改写配置文件。
- 未做真实外部大系统联调；启用管理员工具时 `external_key` 必须与后端密钥映射一致。
- 未增加 `Retry-After` 响应头，客户端需按 60 秒窗口自行退避。
