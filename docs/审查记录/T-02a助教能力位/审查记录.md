## 3. 决策说明

| 决策 | 理由 | 放弃的替代方案 |
| ---- | ---- | -------------- |
| 申请即声明身份（apply 无 body，直接置 postgraduate + pending） | 用户选定方案；身份自报 + 教师审核把关符合校园场景，避免"改身份"独立接口 | 注册时选身份（注册接口已定案不含身份字段，改动面大）；身份类型由管理员设置（无对应接口文档） |
| 能力位判定集中 `identity/domain.is_graduate_assistant`，permissions.py 复用 | 分层基线 D-1"规则集中在 domain"；T-05 助教推荐标记将复用同一判定 | permissions.py 内联三个比较（规则重复两处，domain 与 core 漂移风险） |
| 契约 4 追加豁免 `core.permissions -> identity.domain` | domain 零框架依赖，core 复用它无分层污染；lint 可检查 | 在 permissions 重复常量（违背规则集中） |
| UserPrincipal 扩展 identity_type / assistant_cert_status（带默认值） | 一次 DB 读取即完成能力位判定，不加第二次查询；默认值保证旧构造点不破坏 | require_graduate_assistant 内再查库（多一次查询，principal 不完整） |
| Alembic 单初始迁移（users 含新字段 + governance 两表），不拆"存量+增量"两迁移 | versions 目录此前为空、无已部署环境，单迁移语义等价且少一个文件；autogenerate 生成 | 拆 0001（旧结构）+0002（加字段）（无环境受益，纯增文件） |
| 审核留痕 = 表字段（reviewed_by/reviewed_at）+ action_logger 日志（含 comment） | 教师端文档 §3 审计要求（操作者/时间/对象/结果）；comment 无业务用途仅入日志 | 单独建审计表（一期治理审计随 T-15 二期落地，避免提前建表） |
| 探针路由挂载在测试文件内（`/api/test/assistant-board`） | require_graduate_assistant 在 T-05 前无真实业务路由，测试内挂载不动生产代码 | 在生产代码加"能力位查询"接口（me 已返回身份字段，前端可判定，属冗余接口） |

**遗留与限制**：
- 申请接口为用户确认的最小闭环设计；若后续要求上传证明材料，需扩展 apply 与列表接口（二期）。
- 审核动作审计目前为进程日志（action_logger），持久化审计随二期 T-15 治理落地。
- 助教板块真实业务路由（推荐标记 `/api/answers/{id}/recommend`）随 T-05 挂载同一依赖。
- 迁移在 Windows 下要求 alembic.ini 保持 ASCII（已改英文注释并注明），否则 Alembic 以 GBK 读取会解码失败。
