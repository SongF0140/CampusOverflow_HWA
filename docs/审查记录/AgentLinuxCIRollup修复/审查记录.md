# Agent Linux CI Rollup修复

## 设计依据

2026-11-03，依据用户新的CI日志、AGENTS.md、constitution/plan/tasks/analyze、Workflow接入和此前CI堆内存验证记录。原2GB堆问题修复后，Linux仍在依赖追踪完成后的Rollup渲染阶段失败。本批保持现有4GB堆和全部CI检查，修复计划见docs/superpowers/plans/2026-11-03-agent-ci-rollup.md。

WSL2隔离Ubuntu/glibc、官方Node22.22.0和全新npm ci重现与用户相同堆栈。只在临时Rollup副本增加诊断，定位`@workflow/world-postgres/dist/drizzle/index.js`的`Schema`导入`./schema.js`尚未关联。Nitro externals先调用this.resolve加载，再将追踪命中的模块外部化，导致已加载模块与外部化边界不一致。上游同类线索：https://github.com/nitrojs/nitro/issues/4471 ，实际修改以本项目反例为依据。

## 验证记录

- 修复前：Linux Node22.22.0、锁文件npm ci、显式4GB堆，正式build在追踪54依赖/651文件后稳定触发相同空引用；额外一次诊断构建给出上述具体模块。
- 修复后：仅增加`noExternals: ["@workflow/world-postgres"]`，保留World/Graphile/tslib三个完整追踪项。撤掉所有临时Rollup诊断，entry文件SHA256与未修改的同版本安装一致。正式build退出0，编译33 steps/1 Workflow，追踪55依赖/658文件。
- 同一Linux环境：Agent全量54文件491项通过；npm run lint、npm run typecheck、npm run smoke:workflow、npm run smoke:dev全部退出0。开发冒烟仍有上游runner就绪超时后恢复的提示，最终健康、认证及默认关闭检查通过。
- 新建仅loopback监听的隔离PostgreSQL14.24集群，使用安装包原CLI初始化Workflow及Graphile schema。把冒烟构建产物复制到源码目录之外，再复用现有运行断言：默认关闭、健康/认证、真实Workflow/Step、Postgres内部回调伪造凭据403、MCP单次启动及关闭均通过。没有访问现有PostgreSQL/MySQL或生产数据库。
- 临时chroot最初缺少可用/dev/null导致子进程EACCES，补齐该测试目录的专用设备/proc挂载后重跑通过；不是项目构建问题。临时Postgres已停止、专用挂载和测试目录已移除。旧解压残留清理曾被自动审批拒绝；用户明确批准后完成指定目录清理并恢复原只读挂载。
- 远端Actions此前连接器读取404，未确认远端CI结果。本地Linux验证不能表述为远端Actions已绿。

## 决策说明

统一打包Postgres World代码，避免其内部Schema关联被中途外部化；仍完整复制所需运行资源，保持Graphile动态模块布局。不修改依赖源码或锁文件，不吞异常，不切换整套构建器，不改变治理轮数、审批、数据库职责、生产开关或部署行为。只提交本次配置及配套记录，既有GL未提交改动不纳入。
