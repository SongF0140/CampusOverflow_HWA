## 决策说明

1. **冻结集合收窄（关键适配）**：只冻结 WHAT 层（constitution/spec/plan/AGENTS/rules）。tasks.md、analyze.md、审查记录保持可写——否则勾选任务本身会被钩子拦截，与增量开发纪律冲突。人类修改规格的合法路径：人工确认改动 → `bash scripts/update-protected-sha.sh` 刷新基线 → 重跑 specs/analyze.md 一致性分析。
2. **用 git pre-commit 而非 IDE 钩子**：本机 `bash` 指向未安装的 WSL（execvpe 失败），Claude Code 式 PreToolUse 不可假设存在；git 钩子由 Git 自带 bash 执行、跨 IDE/跨平台。配套 `.gitattributes` 锁 `*.sh eol=lf`（autocrlf 环境下 CRLF 会直接弄坏 bash 脚本，本次实际踩到）。
3. **快速门禁不含全量 pytest**：全量 112 项约 2 分钟，放 pre-commit 会拖垮每次提交；pre-commit 只跑秒级 ruff+lint-imports，全量 pytest 留给 gate.sh（任务收尾）。与参考项目"Stop 才跑 verify"分层一致。
4. **覆盖检查以"编号被测试代码引用"为判据**：不重命名既有 110+ 测试函数（侵入大收益小），约定新测试在 docstring/名称标注 E-xx；豁免清单逐条给理由并注明摘帽任务号（E-03→T-07、E-04→T-08、E-11→T-08/T-10），避免豁免变黑洞。
5. **变异体全部来自真实规则**（E-02/E-05/E-06/E-10/X-03/D9），不是随机变异：每个 patch 对应"智能体常犯错误"（差一、权限取反、过滤遗漏、顺序反转、双保险拆一、归属校验删除）。M01 特意设计为"组合变异"（domain 前置校验 + DB 唯一约束一起拆）——单独拆任何一层现有测试都杀不死，组合拆才红，用来检验纵深防御的测试只覆盖了"整体链路"的真相。
6. **sha256sum 星号坑**：Git Bash 的 sha256sum 二进制模式输出 `hash *path`，与脚本解析的双空格格式不符（会导致校验形同虚设）；update 脚本统一规范化为 `hash  path`。
7. **后台任务不可靠 + 交叉污染教训**：drill 全程约 12 分钟，后台执行三次均出问题（被系统清理、日志丢失、变异残留工作区）。更隐蔽的是：残留变异未回滚时下一轮演练的失败被错误归因——首轮 `.killer` 记录中 M03（清洗顺序）显示的杀手竟是列表排序测试、M04（采纳权限）显示截断测试，证明结果被交叉污染，全部作废重跑。整改：判定改 `-x` 首败即停、加回滚失败强制 `git checkout --` 兜底、加 ONLY 单变异模式支持分步执行；每次演练前 `git status --porcelain` 检查 backend 干净（脚本内置），演练后人工核对无残留。教训：长任务优先拆块或缩短单次运行；自动化产生的"证据文件"也要审查合理性。

## 遗留限制

- pre-commit 只在**本机**生效（.git/hooks 不入库）；换机需重新执行安装命令：`cp campus-overflow-ai/scripts/hooks/pre-commit .git/hooks/pre-commit`（已写入钩子头注释与审查清单）。
- 变异演练当前覆盖 qa 模块 6 个规则点；courses/identity 模块变异体未建（可在 T-19 测试补齐时按同一模式扩展）。
- `alembic check` 只验证"模型与迁移一致"，不能发现迁移内容语义错误（如约束命名）；后者靠 code review。
- gate.sh 的 pytest 无覆盖率门槛（参考项目 JaCoCo ≥90/85%）；pytest-cov 接入留待 T-19 评估。
