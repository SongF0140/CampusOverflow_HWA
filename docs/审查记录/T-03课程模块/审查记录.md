## 决策说明

1. **E-06 收敛为单条领域规则**：`ensure_can_manage(role, course_teacher_id, user_id)` 同时覆盖编辑课程与成员列表两个用例——两者同为"管理自己课程"语义，放弃为两个接口各写一份 if。学生调 PATCH 也会经此规则 403，router 只做登录依赖，不做 `require_roles` 预筛，保证规则单点。
2. **四聚合区块与 question_count 本期返回空数组 / 0**：它们依赖 qa/interaction 模块（T-04/T-07/T-08），而 courses 不能反向依赖 qa（qa → courses 是架构既定方向，反向会产生循环依赖）。接口文档明确允许"无数据时返回空数组"，即预留了口子；T-04 落地后由 qa 侧提供统计、courses.service 调用回填。放弃方案：courses.repository 直查 qa 表（违反"models 只被本模块 repository import"）。
3. **教师名/成员名跨模块批量取**：新增 `identity.service.get_usernames_by_ids`（D-5 跨模块只调对方 service 公开函数），列表页一次 `IN` 查询，避免 N+1；放弃方案：courses.repository 直查 identity.models（违反 D-2）。
4. **semester 定为自由字符串 ≤20 字**：接口文档写"格式随 plan 落定"但 plan 未定，按遇事原则本应询问，因低风险采用默认（精确匹配筛选），已在接口文档与 schemas 中显式标注，审查时可改。
5. **PATCH 不可编辑编码**：接口文档"传什么"仅列 name/description/semester，但错误清单残留"编码改为重复值 → 400"，两处矛盾；取"传什么"为契约（编码是课程标识），错误条目随本次回填作废并注明。
6. **join/退出限学生角色**：接口文档"谁调用？登录学生"。教师/管理员调用 → 403（require_roles("student")）；负责教师身份在 courses.teacher_id，不在成员表。
7. **蛇形字段回填**：接口文档原稿 teacherName/memberCount 等驼峰与 2026-09-20"接口字段一律蛇形"定案冲突，实现按蛇形，文档课程节已同步回填（学生端 §2、教师端 §1）。

**遗留限制：**
- 课程问答区 GET /api/courses/{id}/questions 归属 qa 模块，随 T-04 落地（本期前端调用会 404，符合任务边界）。
- question_count / 四聚合区块为占位值，T-04/T-07/T-08 回填时需在本模块 service 加跨模块统计调用。
- 退出课程仅解除成员关系，不清理该学生在课程内已发内容（qa 模块落地后评估是否需要）。
