## 决策说明

1. **标签随 T-07，本期不收 tagIds**：tasks.md T-04 目标含"标签"但 tags 表随 T-07 才建，本期无从落地绑定逻辑。QuestionCreateRequest 不设 tag_ids 字段，列表/详情的 tags 返回空数组占位，接口文档注明"随 T-07 落地"。放弃方案：提前建 tags 表（拆散 T-07 范围，破坏任务边界）。
2. **发布资格规则**：课程负责教师天然可发（不要求先加入自己课程）；其余用户必须已加入课程（CourseMember 存在）否则 403；课程不存在 404。判定经 courses.service 公开函数 `get_course` / `is_member`（D-5 跨模块只调对方 service），qa 不 import courses.models，避免循环依赖。
3. **内容上限定案：标题 ≤100 字、正文 ≤20000 字**：spec 只说"超长截断并提示"，plan 未落定数字；按常见社区问答上限取 100/20000，以 domain 常量集中（TITLE_MAX_LEN / BODY_MAX_LEN），审查时可调。截断在清洗之后执行（先 bleach 后截断，避免截断点落在标签中间留下残缺标记）。
4. **X-03 采用 bleach 全标签剥离**：存储的是 Markdown 源文本，HTML 标签本就不该执行，全部剥离最简单且安全。strip=True 会保留标签内部文本——内部文本降级为纯文本，不构成可执行标记，安全性在于标签被剥离而非文本消失（单测按此语义断言）。放弃方案：白名单放行部分标签（当前无富文本渲染需求；二期如需渲染 HTML 再放宽白名单）。
5. **E-02 提示文案放 router，规则数字进 domain**：service 返回 (question, truncated) 二元组，router 引用 domain 常量拼提示——文案是展示层关注点，数字规则单点维护在 domain。
6. **sort=hot 暂按浏览数**：投票分依赖 T-08 votes 模块，本期 hot = view_count 降序（次级 created_at 降序），接口文档已注明 T-08 后改投票分。
7. **浏览数原子自增**：`increment_view` 用 `query.update()` 单条 UPDATE 原子 +1，避免读-改-写竞态；详情接口返回自增后的 view_count。
8. **E-07 封禁拦截在 identity 层统一生效**：`core/permissions.get_current_user` 对 status=="banned" 直接 403（T-02 已实现），qa 各接口因依赖 get_current_user 天然覆盖，无需在 qa 层重复拦截。
9. **跨模块占位回填**：vote_score=0、tags=[]、answer_count=0、has_accepted=False、my_vote=0、accepted_answer_id=None 均为占位（同 T-03 四聚合区块模式），随 T-05/T-07/T-08 回填。

**遗留限制：**
- 详情页"完整展示问答闭环"依赖回答/评论（T-05/T-06），本期详情仅含问题本体，回答/评论经后续接口分页获取。
- tag_ids 入参、tags 展示随 T-07 回填；sort=hot 投票分随 T-08 回填；E-05/E-06 采纳规则随 T-05。
- 标题/正文上限为默认值（100/20000），如课程场景需要更宽/更严，改 domain 常量即可，测试同步调整。
