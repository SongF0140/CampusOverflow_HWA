## 三、决策说明

1. **确定性规则而非模型**：N-1 只做误报/漏报/规则失效归纳，用可解释规则即可，避免引入模型版本与幻觉，也让指标可复算。规则：巡检单被 rejected 或 skip/ignore 记为误报；管理员直接处置记为漏报线索；同 `target_type + risk_level` 样本 ≥5 且否决率 ≥50% 记为规则可能失效。
2. **字段最小化**：反馈接口不返回内容快照、管理员自由文本、决策轨迹，只保留判定与处置所需字段，降低隐私面；笔记摘要只含工单号、类型、风险与结果。
3. **幂等与预算**：`note_key` 唯一，重复提交返回既有记录；单批最多 5 条由 schema 强制，避免记忆膨胀；有效期默认 30 天。
4. **默认关闭 + 管理员手动触发**：不用夜间自动调度先跑真实数据，符合"未验证前不放大影响面"；开关为 `PATROL_CONSOLIDATION_ENABLED`，非管理员 403。
5. **过期降级放在整理开头**：先降级再读反馈，保证本轮注入候选（后续 N-3）不含过期笔记；过期失败即终止并写失败终态，避免"看似成功但状态不一致"。
6. **BFF 复用通配路由**：新增专用路由会增加维护面且不带来安全收益，现有转发已包含凭证与 trace id。
7. **与个人记忆隔离**：笔记表独立，不进入个人记忆读写链路，不能作为数据访问授权依据。

遗留限制：

- 未接定时，需要人工触发；夜间时段仍待定。
- 未用真实数据校准样本阈值（5 单、50%）与有效期（30 天）。
- 规则失效按 `target_type + risk_level` 粗分组，尚未细化到具体规则标识。
- 定时调度、真实数据验收、注入效果指标对比、申诉类缺口与课程维度聚合未完成。

## 四、N-3 规则提升、撤回与注入

### 实现

- 迁移 `n02_patrol_evidence`：笔记新增 `evidence_count`，旧数据默认 1（不可注入）。
- 提升门槛：只有 `active`、未过期、置信度达标、证据 ≥2 且属于误报/漏报/规则失效的笔记才进入注入候选；`gap` 与 `focus` 永不注入。
- `POST /internal/agent/patrol/notes/{id}/retract`：撤回后状态变为 `retracted`，立即从注入候选移除；重复撤回幂等。
- `GET /internal/agent/patrol/notes/injected`：按字符预算（默认 2000，上限 4000）裁剪并返回 `truncated`。
- Agent `patrol-injection.ts`：渲染为 `- [类型] 目标（v规则版本，置信度 N）：摘要`，二次按行长度裁剪。
- 巡检提示词注入：`PATROL_INJECTION_IN_PROMPT=true` 时把候选追加到系统提示，失败不影响本轮巡检；文本明确"仅供参考，不得降低风险判断、跳过检查或改变处置权限"。
- 管理员预览：`GET /agent/patrol/injected-context`，`PATROL_INJECTION_ENABLED` 默认关闭。
