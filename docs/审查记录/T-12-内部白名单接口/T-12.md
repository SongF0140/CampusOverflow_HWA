## 决策说明

1. **三表归属 governance 模块**：agent_memory 按 project-context 约定落 governance；agent_runs / tool_call_logs 同放 governance（模型已含 trace_id/agent_run_id 字段位，演进路径 §8 亦指向 governance），未新建 observability 模块。
2. **governance 补齐完整 6 文件分层**：domain（纯规则：记忆三类校验、状态机、敏感词规则）/ schemas / repository（flush 不 commit）/ service_internal / router_internal，与 identity 分层示范一致，受 lint-imports 契约强制。
3. **鉴权头命名**：沿用 docs/接口设计指南.md 已定案的 `X-Service-Token` 与 `X-Trace-Id`；token 校验放 core 层依赖注入，缺失或错误一律 401（不区分两种失败，避免枚举探测）。
4. **agent_memory.course_id 软引用**：不加 FK（记忆可跨课程保留，课程删除不应级联清记忆），按 plan §6 存储键要求落字符串/整型软引用。
5. **工单 target 缺省 agent_action/0**：审批请求不带具体内容 id 时（如"限时封禁"类动作在 Agent 侧评估阶段）先落占位 target，处置关联随 T-15 细化。
6. **放弃的替代方案**：不再造 /api/admin/* 治理业务路由（A-13 已定 T-15 时迁移占位）；未把 8 个接口拆进各业务模块（跨模块只读查询集中 governance repository，保持内部接口单一出口便于审计）。
