# WF-03D 模型治理五轮闭环

2026-11-02；按用户连续至WF-04授权实施，本地待批末统一审查。

后台巡检通过默认关闭的GOVERNANCE_WORKFLOW_ENABLED分流至系统根任务；未开启仍保留旧流程。未绑定根任务在下一次巡检补偿，已绑定/终止根任务不重新启动。每轮WorkflowAgent规划最多3个白名单动作，逐次申请与人工批准，再通过原网关、租约和后端原子执行器执行。动作结束重新读取真实状态，第二次模型调用判断效果并由WF-01推进；完整loop最多5轮。40个逻辑工具调用和120秒活动预算跨轮累计，人工durable sleep独立，后端根有效期7天。未知回执只核对同一execution，不换参数或另申请重做；无法确认转人工。

实际SDK 5.2.3的start不接受原子hook选项。实施调整为第一持久step在后端行锁/CAS绑定唯一run；重复候选在此失败，不能取得治理动作。可能产生多个候选Run，不能宣称只有一次start。该决策已同步plan/README，保持根任务唯一性和轮数不重置要求。

发现SDK默认模型序列化会解析headers，因此增加空描述符GovernanceWorkflowModel；真正provider、密钥和baseURL仅在模型step内读取。服务/executor凭据和短期租约均留在step内部，不返回模型或持久输出。新增按根/申请绑定的只读回执入口，恢复时验证原审批与回执字段。

验证：Agent全量479项通过；另有4项dispatch默认关闭、重复、启动响应丢失与补偿专项通过；类型和lint通过。真实FastAPI/MySQL 8.0.25 + Postgres 18 + OpenAI兼容模型HTTP替身跑完5轮/10动作/10次模型调用，第三轮Agent重启、首次执行响应丢失恢复通过，业务执行各一次。后端根/审批/迁移专项28项通过，系统撤权/终止/审计反例包含在内，ruff及5导入契约通过。最终Postgres本身重启、凭据扫描及批末完整证据归WF-04记录。模型替身仅证明编排，不代表真实模型判断质量验收。
