# Agent CI堆内存修复

## 设计依据

2026-11-02开始排查，2026-11-03收口。依据用户推送后的CI失败日志、AGENTS.md、现有Agent CI与Nitro构建配置、修复计划及一致性分析。日志实际终止原因为V8约2GB堆耗尽，Linux退出134；前面的Nitro/Zod/node:sqlite提示不是本次终止原因。本地此前Node24默认堆约4288MB，未覆盖CI的2GB限制，属于验证缺口。

## 验证记录

- 同一代码以NODE_OPTIONS=--max-old-space-size=2048运行npm run build，在约2035MB存活堆处稳定触发同类JavaScript heap out of memory。Windows进程退出1，终止错误与用户Linux日志一致。
- 以NODE_OPTIONS=--max-old-space-size=4096依次执行npm run build、npm run smoke:workflow、npm run smoke:dev，全部退出0。正式构建33 steps/1 Workflow；运行冒烟覆盖真实Workflow/Step、健康/认证、默认关闭与MCP生命周期，开发冒烟覆盖健康/认证及默认关闭。
- 使用js-yaml解析CI文件，确认Agent job的NODE_OPTIONS为4096并由该job各步骤继承。新增资源诊断只输出Node版本、V8堆上限和机器总内存，不输出环境变量或凭据。
- 本地验证环境为Node24.16.0/Windows，不能替代远端Node22/Linux结果。GitHub CLI未安装，GitHub连接器读取该仓库Actions返回404，本次没有确认远端CI已绿。

## 决策说明

仅为Agent CI job显式配置4GB V8堆，覆盖正式构建、两个冒烟及子进程；保持Node版本、依赖锁、业务运行参数和全部检查不变。没有通过跳过检查、过滤警告或扩大生产Agent内存设置掩盖失败。开发冒烟仍出现上游runner就绪超时后恢复的提示，最终检查通过；既有构建警告保留记录。
