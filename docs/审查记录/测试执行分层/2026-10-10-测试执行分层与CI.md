# 测试执行分层与 CI 全量回归工作流（2026-10-10）

## 设计依据

- 读取文档：`AGENTS.md`（增量开发纪律 #2、硬性约束 #7/#8、常用命令节）、`.trae/rules/coding-style.md`（测试风格节）、`.trae/rules/conventions.md`（§2 Git 与提交、§3 四处一致性、§6 测试与验收）、`docs/workflow.md`（核对 pytest 表述，确认无冲突、无需改动）。
- 需求来源：用户 2026-10-10 决策——开发期小步快跑只做冒烟（口径定为"按改动范围跑"），全量回归交给 headless/CI；与 2026-10-09 已确认的"开发期只跑冒烟、全部改完后跑一次全量"工作方式一脉相承。
- 本板块为工程流程约定，不对应 US/E/Q 业务条款；spec/plan/tasks 不受影响（无 WHAT 层变更，无需重跑 analyze）。

## 验证记录

- 后端全量：`uv run pytest`（campus-overflow-ai/backend/）两次执行均 exit 0（建 CI 前基线 + 重跑确认）。
- 前端全量：`npm test`（vitest run）72 个测试文件、411 个用例全部通过；本地退出码 1 为沙箱拦截 npm 调试日志写入（`D:\npm_cache\_logs`）所致假警报，用例本身无失败。
- Agent 全量：`npm test`（vitest run）8 个测试文件、47 个用例全部通过；同上为沙箱假警报。
- CI 配置：`ci.yml` 经 Python yaml.safe_load 解析通过；三个 job 命令与本地验证命令一一对应。
- `.trae/rules/coding-style.md`、`.trae/rules/conventions.md`、`AGENTS.md` 三处文本同步更新，交叉引用一致。

## 决策说明

- **冒烟口径选"按改动范围跑"，放弃 pytest marker（`-m smoke`）方案**：无需给存量测试打标（一次性成本低）、规则简单可检查（"改哪个验哪个"），且前端/Agent 的 vitest 无需另建等价标记机制。代价是"关键路径子集"不如 marker 精确，由"高风险路径测试必须存在"的编写约束兜底。
- **CI 本次顺带建立，放弃"只改规则、CI 留到三期"**：`.github/workflows/` 此前不存在，若规则写"全量由 CI 承担"而无 CI，全量闸门出现真空期，破损测试会累积。backend job 复用与本地一致的安装路径（`uv pip install -e ".[dev]"`）；后端测试基于 SQLite 内存库（tests/conftest.py），CI 无需 MySQL 服务容器，成本低。
- **三个 job 全部设为阻塞**：依据是三服务全量基线当天验证全绿；若后续前端/Agent 在 CI 环境出现环境性失败，可临时降级为 continue-on-error 并在此记录。
- **分层不降低编写要求**：AGENTS.md 硬性约束 #8 注明"编写要求不变"，避免规则被读成"可以少写测试"。
- **遗留限制**：① 本地沙箱跑 `npm test` 会有 npm 调试日志写入被拦的假失败（退出码 1），CI（GitHub runner）无此问题；② pyproject 默认清华 PyPI 源，GitHub Actions runner 上安装稍慢但公网可达；③ 前端处于"未完成"基线状态，其 lint 步骤若因存量代码报错导致 CI 红，届时按实际情况评估修复或临时降级。
