# 前端设计技能使用指南

> 状态：v1（2026-09-09）
> 适用读者：前端成员（后端 / Agent 成员出 UI 需求时同样参考）
> 冲突规则：**技能建议与项目宪法冲突时，一律以宪法为准**——C-01 界面文案全简体中文、C-04 清爽现代、无大面积蓝紫渐变、无"AI 模板感"。
> 一句话原则：**开发期用 clean 定基线 + taste 约束写法；视觉收尾用 redesign 审计 + ui-ux-pro-max 出检查表。**

## 1. 三个工具分别管什么

| 工具（仓库） | 装载位置 | 一句话定位 | 什么时候用 |
| ------------ | -------- | ---------- | ---------- |
| ui-ux-pro-max | 项目 `.trae/skills/`（随仓库分发，clone 即有） | 设计系统生成器：按产品类型匹配风格 / 配色 / 字体，输出反模式清单与交付前检查表 | 新模块动手前定方向；收尾时出检查表 |
| taste-skill | 全局 `~\.agents\skills\`（含两个子技能） | 反"AI 模板感"硬规则：布局变化、排版节奏、动效分寸、间距系统 | 所有 UI 编码过程中持续生效 |
| awesome-design-skills | 全局（当前启用 `clean` 子技能） | clean 设计系统：充足留白、清晰字阶、有限色板 | 全站基础风格基线 |

taste-skill 的两个子技能分工：

| 子技能 | 安装名 | 用途 |
| ------ | ------ | ---- |
| taste-skill（主） | `design-taste-frontend` | 新页面实现时的默认规范，自带交付前自检 |
| redesign-skill | `redesign-existing-projects` | 对已存在的页面"先审计、后修复"，不打断功能 |

## 2. 怎么触发（示例 prompt 直接抄）

### ui-ux-pro-max —— 定方向、出检查表

```text
用 ui-ux-pro-max 为"校园课程问答平台"生成设计系统：
学生端（问题列表 / 详情 / 提问）+ 管理后台（审核 / 审批 / 运行记录），风格清爽现代。
```

它会输出：推荐页面模式（pattern）、UI 风格、配色（主/辅/CTA/背景/文字）、字体搭配、关键效果、**反模式清单（AVOID）**、交付前检查表。生成结果贴进 PR 描述或 `docs/`，作为该模块的视觉依据。

换风格对比：

```text
用 ui-ux-pro-max 比较 bento / aurora / soft ui 三种风格对问答社区的适配度，说明理由。
```

### design-taste-frontend —— 编码期约束

```text
按 design-taste-frontend 规范实现问题详情页（frontend/src/app/questions/[id]），
移动端优先，动效克制（MOTION 低档）。
```

它会在实现时强制：布局不做模板化三栏卡片堆叠、字号层级明确、间距成体系（Tailwind token）、hover/焦点态完整、动效 150~300ms。收尾自检不过不放代码。

### redesign-existing-projects —— 视觉收尾审计（第五步核心工具）

```text
用 redesign 技能审计 frontend/src/app 下 questions 与 auth 全部页面：
先输出审计清单（模板化痕迹 / 间距混乱 / 层级不清 / 缺状态），逐条确认后修复，不改功能逻辑。
```

### clean —— 基线校正

```text
以 clean 设计系统为基线整理 tailwind 配置：色板收敛到有限几个 token，正文/标题字阶固定。
```

## 3. 推荐组合（对齐开发协作流程文档的五步流程）

| 阶段 | 用什么 | 产出 |
| ---- | ------ | ---- |
| 第二步 交互稿 / 流程图 | ui-ux-pro-max（定风格方向） | 设计系统决策贴进交互稿 |
| 第三步 并行开发 | clean 定 tokens + design-taste-frontend 约束实现 | 风格统一、三态齐全的页面 |
| 第五步 视觉收尾 | redesign 逐页审计 → ui-ux-pro-max 检查表 → C-01/C-04 走查 | 走查单 + 修复 PR |

## 4. 安装与同步（给队友）

- **ui-ux-pro-max**：随仓库 `.trae/skills/` 分发，clone 后重启 Trae 即生效；如需更新：`npm install -g uipro-cli && uipro update`（依赖 Python 3.x）。
- **taste-skill 两个子技能**（全局）：

  ```bash
  npx skills add https://github.com/Leonxlnx/taste-skill --skill design-taste-frontend -g -y
  npx skills add https://github.com/Leonxlnx/taste-skill --skill redesign-existing-projects -g -y
  ```

- **clean**（全局）：

  ```bash
  npx skills add https://github.com/bergside/awesome-design-skills --skill clean -g -y
  ```

- 全局技能装完后重启 Trae 才会被加载；awesome-design-skills 还有 60+ 套其他风格，同样命令换名字即可。

## 5. 注意事项

- 技能是**指导文档**，不改变工程流程：视觉层改动照常走分支 → PR → SM 审查；`ruff` / `eslint` / 测试照样跑。
- 技能输出的英文规则不影响成品：**界面文案必须简体中文**（C-01）。
- 三个技能同时对一个页面生效时，优先级：宪法 C-01/C-04 > clean（基线）> taste（写法）> ui-ux-pro-max（参考）。
- 示例图片一律用项目约定的图片源生成，不引外链随机图。
