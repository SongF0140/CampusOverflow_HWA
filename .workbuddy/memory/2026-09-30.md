## agentic-java-lab-starter `mvn test` fork 必死——根因定位与根治（14:30 定案）
- **症状**：`SurefireBooterForkException: The forked VM terminated without properly saying goodbye`，Process Exit Code 1，fork 零输出
- **诊断弯路（均已排除）**：dumpstream 里的 `Boot Manifest-JAR contains absolute paths...'other' has different root` 只是 surefire 对"跨盘导致 manifest 含绝对 URL"的**固定警告**（surefire catch 住 IAE 后兜底绝对路径，非致命）；JDK 21 `URLClassPath` 的 `disableClassPathURLCheck` 检查、中文路径、jacoco agent 中文 destfile 全都不是死因（手动复刻 fork 命令，测试全真实跑通）
- **真根因**：surefire 在 Windows 用 `cmd.exe /X /C "整条命令"` 启 fork，而 **JAVA_HOME 路径含 `()`**（`D:\java(new)_relax\...`）→ cmd 把 `(` 当分组符，截断成执行 `D:\java` → 失败退出 1。实验：Python subprocess 复刻 `cmd /X /C "D:\java(new)_relax\...\java -version"` 得 `'D:\java' 不是内部或外部命令`
- **附带教训**：给 fork JVM 传 `-D` 走 CLI 用户属性/surefire properties 文件都会在 ForkedBooter 里太晚（JVM 启动时已初始化完 app classloader 的 manifest 解析）；想让属性进 fork 只能进启动命令行（argLine / JDK_JAVA_OPTIONS）
- **根治**：JDK 21 移到 `D:\java_relax\install\jdk_21`（同盘 rename 被拒→robocopy /MOVE 复制成功，旧目录删除时文件被一僵尸 JVM 短暂占用，稍后即删净）；HKLM 的 JAVA_HOME/PATH 精确替换并广播；IDEA jdk.table.xml 的 "21" 条目 homePath/jrt/src.zip 全部指向新路径（IDEA 未运行，改动不会被覆盖）
- **验证**：`mvn test` → `Tests run: 25, Failures: 3, Errors: 22`（与 forkCount=0 基线一致，红的是实验 TODO 桩），fork 模式彻底恢复，jacoco 等 argLine 链路天然可用
- **本机无全局 mvn**：可用 `C:\Users\Administrator\.m2\wrapper\dists\apache-maven-3.9.16-bin\5grr65jo27hi51sujmtcldfovl\apache-maven-3.9.16\bin\mvn`（wrapper 发行版，完整可用）；IDEA 在 `D:\java(new)_relax\install\room\`（IDEA 自身路径带括号无影响，它不走 cmd /C 启 java）
