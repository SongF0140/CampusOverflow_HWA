# 管理员端需求文档（业务后端 · 第一期）

> 依据：spec v3（US-02、E-07/E-10；US-13/US-14/US-16/US-18/US-19 二期）｜权威架构：[docs/后端架构说明.md](../后端架构说明.md)｜端总览：[README](./README.md)
> 前端页面为第二阶段；本文档描述第一期后端为管理员端提供的全部接口与验收口径。

## 1. 定位与边界

管理员端承担全局治理：用户治理（封禁 / 解禁，T-02 已实现）、内容治理追溯（E-10）。审批中心与 Agent 审计为第二阶段——第一期 governance 仅建表 + 路由 501 占位。

**必须做（第一期后端）**：

- 封禁 / 解禁接口：记录原因、期限、操作者，写入审计日志。
- 封禁用户不能创建问题、回答、评论、投票（E-07）。
- 被软删除内容对普通用户不可见、管理员可追溯（E-10）。
- governance 建表（ModerationCase / Appeal）+ 501 占位路由（一期形态）。

**禁止做（硬边界）**：

- 治理动作不得绕过审计日志。
- 第一期不提供 AI 工单处理接口的真实逻辑（Agent 服务二期，见 [Agent端预留文档](./Agent端预留文档.md)）。
- C-06 一期形态：高风险动作（封禁）由管理员直接执行并留审计；**二期起** AI 相关高风险动作只能由 Agent 创建待确认工单，人工确认后执行。

## 2. 使用者与触发来源

| 角色 | 能力 | 说明 |
| ---- | ---- | ---- |
| admin | 全局治理 | RBAC 最高角色，不受课程归属限制 |

触发来源：后台治理操作（封禁 / 解禁 / 内容追溯）；二期增加 AI 工单处理与申诉复核。

## 3. 功能需求

### 3.1 用户治理（US-02、E-07——T-02 已实现）

| 功能 | 说明 |
| ---- | ---- |
| 封禁用户 | 记录原因、期限、操作者；写入审计日志 |
| 解禁用户 | 恢复正常发言与互动能力 |

验收标准：

- 被封禁用户发帖 / 回答 / 评论 / 投票被拒绝并提示原因（E-07）。
- pytest 已覆盖认证 / 越权 / 封禁边界（T-02 共 18 项）。

### 3.2 内容治理（E-10）

| 功能 | 说明 |
| ---- | ---- |
| 软删内容追溯 | 被软删除的问题 / 回答 / 评论对普通用户不可见，管理员接口可追溯 |

验收标准：管理员列表接口可查已软删内容；普通用户接口不可见。

### 3.3 审批中心 · 申诉复核（US-13、US-14、US-16）【第二阶段】

第一期不实现业务逻辑：

- governance 建表：ModerationCase（审核工单）、Appeal（申诉）随一期迁移落库。
- `/api/governance/*` 路由返回 501 占位。

第二阶段随 T-15 交付：七类处置动作（忽略 / 要求修改 / 临时隐藏 / 软删除 / 警告 / 限时封禁 / 永久封禁）、封禁记录、申诉提交与复核、处置结果通知当事人。

### 3.4 Agent 审计 · MCP 配置（US-18、US-19）【第二阶段】

依赖 T-11 / T-12 / T-16 / T-17：Agent 运行记录查看（按 trace id 检索）、工具调用日志、审批请求处理、MCP Server 白名单配置。相关数据表（agent_runs / tool_call_logs / agent_memories / approval_requests / mcp_server_configs）在二期迁移中落定。

## 4. 接口需求（对外提供，`/api/*`）

> 路径以 T-02 实现为准：封禁 / 解禁挂在 users 模块（`/api/users` 前缀），不使用 `/api/admin/*` 前缀；四问细则见[管理员端接口文档](./管理员端接口文档.md)。

| 接口 | 方法 | 说明 | US / 模块 | 阶段 |
| ---- | ---- | ---- | -------- | ---- |
| /api/users/{id}/ban | POST | 封禁（记录原因；期限 / 独立审计待补，见接口文档 1.5） | US-02、E-07 / identity | 一期（已实现） |
| /api/users/{id}/unban | POST | 解禁 | US-02 / identity | 一期（已实现） |
| /api/admin/questions/{id}/hide 等 | POST | 内容处置（经审批后执行） | US-13、E-10 / qa + governance | 二期 |
| /api/governance/*（占位） | 任意 | 治理路由占位，返回 501 | — / governance | 一期占位 |
| /api/admin/moderation/cases · /resolve | GET / POST | 审核队列与处置（七类动作） | US-13、US-14 / governance | 二期 |
| /api/appeals · /api/admin/appeals/{id}/resolve | POST / POST | 申诉提交 / 复核 | US-16 / governance | 二期 |
| /api/admin/agent/runs · /tool-calls · /approvals · /mcp-servers | GET / POST | Agent 运行审计与 MCP 配置 | US-18、US-19 / governance | 二期 |

## 5. 非功能需求

- **测试**：pytest 覆盖封禁 / 解禁边界（E-07）、软删内容可见性（E-10）、governance 占位路由 501 与表结构约束。
- **审计**：所有治理动作可回答"谁在什么时候对什么做了什么"，审计日志不可删改。

## 6. 一期验收清单

- [ ] 封禁 / 解禁可用且留审计；被封禁用户四类互动被拒（E-07）
- [ ] 软删内容管理员可追溯、普通用户不可见（E-10）
- [ ] `/api/governance/*` 占位路由返回 501；ModerationCase / Appeal 表已建
- [ ] 二期接口（审批中心 / Agent 审计）不在一期注册真实逻辑
- [ ] `uv run ruff check .` 零 error
