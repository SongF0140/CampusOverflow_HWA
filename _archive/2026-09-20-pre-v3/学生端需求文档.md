# 学生端需求文档（业务后端 · 第一期）

> 依据：spec v3（US-02~US-10、US-15、US-20）｜权威架构：[docs/后端架构说明.md](../后端架构说明.md)｜端总览：[README](./README.md)
> 前端页面为第二阶段；本文档描述第一期后端为学生端提供的全部接口与验收口径。

## 1. 定位与边界

学生端是平台主体：学生（含研究生助教）在课程空间内完成提问、回答、评论、采纳、投票、搜索与通知。后端以 `qa` 为核心模块，`courses` / `interaction` / `discovery` / `identity` 支撑。

**必须做（第一期后端）**：

- 提供课程空间、问答闭环、投票声誉、搜索、通知的全部接口，pytest 覆盖核心流程。
- 采纳闭环在**一个事务**内完成：问题状态变更 + 声誉流水 + 通知（跨模块协作，见架构说明第 4.B 节）。
- 助教板块接口受 `require_graduate_assistant` 保护：本科生与未认证研究生访问返回 403（E-12 后端侧）。
- 所有 Markdown 内容入库前 XSS 清洗（X-03）；删除一律软删除（E-10）。

**禁止做（硬边界）**：

- 本端接口不提供任何治理处置动作（隐藏/删除他人内容/封禁属管理员端）。
- 他人积分流水不可查看（E-11）；通知仅本人可见。
- 助教"推荐回答"标记仅作展示标记，不影响提问者的采纳权与问题状态（E-13）。
- 前端入口显隐（E-12 前端侧）不在本期范围。

## 2. 使用者与触发来源

| 角色 | 能力 | 说明 |
| ---- | ---- | ---- |
| student | 基础问答全流程 | 本科生 / 研究生默认能力 |
| student + 助教能力位 | 基础问答 + 助教板块 | 研究生身份且助教认证通过（Q-07）；不是独立角色 |

触发来源：登录用户主动操作（提问、回答、评论、投票、搜索、查看通知）；被动触发（被回答 / 被评论 / 被采纳 → 通知）。

## 3. 功能需求

### 3.1 课程空间（US-10）

| 功能 | 说明 |
| ---- | ---- |
| 课程列表 / 详情 | 分页、按学期 / 关键词筛选 |
| 加入课程 | 学生加入 / 退出，即时反馈 |
| 课程页聚合 | 课程内问题、标签云、活跃用户、高频问题四个区块 |

验收标准：

- 未加入课程的学生可浏览公开内容。
- 聚合区块有数据时正确展示，无数据时返回空集（前端渲染空状态为二期）。
- 接口测试通过。

### 3.2 问答闭环（US-03~US-06、E-01/E-02/E-05/E-06/E-10、X-03）

| 功能 | 说明 |
| ---- | ---- |
| 问题 | 发布 / 编辑 / 软删除；标题 + 正文（Markdown）+ 课程 + 标签 + 状态 |
| 回答 | 发布 / 编辑 / 软删除；列表按采纳 / 时间 / 票数排序 |
| 采纳 | 仅提问者；一题最多一个采纳；与积分变更同事务 |
| 评论 | 挂问题或回答下；`parent_id` 二级回复；软删除 |

验收标准：

- 空标题 / 正文不能提交（E-01）；超长截断并提示上限（E-02）。
- 非提问者采纳被拒绝（E-06）；一题再次采纳被拒绝（E-05）。
- 采纳与积分变更在同一事务，任一步失败整体回滚。
- 软删除后普通列表与详情不可见（E-10）；含脚本内容被清洗后安全展示（X-03）。

### 3.3 标签（US-03、E-03/E-09）

课程 / 技术 / 自定义三类标签；问题多标签绑定；按标签筛选与热门标签。

验收标准：

- 同一问题重复绑定同一标签被拒绝并提示（E-03）。
- 未经用户确认的 AI 推荐不产生任何写入（E-09；AI 推荐流程为二期，本期仅预留确认后写入的接口语义）。

### 3.4 投票与声誉（US-07、US-08、E-04/E-11）

问题 / 回答点赞点踩（可修改取消，toggle 语义）；采纳 +15 / 点赞 +10 / 点踩 -2 积分流水；用户主页声誉展示；周 / 月 / 课程榜。

验收标准：

- 同一用户对同一内容仅一个有效投票（E-04）。
- 每笔积分变化必有流水记录，可对账。
- 他人积分流水不可查看（E-11）。
- 榜单为内存实现，代码中无 Redis 依赖（Q-04）。

### 3.5 搜索与筛选（US-09）

关键词搜索（标题 + 正文，MySQL LIKE 或 FULLTEXT）；课程 / 标签 / 时间 / 热度 / 未解决状态组合筛选；相关问题和热门列表。

验收标准：关键词能命中标题或正文；筛选条件可任意组合且结果正确。

### 3.6 通知（US-15、E-11）

被回答 / 被评论 / 被采纳 / 审核结果通知；标记已读；导航未读数。

验收标准：通知数量与已读状态正确；仅本人可见（E-11）；动作触发通知无遗漏无重复。

### 3.7 助教板块（US-20、Q-07/E-12/E-13）

| 功能 | 说明 |
| ---- | ---- |
| 助教回答 | 研究生助教在助教板块回答问题（复用 qa 回答能力） |
| 推荐回答标记 | 研究生助教可标记"推荐回答"；仅展示标记 |

验收标准：

- `require_graduate_assistant` 依赖生效：本科生、未通过助教认证的研究生访问助教板块接口返回 403（E-12 后端侧）。
- 助教标记后问题状态与采纳闭环不受影响（E-13）；无助教能力位用户调用标记接口被拒。
- pytest 覆盖本科生 / 未认证研究生 / 已认证研究生三类身份边界（T-02a）。

## 4. 接口需求（对外提供，`/api/*`）

| 接口 | 方法 | 说明 | US / 模块 |
| ---- | ---- | ---- | -------- |
| /api/auth/register | POST | 注册（学生角色） | US-02 / identity |
| /api/auth/login · /logout | POST | 登录返回 JWT / 退出 | US-02 / identity |
| /api/users/me | GET / PATCH | 当前用户信息 / 资料编辑 | US-02 / identity |
| /api/users/{id}/reputation | GET | 用户公开声誉（不含他人流水，E-11） | US-08 / interaction |
| /api/courses · /{id} | GET | 课程列表 / 详情 | US-10 / courses |
| /api/courses/{id}/join | POST | 加入课程 | US-10 / courses |
| /api/courses/{id}/questions | GET | 课程问答区（高频问题复用列表 + `sort=hot`） | US-10 / courses + discovery |
| /api/questions | POST / GET | 发布 / 列表（分页 + 组合筛选） | US-03 / qa |
| /api/questions/{id} | GET / PATCH / DELETE | 详情 / 编辑 / 软删除 | US-03 / qa |
| /api/questions/{id}/answers | GET / POST | 回答列表 / 回答 | US-04 / qa |
| /api/answers/{id}/accept | POST | 采纳（仅提问者，事务内联动积分与通知） | US-06 / qa |
| /api/answers/{id}/recommend | POST | 助教推荐回答标记（路径随 T-05 实施落定） | US-20 / qa |
| /api/questions/{id}/comments · /api/answers/{id}/comments | GET / POST | 评论与二级回复 | US-05 / qa |
| /api/comments/{id} | DELETE | 删除评论（作者或管理员） | US-05 / qa |
| /api/tags · /api/questions/{id}/tags | GET / POST | 标签列表 / 绑定（重复绑定 400） | US-03 / qa |
| /api/votes | POST / DELETE | 投票（toggle 语义） | US-07 / interaction |
| /api/reputation/me · /api/reputation/rank | GET | 我的积分流水 / 榜单（内存实现） | US-08 / interaction |
| /api/search | GET | 综合搜索与组合筛选 | US-09 / discovery |
| /api/notifications · /{id}/read · /read-all | GET / POST | 通知列表 / 已读 / 全部已读 | US-15 / interaction |

> 出入参细节以 `plan.md` 第 5 节为权威；实施时按"谁调用 / 传什么 / 回什么 / 错了怎么办"四问补全并回填。

## 5. 非功能需求

- **测试**：pytest 覆盖认证、问答、采纳事务一致性、投票唯一约束、助教能力位三类身份边界、通知触发。
- **响应**：统一 `{ code, data, message }`；错误码六种；错误消息简体中文。
- **性能**：榜单 / 热点内存实现，不依赖 Redis（Q-04）。
